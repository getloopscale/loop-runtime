# Registro das camadas de cobrança — lido por `loopzero-ops quality billing-layers`.
#
# POLARIDADE: FECHADO POR PADRÃO. Um arquivo que referencia um insumo de cobrança e não
# aparece aqui é uma REPROVAÇÃO, não um silêncio.
#
# POR QUE ELE EXISTE
#   Em 2026-08-11 mediram-se CINCO camadas independentes onde a ausência de configuração
#   de cobrança era tolerada, todas falhando para o MESMO lado — não cobrar, não barrar,
#   não verificar — e nenhuma dizendo isso. O painel serviu 20h com plano e preço na tela
#   enquanto o segredo que verifica pagamentos não existia no cluster.
#   Cada escolha é defensável isolada. A direção do erro é o achado: um sistema de
#   cobrança que erra sempre para o mesmo lado não é tolerante, tem viés. (B-038)
#
# FORMATO
#   [ancora]       um insumo por linha — a referência que marca um arquivo como candidato
#   [piso]         o número mínimo de camadas; menos que isso REPROVA
#   [camadas]      <id> | <repo> | <arquivos,vírgula> | <guarda> | <como degrada>
#   [referencias]  <arquivo> | <por que NÃO é uma camada>
#
# GUARDAS
#   gate:<nome>   um gate do loopzero-ops cobre — só resolve se o gate for RODADO no quality.yml
#   test:<path>   um teste afirma o invariante (verificado por EXISTÊNCIA, não conteúdo)
#   open:B-NNN    dívida declarada com dono — resolve SÓ enquanto o item estiver aberto
#                 (raw, triaged ou planned); shipped e killed REPROVAM
#
# A CATRACA: fechar um item `open:` sem trocar a guarda REPROVA. É isso que impede a
# dívida de virar tapete — sem ela, bastaria marcar o B-033 como entregue para a camada
# ficar descoberta e silenciosa com este arquivo ainda afirmando que alguém cuida dela.
