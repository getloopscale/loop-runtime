# Charts que existem nas DUAS árvores com o mesmo `name` — lido por
# `loopzero-ops quality chart-pairs`.
#
# `infra/helm/` e `charts/` coexistem por desenho (ADR D1): a primeira é bootstrap
# instalado pelo Helmfile L2, a segunda é OCI publicado e consumido pelo ArgoCD L3. Quando
# um chart existe nas duas com o mesmo `name`, o `CLAUDE.md` manda mantê-los em paridade —
# *"when patching one, apply the same fix to the other"* — e a única forma de saber de qual
# se fala é pelo caminho.
#
# Este registro existe porque a prosa já envelheceu uma vez: o `CLAUDE.md` afirmava TRÊS
# pares, incluindo `loopzero-admission-policies`, e `infra/helm/loopzero-admission-policies` nunca
# existiu. O contrato mandava aplicar o mesmo conserto num par sem outro lado, e diluir a
# paridade com um par inexistente enfraquece os que são reais.
#
# O gate compara esta lista com o disco: par novo não declarado reprova, e declaração que
# sobreviveu ao par também.
#
# Como se refere a cada um: SEMPRE pelo caminho, nunca pelo nome nu.
#   "o loopzero-api de infra/helm"  = o de bootstrap, instalado pelo Helmfile
#   "o loopzero-api de charts/"     = o publicado como OCI, consumido pelo ArgoCD
#
# Formato: <name> | <o que cada lado é>

loopzero-api | infra/helm faz o bootstrap do engine no cluster core; charts/ é o OCI que o ArgoCD consome
loopzero-cloud | infra/helm faz o bootstrap do plano de controle; charts/ é o OCI publicado
