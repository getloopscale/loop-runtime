# What it is

Postgres is the source of truth for every user-visible fact in the platform. Access is layered:
`api.db.generated` holds the sqlc output, `api.db.store` holds the hand-written wrappers that
are the **only** place a status column is mutated, and `api.db` owns the pgx pool.[^pe-store][^pe-pool]

`api.db.store` is the largest package in the repository at **12,248 lines across 70 files**.

# Relationships

- `api.db` **connects to** Postgres through a `pgxpool` built from `DATABASE_URL`.[^pe-pool]
- `api.lock` wraps `pg_advisory_xact_lock` — transaction-scoped, never the session-scoped
  variant, because the session form breaks under a connection pool. Every
  `(tenant, project, environment)` mutation takes it; see steps 10 and 14 of
  [`/flows/deploy-container-app.md`](/flows/deploy-container-app.md).
- `api.leader` backs the `leader_generations` fence that the metering cursor checks before it
  advances — described in [`/entities/metering-ledger.md`](/entities/metering-ledger.md).
- `api.s3` is one uploader with two targets: DigitalOcean Spaces in the cloud profile and the
  in-cluster MinIO of [`/components/platform-datastores.md`](/components/platform-datastores.md)
  in the standalone profile.[^pe-s3]
- The 48 tables and their foreign-key graph are
  [`/entities/database-schema.md`](/entities/database-schema.md).

## Two shapes the map records rather than resolves

**The persistence layer imports HTTP middleware.** `db/store/membership_wrapper.go` imports
`middleware/auth` and `middleware/policy` — an inward-pointing dependency from the outermost
layer into the innermost one.[^pe-boundary] Nothing in the repository documents this as
intentional.

**`api.objectstore` declares a DIP seam with no consumer**, and holds its own adapter — an
interface defined for a substitution nobody makes.[^pe-orphan] It is not dead code in the
compiler's sense; it is an abstraction whose second implementation never arrived.
