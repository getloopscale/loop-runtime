# T2.3 — ADR-4 CTE empirically validated against real PG (2026-07-01)

Prototyped the same-period writer (ADR-4) in psql against the local PG16 (47 migrations) BEFORE writing sqlc/Go. Period fns concretized:
- period_start(ts) = date_trunc('month', ts AT TIME ZONE 'UTC') AT TIME ZONE 'UTC'  (EC-7 UTC-deterministic)
- period_end   = period_start + interval '1 month'
- period_of(a)=period_of(b) → date_trunc('month', a AT TIME ZONE 'UTC') = date_trunc('month', b AT TIME ZONE 'UTC')
- clamp: GREATEST(LEAST(now()-$expected, $maxDelta), interval '0')  (SC-1 lower-bound)
- value: (reqMillicore * EXTRACT(EPOCH FROM elapsed)/1000)::bigint

Results (FK chain user->account->tenant fixture):
- HAPPY (gen matches, 500 millicore × ~10s): INSERT 0 1, value=5 (exact), cursor advanced. VALUE CORRECT.
- SC-6 fence (stale gen 999): 0 rows, no counter change. Demoted leader rejected.
- SC-1 backward clock (cursor set to now()+1h → now() > last_metered_at false): 0 rows, cursor HELD (still future, no rewind/decrement).
- Atomicity confirmed incidentally: a FK failure on the INSERT rolled back the cursor UPDATE too (one tx).
