# Documentation Governance — Architecture

**Domain:** `governance` (meta-domain: how docs/status flows through the project)
**Status:** AS-IS snapshot (Mode 2 per `/architecture-docs` skill)
**Captured:** 2026-05-11
**TTL:** 60 days (architectural — re-snapshot on major change)

## Purpose

Esse diretório documenta a **arquitetura da documentação** (status, claims, evidência, decay) do projeto LoopZero. Diferente dos outros domains (`application`, `tenant`, `secrets`, etc.) que descrevem componentes de software, esse domain descreve o **sistema de informação meta** sobre o projeto.

## Why a Dedicated Domain?

A conversa de 2026-05-11 expôs que docs de status estão espalhadas em 5+ surfaces (CLAUDE.md, maturity-assessment.md, plans/, meetings/, runbooks/, learnings/, MEMORY.md). Sem domain dedicado, ninguém tem visão de hub-and-spoke da informação. Sem visão hub-and-spoke, drift inevitável.

## Trilha Dupla — PlantUML + Excalidraw

Per ADR D8 do plano `status-validation-and-doc-consolidation-plan`:
- **`c4-*.puml`** → C4 formal (structure: what containers/components exist, how they communicate)
- **`concept-*.excalidraw`** → conceitual (arguments: WHY the design is what it is — bias, decay, triangulation)
