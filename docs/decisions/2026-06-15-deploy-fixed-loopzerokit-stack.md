# ADR 2026-06-15 — LoopZeroCloud deploy supports only the fixed LoopZeroKit stack (python + node)

**Status:** Accepted
**Date:** 2026-06-15
**Tier:** T3 (build pipeline + cross-repo contract + security)
**Ratified by:** MEET-2026-06-15-001 (APPROVED_WITH_CONDITIONS)
**Plan:** `.claude/knowledge-base/plans/simplify-deploy-loopzerokit-only-plan.md` v1.2
**Supersedes (partially):** MEET-2026-03-29-017 (which universalized loopzero-packs)

## Context

The ingestion layer is already LoopZeroKit-only: `api/internal/routes/source.go:183` rejects the legacy `loopzero_yaml` field; `api/internal/source/services.schema.json:59` constrains `runtime` to `["python","node"]`. The remaining generic complexity lives in the build layer (`loopzero-packs` 11-language Dockerfile generator + 8 `LanguageStrategy` impls including a user-supplied-Dockerfile path) and in dead `frontend`/`render:static` affordances the only supported producer (LoopZeroKit) never emits.

## Decision

1. **D1** — Build support is restricted to `runtime ∈ {python, node}`, keyed off `services.json.runtime`.
2. **D2** — Two platform-owned canonical multi-stage Dockerfiles (node, python; server/worker shapes) generated by embedded API logic replace `loopzero-packs`; the `loopzero-packs-runner` image is removed from the pipeline. The `generate-dockerfile` step name + log marker are preserved.
3. **D3** — `services.json` is the single manifest; the deprecated `ValidateServicesJSON` bridge is removed in favor of `ValidateServicesJSONNative`. (Side effect: fixes a latent worker-mislabel — the bridge hardcoded `Type:"server"`.)
4. **D4** — No user-supplied Dockerfile is ever executed. Any `Dockerfile`/`Containerfile`/`*.dockerfile` in the uploaded bundle is excluded fail-closed (BuildKit `--opt filename=` pinned to the canonical path; canonical overwrites after extract+strip) and a warning is surfaced. The BYO-Dockerfile path is deleted.
5. **D5** — `frontend` is removed from the `services.json` `type` enum and `render` is removed, synced across all four in-repo enum mirrors + the LoopZeroKit mirror + the integration doc. The orphaned frontend/static renderer subsystem (~300+ LoC) is deleted in-scope per the "delete legacy" mandate.
6. **D6** — The loopzero-cloud dependency on `loopzero-packs` is removed here; physical deletion of the `loopzero-packs` repo is a separate follow-up ADR.

## Rationale

- KISS/YAGNI: a 2-runtime fixed stack makes heuristic 11-language detection purposeless; canonical Dockerfiles are simpler, auditable, and remove an external build-plane image + an entire repo dependency.
- Security: removing BYO-Dockerfile eliminates the build-escape/RCE attack class by construction (the build sandbox runs unconfined seccomp/AppArmor; a static lint of an arbitrary Dockerfile is not a real control).
- Honesty: schema/docs claiming `frontend`/`render`/"30 frameworks" lie about platform capability; pruning aligns the contract with reality.
- Aligns with the contract the ingestion layer already enforces and the LoopZeroKit owner decision (2026-05-27) that polyglot services energy is 100% LoopZeroCloud.

## Alternatives considered

- TS/Node-only (drop python) — rejected: breaks LoopZeroKit apps with a python backend service.
- Strip loopzero-packs to python+node but keep it as an external image — rejected: keeps the cross-repo dependency + image build/push + heal logic the owner wants gone.
- Have LoopZeroKit emit the Dockerfile — rejected: violates the seam invariant "LoopZeroKit knows nothing about K8s/build".
- Hard-reject (vs ignore-and-warn) a bundle containing a Dockerfile — rejected at v0.1 (worse UX; a stray Dockerfile is not malice). A future flag may revisit.
- Leave frontend/render as harmless dead affordance — rejected: pre-release "delete legacy" mandate; a schema that advertises an unbuildable shape is a lie.

## Consequences

- Enables deleting 6 strategies + loopzero-packs + ~300 LoC of frontend/static renderer code.
- Constrains future polyglot/static support to a deliberate ADR re-opening this decision.
- T2 cross-repo contract change: loopzero-cloud schema + LoopZeroKit schema mirror + integration doc must change in coordinated commits.
- Static-frontend deploy mode (S3 proxy) is removed — recorded in CHANGELOG `[Unreleased] § Removed`.
