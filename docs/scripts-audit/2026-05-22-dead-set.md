# Dead-Set Validation (T1.1) — 2026-05-22

Per Phase 1 T1.1 of `docs/plans/completed/2026-05-22-shell-script-strategic-plan.md` v1.3.
Output of the manual validation gate that MUST run before any T1.2 bulk-delete.

## Methodology

1. Re-ran `loopzero-ops quality scripts-audit` → 73 scripts with 0 callers (in the
   audit's grep paths: CI workflows, Taskfile, helmfile gotmpl, cross-scripts).
2. Applied **full-repo grep** for each basename (all file types, excluding the
   script itself + allowlist + audit CSVs + plan/status docs + CHANGELOG).
   → 15 "truly-orphan" candidates.
3. Applied **T1.1.a dynamic-invocation grep (EC-03)**: searched for
   `bash "$VAR"`, `source "$DIR/$NAME.sh"`, and variable-interpolated paths.

## Result: VALIDATED DEAD-SET IS EMPTY

All 15 candidates were **disqualified** from deletion by the validation. None
are safely deletable on this branch. Breakdown:

### Disqualified group 1 — Dynamically sourced (EC-03 catch) — 13 files

```
infra/tests/parity/lib/cell2-gate-c2.sh   … c12.sh   (11 files)
infra/tests/parity/lib/cell2-gate-postflip.sh
```

**Why alive:** `infra/tests/parity/cell2-activation-gates.sh:76` does:
```bash
lib_file="$LIB_DIR/cell2-gate-${g}.sh"
```
i.e., it sources each gate file via **variable interpolation** in a loop. The
static audit regex (`<basename>\b`) cannot see this — exactly the EC-03
false-positive the plan's T1.1.a guard exists to catch. Deleting these would
break `cell2-activation-gates.sh` silently.

**Disposition:** these are live; `cell2-gate-c1.sh` (the seed, has callers)
and the lib set are a unit. Future Phase 4 (Ginkgo migration of parity tests)
should convert the whole `cell2-activation-gates.sh` + lib/ set together.

### Disqualified group 2 — Orphan tests of LIVE code — 2 files

```
infra/tests/scripts/dry-run-lib_test.sh   → tests infra/scripts/lib/dry-run.sh (ALIVE)
infra/tests/chaos/values_gate_test.sh     → tests infra/helm/chaos-mesh chart (ALIVE)
```

**Why NOT delete:** Both are hermetic tests of code that still exists and ships.
0 callers means they are **orphan (not wired to a CI runner)**, NOT dead.
Deleting them destroys test coverage of live code — violating the global rule
"if it has no test, it doesn't work" (CLAUDE.md §7). D6 AUTO-DIE applies only
when the PARENT `.sh`/chart is deleted; both parents are alive.

**Disposition:** WIRE-CANDIDATE — these should be added to a CI runner
(drill-hermetic-tests.yml or a chaos test job), not deleted. Flagged for a
future iter / operator action.

### Disqualified group 3 — Logical pair with unclear harness — 1 file

```
infra/tests/snapshots/sanitize.sh   (paired with render-drill.sh)
```

**Why hold:** `sanitize.sh` strips helm non-determinism; `render-drill.sh`
renders the drill helmfile. They form a golden-file snapshot pipeline
(`render-drill | sanitize > golden.yaml`). `render-drill.sh` is NOT orphan
(referenced somewhere), so `sanitize.sh` may be invoked by the same snapshot
harness via a path the grep missed. Deleting risks breaking snapshot tests.

**Disposition:** REVIEW-NEEDED — operator confirms the snapshot harness before
any deletion.

## Conclusion

**Validated dead-set for T1.2 bulk-delete: 0 scripts.**

This is the honest, rigorous outcome. The raw "73 zero-caller" count is
misleading — it is dominated by dynamically-sourced libs + orphan-tests-of-live
-code. Bulk-deleting the 15 full-repo-grep candidates would have broken 13 live
files + destroyed 2 valid test suites. The validation PREVENTED a destructive
delete — which is exactly its purpose.

The big script-count reductions toward the ≤30 target will come from:
- **Phase 4 (Ginkgo migration)** — converting the ~35 parity/dogfood test
  orchestrators (incl. the cell2-gate set) to Ginkgo, deleting the bash as a
  side effect.
- **Phase 5 (SDK-native Go)** — continued pure-logic gate migrations.
- **Operator-reviewed dead-set** — a human pass over the REVIEW-NEEDED scripts
  with git-history + sprint-completion context the static audit lacks.
