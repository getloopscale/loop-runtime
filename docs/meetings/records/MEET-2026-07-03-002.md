## Decision

Execute Steps 2–4 as **two atomic, green-at-every-step commits** (Step 2 = move; Step 3 = rename incl. gate; Step 4 = verify folded into Step 3's proof).

- **Name:** `deploycontracts` accepted over `deploymodel` (excludes the 6 ports) and `deploykernel` (leaks a DDD tolerated-coupling judgment into the public path). A "contract" = data contract (DTO) ∪ behavioral contract (port) — exactly this package's content. Stays in `api/internal/services` (NOT `pkg`) because it imports `api/internal/db` — it is app-level, not a base contract.
- **`SafeJSONMarshal` home:** `pkg/events` is correct — it serializes SSE payloads and its `{}`-fallback semantic is SSE-emit-specific; it is stdlib-only so `pkg` stays base-safe and the direction stays inward (services → pkg).
- **No cycle / no leaf erosion:** no new edges; the DAG shape is identical, only the sink's label changes. `deploycontracts` imports exactly what `shared` imported (`api/internal/db` + stdlib).

### Alternatives rejected
- `deploymodel` / `deploykernel` (worse names — see above).
- Leave `SafeJSONMarshal` in the leaf (keeps a fake dependency reason for the leaf; misplaced).
- Defer entirely (rejected by sponsor — pre-release is the cheap window; 61 importers only grow).

### Trade-offs accepted
- ~85-file mechanical diff / review noise + in-flight-branch churn — accepted because the change is compiler + fitness-gate-enforced and reversible.
- Latent SRP smell (DTOs + ports in one leaf) survives the rename — out of scope; natural future seam is `deploycontracts` (DTOs) vs a `deployports` package (YAGNI now).
