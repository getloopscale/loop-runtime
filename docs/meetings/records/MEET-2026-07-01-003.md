# MEET-2026-07-01-003 — Metering data-source decision (k8s LIST vs Prometheus KSM)

**Date:** 2026-07-01
**Type:** billing · database · multi-cell (T2+) — focused data-source mini-meeting
**Trigger:** PR #128 (merged `b02934bc`, 2026-07-01) landed cross-cluster Prometheus federation of workload kube-state-metrics + `operators/internal/app/data_plane_poller.go` (leader-elected, 1 query/tick, PG snapshot) — opening a materially simpler metering data source (ADR-12) than the meeting-ratified ADR-2 (direct k8s pod LIST).
**Plan:** `knowledge-base/plans/metering-compute-loop-plan.md` (v1.3, ADR-12)
**Verdict:** **KEEP ADR-2** (direct k8s pod LIST, PG-derived namespace attribution) as the billing source of truth. **Reframe ADR-12 as a read-only reconciliation oracle** (not a data-source switch). Unanimous across all three reviewers.

## Committee
- sre-engineer (production-readiness)
- distributed-systems-engineer (correctness / failure-semantics)
- tenant-guardian (attribution / isolation)

## Decision
The metering billing producer keeps **ADR-2**: meter `pod.Spec.Requests` via direct per-namespace k8s LIST on the tenant's cell, attribute by **PG-derived namespace** (`ListProjectsByTenant` → `naming.Namespace`), never by a label. The #128 Prometheus federation is adopted **only** as an optional, non-authoritative **reconciliation oracle** (renamed ADR-12′).

### Why — three independent lenses converged

**SRE (production-readiness):** ADR-12 dissolves only the *read* half of the R1 BLOCKER (k8s LIST fan-out); the *write* half (the PG write burst that trips the API `pg_breaker` → 503) is **unchanged** (plan:127) and is what ADR-10 + the 1,500-tenant load test protect — **those conditions survive both designs and MUST NOT be retired**. The #128 poller is a **badge, not a billing producer** (preserve-last-known-good / degrade-to-Unknown is correct for a stale badge, wrong for a money accumulator). A down cell contributes zero series to a globally-successful query → **silent under-metering of a whole cell** (can't distinguish "0 pods" from "federation down"). ADR-2 already gets KSM-grade pod-math by vendoring `k8s.io/component-helpers/resource.PodRequests` (plan:190,288) — the same SIG-node math KSM uses, **without** the Prometheus dependency.

**Distributed-systems (correctness — decisive):** an exactly-once monotonic-cursor elapsed-time accumulator requires read-failure to be an **explicit, scoped error so the cursor can HOLD**. A `pod.Spec` LIST provides that (linearizable, errors on failure). A Prometheus **instant query structurally cannot**: partial-result-as-success (a short vector is `err==nil`), 5-minute staleness, **discarded Warnings** (`data_plane_poller.go:52`). A scrape gap → Σreq reads low → cursor advances over an under-measured interval → **permanent, silent under-bill** (monotonic cursor never revisits; drops are asymmetric so they accumulate). ADR-12's claim that "#128's preserve-last-known-good applies" is a **false analogy** — #128 preserves a gauge/snapshot (harmless stale badge); a billing accumulator is a moving-cursor counter where "leave the old value" has no meaning. ADR-12 silently **downgrades exactly-once → at-most-once** (can only under-bill, invisibly, every scrape gap). ADR-2 under-bills only a *long* outage in a **bounded + alarmed** way (ADR-8 `LEAST` clamp + `loopzero_metering_clamped_total`). The genuinely useful role for #128: a **read-only reconciliation oracle**, not a write source.

**Tenant-guardian (attribution):** ADR-12 attributes by `loopzero.io/*` labels (renderer-set) — a **probability argument, not a boundary argument**. A PG-derived namespace name **IS** the isolation boundary (RBAC/NetworkPolicy/quota scoped to it); a label merely *describes* it and can diverge without any isolation break (mutating webhook, HPA/Rollout re-emit, controller copy, renderer bug, `kubectl label`) → a Deployment in `loopzero-{A}-…` carrying `loopzero.io/tenant={B}` bills **B for A's compute**, silently, into a **Stripe-reported** table, with no PG cross-check and a silent skip on label absence (`data_plane_poller.go:132-138`). Switching to ADR-12 would **re-open INV-4 + INV-5** (require deleting `TestMeteringLoop_IgnoresMutablePodTenantLabel`) and **partially defeat EC-1** (a scaled-to-zero Deployment emits zero KSM samples → indistinguishable from label-absence). Under KEEP-ADR-2 the tenant-guardian v1.3 sign-off basis is **UNCHANGED**.

## Guardian invariants
- tenant-guardian: **SAFE under KEEP-ADR-2** (INV-4 ✅, INV-5 ✅) — v1.3 sign-off basis unchanged; +2 additive oracle conditions.
- (state-guardian not convened — this decision does not touch the period/state machine; its v1.3 conditions are unaffected.)

## Mandatory actions

1. **Keep ADR-2 as the billing SoT.** No data-source switch. Update plan ADR-12 from "OPEN alternative" to "DECIDED: KEEP ADR-2; ADR-12′ = read-only reconciliation oracle."
2. **ADR-10 (dedicated pool) + 1,500-tenant load test STAY** — orthogonal to the data source; protect the write path (SRE). Not retired.
3. **Pod-math via the vendored `k8s.io/component-helpers/resource.PodRequests`**, not hand-rolled (captures ADR-12's one real correctness win under ADR-2). Already in the plan (§ Dependencies).
4. **ADR-12′ reconciliation oracle (OPTIONAL, additive, may defer to a follow-up):** if implemented, it MUST (C-attr-1) write **zero** billing rows — reuse the `DataPlanePoller`/`env_targets` snapshot shape, never `cost_counters`/`usage_records`; its divergence alert MUST NOT gate or correct billing. And (C-attr-2) wire a **`MeteringLabelDrift`** alert: per-`(tenant,project,env)`, `|oracle_label_sum − meter_PG_ns_sum| > ε` fires — converting the oracle into the standing INV-5 production detector.
5. **Read-failure-holds-cursor stays hard-gated** (dist-sys): cell LIST error → skip + `loopzero_metering_cell_errors_total`, cursor unadvanced; `TestMeteringLoop_PartialCellFailure_NoLostNoDouble` PG-REAL; extend the ≥2-cell LIVE test to inject a down-cell mid-window and assert the down cell's cursor is **HELD (deferred)**, not advanced-to-0.
6. **Record ADR-12′ as the sanctioned scale-out escape hatch** — gated on the `loopzero_metering_pass_duration_seconds` ceiling (same trigger as the ADR-11 informer migration). It may become the *write* source ONLY IF a future redesign makes query-incompleteness (Warnings / short vector / stale-beyond-threshold / per-cell expected-series count) a **per-cell READ FAILURE that HOLDS the cursor** — absent that, it is a revenue-losing correctness regression.
7. **Renumber migrations** — done in v1.3 (000045 taken by #128 → my migrations are 000046 CHECK+cursor+config, 000047 usage_records BIGINT).

## Anti-patterns flagged
- Presenting a **read-side** optimization as retiring **write-side** protections (ADR-10 / load test). They are orthogonal.
- Reusing the #128 badge poller's failure model (preserve-last-known-good) on a billing accumulator — correct-code-in-the-wrong-place / false analogy.
- Label-provenance ("renderer-set, unlikely to be forged") offered as a tenant-isolation guarantee — isolation is not satisfied by "unlikely."
