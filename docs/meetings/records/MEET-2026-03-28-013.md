## Problem Statement

The ArgoCD SyncClient uses a static Bearer token set at startup. Multiple failures occurred:

1. Bootstrap Job stored admin PASSWORD instead of JWT in `ARGOCD_TOKEN` Secret
2. PlatformBootstrap controller generates 24h session JWT (not apiKey)
3. Circuit breaker treats 401 (auth) same as 503 (infra) → permanent degraded state
4. No hot-reload: token change requires pod restart
5. `LoopZeroArgoCDCircuitOpen` alert references phantom metric (never emitted)
6. Deep health check can't distinguish auth failure from connectivity failure

---

## Critical Bugs Discovered

### BUG-1: Admin password stored as ARGOCD_TOKEN (bootstrap.ts:1191)
```javascript
--from-literal="ARGOCD_TOKEN=${ARGOCD_PASS:-admin}"
```
The API sends the admin password as a Bearer token. ArgoCD rejects it (expects JWT).

### BUG-2: PlatformBootstrap creates session JWT, not apiKey (platformbootstrap_argocd.go)
The controller calls `/api/v1/session` (24h TTL) instead of `/api/v1/account/loopzero-api/token` (no expiry).

### BUG-3: Phantom Prometheus alert
`LoopZeroArgoCDCircuitOpen` references `loopzero_argocd_circuit_state` metric that is never emitted by the circuit breaker code.

## Alternatives Rejected

| Alternative | Reason |
|-------------|--------|
| **Auto-renew via admin credentials (Proposal B)** | API should NEVER hold admin credentials. Blast radius: total platform compromise. Security VETO. |
| **Sidecar token refresher (Proposal C)** | YAGNI with apiKey tokens (no expiry). Adds operational complexity for zero value. Architect VETO. |
| **Session-based auth** | 24h TTL causes silent failures. Already proven broken in incident history. |
| **Do nothing (YAGNI)** | Rejected by Orchestrator. Token was invalid 2x during this session. Not hypothetical. |

---

## Trade-offs Accepted

1. **Phase 2 deferred (not immediate)**: Token Provider pattern adds complexity. Phase 1 (error classification + observability) is sufficient to prevent permanent degradation. Phase 2 adds self-healing.
2. **No sidecar**: Simpler operations but token lifecycle depends on Secret watch + mounted volume. K8s Secret propagation delay (~60s) is acceptable.
3. **apiKey tokens (no expiry)**: Simpler lifecycle but no forced rotation. Mitigated by proactive monitoring (`token_age_seconds`).

| Risk | Likelihood | Impact | Mitigation | Owner |

## Security Conditions (from Security Engineer VETO)

1. ArgoCD admin password MUST be removed from `loopzero-platform-tokens` Secret
2. `loopzero-api` account MUST have RBAC limited to `sync` + `get` (verified in Helm values)
3. SyncClient MUST support token replacement without restart (Phase 2)
4. PlatformBootstrap MUST use apiKey endpoint, NOT session endpoint
5. Gitea token scope MUST be reduced from `["all"]` to `["write:repository","write:organization","read:user"]`
