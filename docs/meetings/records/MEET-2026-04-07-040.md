## Stage 1 — Context

**Problem:** Platform has fragmented routing (4+ subdomains). Dashboard requires two URLs,
complex cloud→engine proxy, X-Service-Auth shared secret, and CORS multi-origin. Critical
finding: `cloud.{domain}` has DNS but NO IngressRoute — Kratos browser flows 404 in production.

**Decision Required:** Unify routing to fix the Kratos 404 and simplify dashboard architecture.

---

## Stage 2 — Key Findings

### Architect
- `cloud.{domain}` has DNS (expose.ts:24) but no IngressRoute → Kratos 404 in production
- Two hosts (cloud for dashboard, api for CLI) is the correct granularity — not one, not five
- The `/engine/*` proxy is the correct BFF pattern, not complexity to remove
- Dashboard should use relative URLs (same origin as cloud service)

### Security
- **ABSOLUTE VETO on Option A** (engine accepts HMAC) — violates MEET-039 B3
- Audience separation must remain (`loopzero-cloud` vs `loopzero-engine`)
- Cookie scope: Kratos cookies will flow to all paths on same host — engine MUST ignore cookies
- Proxy is correctly secured; keep it until Hydra token exchange is implemented

### SRE
- **CONDITIONAL VETO: zero Traefik alerts exist** — critical gap regardless of routing changes
- Current two-host architecture is already correct; don't expand blast radius unnecessarily
- Single IngressRoute for dashboard + Kratos + cloud + Hydra is acceptable (they're co-dependent)
- git/argocd/grafana MUST stay on separate subdomains

### DX
- Two env vars for one platform fails "Vercel-quality DX" bar
- `engineFetch` / `cloudFetch` split leaks architecture into UI code
- Single `LOOPZERO_URL` + relative dashboard URLs is the correct target
- Proxy error codes expose internal terms (`ENGINE_UNAVAILABLE` violates Rule 3)

---

## Stage 3 — Confrontations

### Confrontation 1: Consolidation Scope

SRE says "don't change routing." DX says "single URL." Architect says "two hosts."

**Resolution:** Fix the actual bug (missing `cloud.{domain}` IngressRoute). Move dashboard
to `cloud.{domain}` (same origin). Keep `api.{domain}` for CLI. Minimal routing change
with maximum DX improvement.

### Confrontation 2: Dashboard→Engine Auth

All agree: keep the `/engine/*` proxy as BFF pattern. Engine stays RSA-only.
What changes: dashboard code unifies to single `apiFetch()`. The proxy exists but
the frontend doesn't know about it.

### Orchestrator Challenge: P0 Bug Discovered

`cloud.{domain}` has DNS but no IngressRoute. Kratos redirects to 404. No browser
user can sign up or log in. This is a production bug, not an architecture discussion.

---

## Stage 4 — Decision

### Chosen Approach

Create `cloud.{domain}` IngressRoute. Move dashboard there. Unify dashboard code.
Keep `api.{domain}` for CLI. Keep engine proxy. Add Traefik alerting.

### Mandatory Actions

1. Create `cloud.{domain}` IngressRoute with priority routing:
   - P300: `/oauth2/*`, `/.well-known/*` → Hydra
   - P200: `/self-service/*`, `/sessions/*` → Kratos
   - P100: `/v1/auth/*`, `/v1/billing/*`, `/v1/webhooks/*`, `/auth/*`, `/engine/*`, `/metrics` → cloud
   - P1: `/*` → dashboard (SPA fallback)

2. Remove `dashboard.{domain}` IngressRoute (dashboard now under `cloud.{domain}`)

3. Dashboard build: `VITE_API_URL` → empty string (relative URLs)

4. Dashboard code: kill `engineFetch`, unify to `apiFetch()`

5. CLI: merge `LOOPZERO_API_URL` + `LOOPZERO_CLOUD_URL` → `LOOPZERO_URL`

6. Rename proxy error codes: `ENGINE_UNAVAILABLE` → `SERVICE_UNAVAILABLE`

7. Add Traefik alerting (LoopZeroTraefikDown, LoopZeroTraefikHighErrorRate)

8. Forward `X-Correlation-Id` through `/engine/*` proxy
