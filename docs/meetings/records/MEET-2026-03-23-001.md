## Stage 1 — Context

**Problem:** LoopZero precisa de shared Go libraries em `pkg/` para centralizar naming, conditions, health model e contracts. Atualmente naming esta split entre `operators/internal/naming/` e `fmt.Sprintf` espalhados. Conditions tem apenas 1 helper em `operators/api/v1/`. Nao existe health model nem contracts compartilhados.

**Decision Required:** Design de 4 pacotes propostos: `pkg/naming`, `pkg/conditions`, `pkg/health`, `pkg/contracts`.

**Constraints:**
- `pkg/` tem zero dependencias externas (pure stdlib)
- Adicionar K8s types quebraria esse padrao
- REFACTOR.md §7.4: nenhum naming via fmt.Sprintf fora da lib

**Known Context:** spec §5 (state machines), §6 (health model), §7 (naming), existing pkg/ modules

---

## Stage 2 — Analyses

### Principal Platform Architect
- O invariante zero-deps em `pkg/` e uma decisao arquitetural, nao acidente. Quebrar para `metav1.Condition` puxa todo o universo K8s transitivamente.
- `pkg/contracts` e o anti-pattern "shared kernel" — comeca pequeno e cresce ate acoplar release cycles de API e operators.
- **Recomendacao:** Manter `pkg/` pure stdlib. Conditions ficam em operators. Contracts nao devem existir.

### K8s Controller Engineer
- Conditions precisam de reason strings tipados como constantes, nao freeform. ObservedGeneration deve ser enforced pelo helper.
- Colocar conditions em `pkg/` nao resolve nenhum problema para controllers — eles ja importam K8s types.
- **Recomendacao:** Manter conditions em `operators/internal/conditions/` com enforcement de ObservedGeneration e table tests para triples (Type, Reason, Status).

### Distributed Systems Engineer
- Health model com Phase enum e insuficiente. Agregacao precisa de thresholds temporais para evitar oscilacao.
- Sem janela de estabilidade, o health oscila entre Healthy e Degraded durante deploys normais, tornando o sinal inutil.
- **Recomendacao:** `pkg/health` com Phase enum + funcao de agregacao com thresholds temporais (60s non-critical, 10s critical). Property-based tests obrigatorios.

### API/Domain Architect
- API e operators tem lifecycles diferentes. Compartilhar types forca API a aceitar toda mudanca de schema do operator como breaking change.
- API deve definir seus proprios domain types e mapear de CRD status via translation layer.
- **Recomendacao:** Matar `pkg/contracts`. API define seus types. Compartilhar apenas Phase enum via `pkg/health` (string constants).

---

## Stage 3 — Confrontation

### Conflito 1: Escopo de pkg/health
| Agent | Posicao |
|-------|---------|
| Principal Architect | Minimo: enum + agregacao pura |
| Distributed Systems | Temporal thresholds obrigatorios na agregacao |

**Resolucao:** Distributed Systems vence. Agregacao sem thresholds produz oscilacao — operacionalmente perigoso. A complexidade e essencial. Logica continua pure Go, sem K8s deps.

### Conflito 2: Quem computa health do CRD — operator ou API?
| Agent | Posicao |
|-------|---------|
| K8s Controller | Operator computa .status.phase e expoe no CRD |
| API/Domain | API computa health lendo conditions brutas |

**Resolucao:** K8s Controller vence parcialmente. Operator e o writer autoritativo de .status.phase. API le esse campo diretamente. Logica de computacao vive em `pkg/health` para ambos usarem o mesmo algoritmo.

### Consenso: pkg/contracts
Todos os 4 agentes convergem — `pkg/contracts` NAO deve existir. Decisao unanime.

## Stage 4 — Decision

| Package | Decisao | Conteudo | K8s deps |
|---------|---------|----------|----------|
| `pkg/naming` | CRIAR | RFC 1123 validation, name builders, slug generation | Nenhuma |
| `pkg/health` | CRIAR | Phase enum (string constants), agregacao com thresholds temporais | Nenhuma |
| `pkg/conditions` | NAO CRIAR em pkg/ | Fica em `operators/internal/conditions/` com ObservedGeneration enforced | Sim (operators only) |
| `pkg/contracts` | NAO CRIAR | Cada componente define seus types. Vocabulario compartilhado via pkg/health.Phase | N/A |

**Alternativas rejeitadas:**
- Mover conditions para pkg/ → rejeitado porque quebra invariante zero-deps e nao resolve problema real
- Criar pkg/contracts → rejeitado unanimemente como shared kernel anti-pattern
- Health model sem thresholds temporais → rejeitado porque produz oscilacao perigosa

**Trade-offs aceitos:**
1. Duplicacao de types entre API e operators (intencional — evolvabilidade independente)
2. Phase enum e stringly-typed (mitigado por table tests cross-boundary)
3. Threshold temporal adiciona complexidade ao pkg/health (essencial, nao acidental)
4. Condition helpers nao sao compartilhados (YAGNI — um consumidor)

**Riscos aceitos:**
- [medium] Typo em Phase value falha em runtime → mitigacao: table tests que verificam ambos os lados
- [low] Duplicacao de types cresce demais → mitigacao: review periodico
