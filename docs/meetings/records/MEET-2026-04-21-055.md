# MEET-2026-04-21-055: Post-Stress-Test Tooling Adoption Plan

**Date:** 2026-04-21
**Type:** architecture + pipeline + security
**Verdict:** APPROVED_WITH_CONDITIONS (plan significantly reduced)
**Sponsor:** Founder (Paulo)
**Challenger:** Principal Architect + Security Reviewer
**Owner:** Infra Engineer

## Topic

Review of 10-item tooling adoption plan created after 2-day stress test that revealed 17 systemic problems. Root cause: 62 manual kubectl/doctl operations bypassed IaC, causing 576 drift changes and total infrastructure destroy+recreate.

## Decision

### APPROVED Items (4 of 10)

| Item | Action | Effort | Owner |
|------|--------|:---:|-------|
| **B1: Pulumi Drift Detection** | GitHub Actions cron (every 6h), `pulumi preview --expect-no-changes`. Alert via Slack + GitHub Issue. NEVER auto-remediate. | 0.5 day | Infra |
| **B2: PG Scale-Up + PgBouncer** | `dbNodeClass: medium` (max_connections ~100) + PgBouncer in transaction mode between API pods and PG. Single Pulumi change. | 0.5 day | Infra |
| **A1: k6 + Go Harness Activation** | k6 for HTTP-level SLO testing (already exists). Go harness (`real_deploy_harness.go`) for pipeline E2E. Add `task loadtest:run LEVEL=l1` to Taskfile. Write `infra/tests/load/README.md`. | 1 day | Test |
| **Operation Rules (machine-enforced)** | RBAC restriction on human kubeconfigs + VAP for ArgoCD Application creation + `task api:hotfix` sanctioned fast-path. | 2 days | Infra + Operator |

### REJECTED Items (6 of 10)

| Item | Verdict | Reason | Votes |
|------|---------|--------|:---:|
| **A2: ApplicationSet Enforcement** | DEFER to Phase 4 | Dual ownership with TenantController. ConfigMap race condition. Code not production-ready. | 5/5 |
| **B3: Kyverno** | VETOED | Existing VAPs + RBAC sufficient. Kyverno adds SPOF on admission chain. Break-glass not implemented. | 4/5 VETO |
| **B4: Build Priority Queue** | DEFER | YAGNI at <10 tenants. Per-tenant advisory lock already prevents cross-tenant queuing. Instrument first. | 5/5 |
| **B5: ko Builds** | DEFER | API image is multi-binary (migrate + 2 Go bins + ca-certs). ko cannot produce it cleanly. DX fix is `task api:hotfix`, not new build tool. | 3/5 |
| **C2: Crossplane** | REJECTED | Closed decision (MEET-054). Pulumi ISP contracts cover multi-cloud. | 5/5 |
| **C3: Dagger** | VETOED | CWTs are 200 lines of working YAML. Dagger breaks build/release separation. BuildReconcileLoop depends on Workflow CRDs. | 4/5 VETO |

## Alternatives Rejected

| Alternative | Why Rejected |
|-------------|-------------|
| Kyverno for policy enforcement | VAPs are K8s-native, zero external dependency, already 5 policies deployed. Kyverno adds admission webhook SPOF. |
| ApplicationSet now | TenantController is current owner. Dual ownership causes convergence conflicts. Phase 4 with explicit ownership transfer. |
| Dagger replacing CWTs | CWTs work. 200 lines YAML. No documented problem. Removes K8s-native scheduling semantics. |
| ko for API images | Multi-binary image. ko requires workarounds that negate the benefit. |
| Weekly drift check | Unacceptable. 576 changes in 2 days = daily minimum. Changed to every 6h. |
| Human-enforced rules only | 62 manual operations prove humans bypass rules under pressure. Machine enforcement required. |

## Trade-offs Accepted

| Trade-off | Accepted Because |
|-----------|-----------------|
| Slower tooling adoption (4 items vs 10) | Foundation (RBAC, alerting, cell model) must work before adding complexity |
| No build priority queue | FIFO is correct at <10 tenants. Instrument admission gate rejections first. |
| No ko (slower CI builds) | 3-5 min Docker builds are functional. `task api:hotfix` addresses the bypass incentive. |
| PgBouncer adds operational surface | Connection multiplexing is mandatory for HA (2+ API pods competing for max_connections). |

## Risks Accepted

| Risk | Severity | Mitigation | Owner |
|------|:---:|-----------|-------|
| Drift detection false positives | LOW | Alert-only (never auto-remediate), ack mechanism | Infra |
| PgBouncer failure | LOW | API falls back to direct PG connection (restart required) | Infra |
| Break-glass procedure abuse | MEDIUM | Audit trail in PG, TTL expiry, Prometheus metric | Security |
| Bash scripts reused despite rules | MEDIUM | `task loadtest:run` makes sanctioned path easier than bash | DX |

## Risks NOT Accepted (Blockers)

| Risk | Why Blocked | Resolution Required |
|------|-------------|-------------------|
| Kyverno `failurePolicy: Fail` without break-glass | Platform-wide outage on Kyverno crash | Break-glass first, then Kyverno in Phase 2b audit mode |
| Any alerting-dependent tool before Alertmanager fix | Alerts go to /dev/null | S1 must complete first |
| ApplicationSet before TenantController ownership transfer | Convergence conflict, phantom Applications | Phase 4 with ADR + migration plan |

## Execution Contract

### Sequencing (revised from 4 weeks → 2 weeks)

**Week 1 — Foundation:**
- M1: Fix Alertmanager → real Slack receiver (S1 from next-sprint-execution.md)
- M2: Restrict human RBAC (read-only kubeconfig default, cluster-admin via break-glass only)
- M3: Implement break-glass procedure (time-boxed SA + audit + TTL)
- B2: PG scale-up + PgBouncer

**Week 2 — Operational Tooling:**
- B1: Pulumi drift detection (cron every 6h)
- A1: k6 HTTP SLO tests + Go harness Taskfile integration + README
- VAP for ArgoCD Application creation restriction
- `task api:hotfix` + `task loadtest:run` + `task infra:drift`

### Definition of Done

- [ ] Alertmanager sends synthetic test alert to Slack → received
- [ ] Human kubeconfig cannot `kubectl set image` on production deployments
- [ ] Break-glass script issues time-boxed cluster-admin, metric emitted, SA auto-expires
- [ ] `pulumi preview --expect-no-changes` runs on cron, drift → GitHub Issue created
- [ ] PG `SHOW max_connections;` returns ≥100
- [ ] PgBouncer transaction pooling active, API connects via PgBouncer
- [ ] `task loadtest:run LEVEL=l1` works end-to-end
- [ ] VAP rejects ArgoCD Application without `loopzero.io/managed-by` label
- [ ] `task api:hotfix` builds, pushes, and restarts with audit logging
- [ ] `infra/tests/load/README.md` documents canonical tools vs deprecated scripts
