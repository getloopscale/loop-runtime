## Stage 2 — Blockers Analyzed

### B1: `github_id BIGINT NOT NULL UNIQUE` + hardcoded 0

**Files:** `api/internal/db/migrations/000002_auth_tenants.up.sql:9`, `cloud/internal/auth/tenant.go:65-69`

**Problem:** Every Kratos user gets `github_id = 0`. UNIQUE constraint means the second user fails with constraint violation. System is limited to exactly 1 user.

**All agents agree:** P0. Ship-stopper. Fix immediately.

### B2: `resolveSlug()` TOCTOU — Cross-Tenant Privilege Escalation

**Files:** `cloud/internal/auth/tenant.go:140-168` (resolveSlug outside tx), `cloud/internal/auth/tenant.go:57-99` (ON CONFLICT DO NOTHING)

**Problem:** Two concurrent signups with same email prefix (ana@a.com, ana@b.com) → both get slug "ana" → User A creates tenant → User B's tenant INSERT silently fails via DO NOTHING → User B's membership INSERT SUCCEEDS → User B is owner of User A's tenant.

**All agents agree:** P0. Cross-tenant privilege escalation. Security vulnerability.

### B3: Shared `SESSION_TOKEN_SECRET` Between Cloud and Engine

**Files:** `api/cmd/main.go:113-116`, `cloud/cmd/main.go:96-100`, `infra/pulumi/src/components/mgmt-bootstrap.ts:1205,1345`

**Problem:** Both services use identical HMAC secret and audience `"loopzero-cloud"`. Compromise of either service compromises both. No `kid` header, no rotation support.

**Security:** P1 VETO. **SRE:** Conditional veto (needs runbook). **DistSys:** Tolerable for pre-release.

### B4: RSA Tokens Missing `aud` Validation

**Files:** `pkg/jwt/validator.go:93` (no WithAudience), contrast with `:159` (HMAC has WithAudience)

**Problem:** Any Hydra RSA token accepted by any service regardless of intended audience. Token confusion possible when second OAuth2 client exists.

**Security:** P1 VETO. **SRE:** P2. **Verification:** Must have tests.

### B5: Auth Coupled to Tenant Provisioning

**Files:** `cloud/internal/consent/handler.go:200-209`, `cloud/internal/routes/session_token.go:93-107`

**Problem:** Login depends on 3 DB INSERTs succeeding. DB failure = auth failure. Consent handler silently swallows EnsureTenant errors and falls back to `tenantID = "default"`.

**All agents agree:** P1. Decouple. Remove "default" fallback.

### B6 (NEW): Hardcoded Argo Callback Secret

**File:** `infra/pulumi/src/components/mgmt-bootstrap.ts:1340`

**Problem:** `LOOPZERO_ARGO_CALLBACK_SECRET: "cb-loopzero-dev-2026"` hardcoded in IaC source. Anyone who reads the code can forge Argo Workflow callbacks.

**Security:** P1. Move to Pulumi secrets. **Decision:** P2 for this meeting — tracked separately.

### B7 (NEW): `tenantID = "default"` Fallback

**File:** `cloud/internal/auth/middleware.go:64,83`

**Problem:** When JWT has no `tenant_id`, middleware silently sets `tenantID = "default"`. If someone creates a tenant named "default", all failed-provisioning users silently join it. Implicit privilege escalation.

**All agents agree:** Must be removed. Promoted to mandatory fix, ships with B5.

### B8 (NEW): In-Memory Rate Limiter Not Distributed

**File:** `cloud/internal/routes/session_token.go:128-150`

**Problem:** Rate limiter uses `map[string][]time.Time`. Multiple replicas have independent state. Bypassable by distributing requests.

**Decision:** P3 — single replica currently. Track for scale.

## Stage 3 — Technical Confrontations

### Confrontation 1: Tenant ID — UUID vs Human-Readable Slug

| Agent | Position |
|-------|----------|
| Principal Architect | UUID. Slug is cosmetic. Deriving identity from user input is anti-pattern. |
| Distributed Systems | Against UUID. Slug is product requirement for CLI/URLs. Fix race with advisory lock. |
| Security | UUID preferred. Eliminates collision entirely. |

**Resolution:** Hybrid. `tenants.id` = `tn-` + UUID (opaque PK). `tenants.slug` = human-readable display name (UNIQUE, derived from email, collision produces explicit error). CLI shows slug. Internal systems use UUID-based ID. Eliminates resolveSlug and TOCTOU while preserving DX.

### Confrontation 2: Engine HMAC — Drop vs Separate Secrets

| Agent | Position |
|-------|----------|
| Security | Phase 1: separate secrets. Phase 2: engine drops HMAC, RSA-only. |
| Architect | Split SessionTokenIssuer into Issuer/Validator. Asymmetric is target. |
| Distributed Systems | Shared secret is standard. Fix rotation. Not urgent. |

**Resolution:** Engine drops HMAC entirely. RSA-only (public key verification, no secret material on engine). Dashboard→engine calls proxy through cloud or use Hydra tokens. This is the cleanest boundary.

### Confrontation 3: Auth-Provisioning Decoupling Depth

| Agent | Position |
|-------|----------|
| Architect | Non-fatal EnsureTenant. JWT with sub only. Lazy resolution. |
| Distributed Systems | Keep EnsureTenant but make non-fatal. Add cache for returning users. |
| Security | Full decoupling. Separate onboarding endpoint. |

**Resolution:** For pre-release: make EnsureTenant non-fatal in consent handler. Remove "default" fallback. JWT issued with `sub` only on failure. API rejects with explicit "account setup required." Full onboarding endpoint is P2 (before public launch).

### Orchestrator Challenge: Deployment Ordering

Agents did not flag: CLI tokens currently have `aud: []`. Adding audience validation will break all existing tokens. **Deployment constraint:** Configure Hydra audience FIRST → wait for token expiry (1h) → deploy audience validation code.

## Stage 4 — Decision

### Chosen Approach

Execute all fixes as one coherent identity migration. Changes are interdependent and reinforce each other.

### Alternatives Rejected

| Alternative | Reason |
|-------------|--------|
| Fix only B1+B2, defer rest | B3/B4 leave security boundaries open; simple fixes that should ship together |
| Keep slug-based tenant ID with advisory lock | Still derives identity from user input; collision logic remains |
| Keep HMAC on engine with separate secrets | Adds operational complexity; engine can use RSA-only (zero secret material) |
| Full decoupled onboarding microservice | Over-engineering for pre-release |

### Trade-offs Accepted

1. UUID-based tenant IDs require local dev data reset (`task db:reset`)
2. Engine dropping HMAC requires dashboard→engine to proxy through cloud or use Hydra tokens
3. Audience validation requires Hydra reconfiguration before code deployment (ordering constraint)
4. Non-fatal EnsureTenant means first API call may return "setup required" — CLI must handle

### Risks Accepted

| Risk | Severity | Mitigation | Owner |
|------|----------|------------|-------|
| Hydra audience config must deploy before code | medium | Deploy Hydra config first, wait 1h for token expiry | Infra |
| Existing dev data has `tn-slug` format IDs | low | `task db:reset` | Dev |
| Dashboard→engine needs proxy or Hydra token | medium | Cloud service proxies engine calls | API Engineer |

### Risks NOT Accepted (Blockers)

| Risk | Blocking Agent | Condition to Lift |
|------|---------------|-------------------|
| Cross-tenant escalation via TOCTOU | Security, DistSys | UUID tenant ID + no resolveSlug |
| Second user signup blocked | All | github_id dropped or nullified |
| Token confusion (no aud) | Security | WithAudience on RSA + Hydra config |
| "default" tenant fallback | Security | All `= "default"` removed from codebase |
| No concurrent signup test | Verification | Test passes 100/100 runs |

### Mandatory Actions

1. **Migration 000016:** Drop `github_id` NOT NULL + UNIQUE. Update `tenant.go` to stop inserting `github_id=0`.
2. **Migration 000017:** Add `tenants.slug TEXT UNIQUE`. New tenants get `tn-` + UUID as `id`.
3. **Rewrite `EnsureTenant`:** UUID-based tenant ID. Delete `resolveSlug`. Check `RowsAffected`.
4. **Update `pkg/jwt`:** Add `audience` param to `NewValidator` + `NewSessionTokenIssuer`. Enforce `WithAudience` in both `Validate()` and `ValidateSession()`.
5. **Engine drops HMAC:** Remove `SESSION_TOKEN_SECRET` from engine config. RSA-only.
6. **Remove "default" fallback:** Replace `tenantID = "default"` with explicit 403 error.
7. **Non-fatal EnsureTenant in consent:** On failure, issue JWT with `sub` only.
8. **Observability:** Add `loopzero_signup_failures_total`, `loopzero_tenant_provisioning_errors_total`, `loopzero_auth_jwt_validation_total{type,result}`.
9. **Hydra config:** Set audience per OAuth2 client BEFORE deploying code.
