## Context

**Problem:** J-06 Overview needs (1) a plan-price money KPI and (2) a cross-project
deploys aggregate; neither had a backend source. Plan J-06 v1.0 assumed `/v1/billing`
returned a `total_amount_minor` — **factually false** (it returns usage quotas, no
money). Two design decisions required ratification before code.

## Decision (see ADR for full shape + conditions)

- **D1 — Price:** materialize `price.unit_amount` + `currency` from Stripe via the
  **existing webhook** onto new `subscriptions.amount_minor/currency` columns;
  `/v1/billing` **observes** the row (no Go constant → no #157 drift; no live Stripe
  on the hot read path). Field named **`plan_price`** (honest — it is the recurring
  list price, NOT metered spend); KPI labeled "Plan", not "Spend MTD".
- **D2 — Deploys:** new engine `GET /api/v1/builds/stats?window={7d,30d,90d}`,
  server-side SQL `GROUP BY date_trunc('day', … UTC)`, tenant-scoped, dense
  zero-filled `by_day` + `last_7d_count` + `total_count`. Engine stays
  resource-named; screen composition stays in loopzero-cloud (BFF).

## Guardian invariants

| Invariant | Result |

## Verdicts

- platform-security-engineer: **APPROVE_WITH_CONDITIONS** (no absolute veto). Two
  corrections: (a) the webhook does NOT parse `unit_amount` today — net-new work;
  (b) `price.unit_amount` is list price, not spend → name honestly.
- tenant-guardian: **SAFE** (Conditions 1–5 gating).
- PDR: reject live-Stripe-on-read + reject raw-list; server-side aggregate + observed
  price only.
- CVP: design sound + testable; 28 RED-first tests across 5 layers (validation contract below).
- api-domain-architect + principal-architect: consensus on shape; **principal diverges**
  from the distsys-purist raw-list view → **ADR filed** (server-side single-resource
  aggregation is a resource query, not a BFF-leak).

## Key risks accepted (with mitigation)
- **[HIGH] cross-tenant leak (#106/#111):** mitigated by explicit `WHERE tenant_id=$1`
  in the sqlc query (not `tenantpredicate:exempt`) + fail-closed on nil TenantID.
- **[MEDIUM] webhook delivery lag → stale price:** Stripe Prices are immutable; a
  price change is a `subscription.updated` (item swap), so no silent-rotation window;
  only a dropped `.updated` after retries leaves it stale → acceptable, omit-when-NULL.
- **[MEDIUM] list-price ≠ true spend for discounted/metered accounts:** mitigated by
  honest naming (`plan_price`, not "Spend"); true spend deferred to a future
  `invoice.paid` ADR.

## Mandatory actions (owner: implement)

1. Engine migration `000049_subscriptions_spend_columns.{up,down}.sql` — `amount_minor BIGINT NULL`, `currency TEXT NULL` (additive, nullable, reversible).
2. loopzero-cloud `webhook.go`: extend Price parse (`unit_amount`,`currency`) + persist on both `.created`/`.updated` UPDATE branches; preserve on missing-price (no clobber to 0).
3. loopzero-cloud `billing.go GetBilling`: SELECT the new columns; emit additive nested `plan_price`; omit when NULL; starter=0-present.
4. Engine sqlc `BuildStatsByDay` in `api/internal/db/queries/builds.sql` (NOT exempt) + `GET /api/v1/builds/stats` handler (window enum, typed 400, fail-closed) + register in `router.go`.
5. Frontend `useOverviewKPIs` aggregator + KPI strip (label "Plan"); honest "—" on omitted `plan_price`.
6. LIVE-triplet + dogfood wrapper (J-06) per delivered-journey-bar convention.

## Validation contract (CVP — 28 RED-first tests; no task closes until its tests are green)

- **L1 webhook (5):** persists amount+currency (pro/team, .created+.updated); missing-price no-clobber; zero-amount persists 0; atomic-rollback on mid-UPDATE error.
- **L2 /v1/billing (7):** pro→2900; starter→0-present; enterprise→omitted; pro-not-yet-persisted→omitted; ErrNoRows→omit; additive (existing keys byte-unchanged, Rule 5); non-usd currency echo.
- **L3 /api/v1/builds/stats (8):** **tenant-isolation (A excludes B — the #106/#111 protector)**; window enum valid; invalid→typed 400 w/ code; empty-state dense all-zero; UTC midnight bucketing (EC-4); last_7d==sum(by_day[-7:]); sparse zero-fill; unauth→401.
- **L4 frontend vitest (5):** aggregator shape; render real data ("$29.00/mo"); starter "$0"; omitted→honest "—" (never $0/NaN); empty by_day zero-state.
- **L5 migration (3):** nullable/additive on pre-existing row (MA-8); down reversible; idempotent replay.

**Rejected as evidence:** "it compiles"; happy-path only; single-tenant stats test (isolation unproven); `by_day.length>0` instead of exact dense length; migration up-only on empty DB; any Go price constant on the read path.
