## Key Decisions

1. **API creates Build/Release CRDs** (within advisory lock, after DB record)
2. **BuildController creates Argo Workflows** (API no longer does this directly)
3. **CRDs parallel to DB** — not replacement. CRD→DB one-directional sync via StatusSync
4. **Single writer per domain** — controller owns CRD status, StatusSync owns DB updates
5. **Outbox pattern** for dual-write safety (`crd_sync_pending` flag on DB records)

## State Machine Ownership

- Controller invokes `pkg/statemachine/` for CRD status transitions
- StatusSync invokes it for DB propagation
- API never updates build/release state after creation

## CRDs

- Build: spec (sourceRef, buildArgs, imageTag) → status (phase, workflowName, imageDigest)
- Release: spec (imageRef, replicas, envVars) → status (phase, giteaCommit, argoSyncStatus)
