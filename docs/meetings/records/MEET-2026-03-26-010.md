# MEET-2026-03-26-010 — Container Registry Architecture (Harbor)

**Data:** 2026-03-26
**Tipo:** architecture + security
**Status:** APPROVED_WITH_CONDITIONS
**Sponsor:** Principal Architect + Platform Security Engineer
**Challenger:** SRE (operational complexity)
**Owner:** Infra Engineer (Harbor deploy) + Operator Engineer (TenantController)

---

## Contexto

DO Container Registry free plan limita a 5 repos. Professional ($20/mês) tem unlimited repos mas 5TB storage max. A 5.000 tenants × 30.000 repos, nenhum plano DO é definitivo. Security: credenciais compartilhadas entre tenants (FINDING-2) e god-token DO no controller (FINDING-1) são riscos críticos atuais.

## Decisão

**Duas fases: (1) Upgrade DO Professional imediatamente, (2) Migrar para Harbor self-hosted no próximo sprint.**

### Fase Imediata: Upgrade DO Registry

Alterar Pulumi `subscriptionTierSlug` de `basic` para `professional`. $20/mês. Desbloqueia repos imediatamente. Zero mudança de código.

### Fase Definitiva: Harbor Self-Hosted

Harbor no build cluster com S3 backend (DO Spaces) e PostgreSQL externo (**dedicado**, NÃO compartilhado com LoopZero app DB).

```
┌─────────────────────────────────────────────────┐
│ Build Cluster                                    │
│                                                  │
│  Harbor Core (2 replicas)                       │
│  Harbor Jobservice                               │
│  Harbor Registry (Distribution underneath)       │
│  Harbor Portal (optional, admin-only)            │
│  Redis (in-cluster, session/cache)               │
│  Trivy (optional, Sprint 6)                      │
│                                                  │
│  Storage: DO Spaces (S3) ← blobs                │
│  Metadata: Managed PG (DEDICATED instance)       │
│                                                  │
│  Ingress: harbor.dev.loopzero.example (Traefik+TLS)  │
└─────────────────────────────────────────────────┘
```

**Tenant ↔ Harbor mapping:**

| LoopZero | Harbor | Lifecycle |
|------|--------|-----------|
| Tenant | Harbor Project | TenantController creates via Harbor API |
| Build credential | Robot Account (push, 24h TTL) | TenantController reconcile |
| Pull credential | Robot Account (pull, 7d TTL) | TenantController syncs to workload ns |
| Image | `harbor.dev.loopzero.example/{tenant}/{project}/{app}:{sha}` | BuildPlan resolves |

### Proposta Rejeitada: Distribution (registry:2)

| Motivo | Detalhe |
|--------|---------|
| **Security VETO** | Sem RBAC. Credencial vazada = acesso a todas as imagens de todos os tenants. Mesmo blast radius do modelo atual. |
| **Sem audit trail** | Impossível saber quem fez push/pull de qual imagem |
| **Sem quotas** | Um tenant pode consumir todo o storage |
| **Sem immutable tags** | Image poisoning cross-tenant é trivial |
| **Reinventa a roda** | Precisaria construir auth service, GC, monitoring — metade do Harbor |

### Trade-offs Aceitos

1. **Harbor é operacionalmente mais complexo que DO managed.** 5+ componentes vs zero. Aceito porque: per-tenant isolation é requisito de segurança, não nice-to-have.
2. **Custo de infra adicional.** ~$40-80/mês (nodes) + storage. Aceito porque: custo é marginal comparado ao DO Professional a escala.
3. **Build cache invalidated na migração.** Primeiro build de cada tenant após migração será mais lento. Aceito porque: one-time cost.

### Riscos Aceitos + Mitigação

| Risco | Sev. | Mitigação |
|-------|------|-----------|
| Harbor down = builds bloqueados | CRITICAL | 2 replicas core + S3 backend (stateless reads) + alerting |
| PG migration failure no upgrade | HIGH | PG dedicado (não compartilhado). Backup antes de upgrade. |
| Redis crash | MEDIUM | Redis é cache, não estado. Auto-restart via K8s. |
| Trivy scanner consome CPU | LOW | Desabilitar inicialmente. Habilitar Sprint 6. |

### Riscos NÃO Aceitos (Blockers — SRE)

| Blocker | Condição |
|---------|----------|
| Zero alerting | `LoopZeroRegistryUnreachable` alert ANTES de Harbor ir live |
| Zero runbooks | Runbook para: Harbor down, PG failure, S3 unreachable, GC execution |
| Shared PG | Harbor PG DEVE ser instância separada do LoopZero app PG |
| No rollback plan | Rollback documentado + testado (Harbor → DO Registry fallback) |

### Security Findings Addressed

| Finding | Status |
|---------|--------|
| FINDING-1: DIGITALOCEAN_TOKEN god-token no controller | Harbor elimina dependência da DO API. Token removido. |
| FINDING-2: Credencial compartilhada entre tenants | Harbor robot accounts per-project. Blast radius: 1 tenant. |
| FINDING-3: MinIO global credentials fallback | Fora do escopo deste meeting, mas documentado para fix. |
| FINDING-4: 7-day TTL sem rotação proativa | Robot accounts com TTL configurável (push: 24h, pull: 7d). Rotação no reconcile. |
