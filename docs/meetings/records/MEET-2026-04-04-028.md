## Context

Review of the content hash feature that enables `loopzero deploy` without git. Implementation spans CLI (`git.ts`, `deploy.ts`, `init.ts`, `index.ts`) and API (`gitea_store.go`, `source.go`, `store.go`).

## Findings

### CRITICAL (Blockers)

**F-01: Path traversal in tar extraction (VETO)**
- `gitea_store.go:191` uses system `tar xzf` on untrusted archive
- Malicious tar with `../../etc/cron.d/backdoor` can write outside extraction dir
- Impact: arbitrary file write on API server → potential RCE
- Fix: Replace with Go `archive/tar` + explicit path validation per entry

**F-02: Symlink attacks in tar extraction (VETO)**
- No symlink validation on tar entries
- Symlink → `/var/run/secrets/kubernetes.io/serviceaccount/token` → exfiltrate via git push
- Impact: credential theft from API pod
- Fix: Reject symlinks and hardlinks during extraction

### HIGH

**F-03: `.git` prefix bug in `computeDirHash`**
- `strings.HasPrefix(rel, ".git")` matches `.github/`, `.gitignore`, `.gitattributes`
- Impact: source files silently excluded from hash and Gitea commit
- Fix: Check `rel == ".git" || strings.HasPrefix(rel, ".git/")`

**F-04: Dual hash computation — guaranteed divergence**
- CLI: `computeContentHash()` applies full ignore patterns
- API: `computeDirHash()` only skips `.git/`
- Hashes will differ → idempotency breaks
- Fix: CLI sends hash as metadata; API trusts it (or verify-only)

**F-05: `sourceId` dead variable in deploy.ts**
- `getSourceIdentifier()` called at line 215, result never used
- `uploadResult.commit_sha` used instead (comes from API)
- Fix: Remove dead variable or wire it into the flow

**F-06: Zero tests on all new functions**
- `computeContentHash`: 0 tests (determinism, ignore patterns, empty dir)
- `createTarBundle`: 0 tests (valid tar, excluded files)
- `pushTarBundle`: 0 tests (format detection, git conversion)
- `computeDirHash`: 0 tests (bug F-03 would have been caught)
- Modified deploy tests: weakened to pass, not proper coverage
- Fix: Minimum 20 tests across CLI + API

**F-07: Sensitive files check disabled for non-git**
- `checkSensitiveFiles()` returns `[]` without git
- `.key`, `.pem`, `credentials.*`, `*secret*` bundled silently
- Fix: Filesystem-based sensitive file detection for non-git

### MEDIUM

**F-08: No decompression limits** — 500MB compressed → terabytes decompressed
**F-09: COMMIT column misleading** — should be VERSION for both git and content hash
**F-10: `CreateGitBundleFromRepo` leaks into SourceStore interface** — ISP violation
**F-11: Repo naming duplicated 3x** in gitea_store.go
**F-12: Silent deploy** — non-git projects get zero feedback on what's being deployed
**F-13: Init warning is jargon** — "content-based versioning" meaningless to target user

## Decision

**REJECTED.** Implementation must be reworked before merge. The feature design is sound but the implementation has 2 security vulnerabilities (VETO), 5 correctness issues, and zero test coverage.

## Mandatory Actions (Priority Order)

### P0 — Security (Unblock Vetoes)

1. **Replace `tar xzf` with Go `archive/tar`** — validate every entry: no symlinks, no hardlinks, no `..`, no absolute paths, decompressed size limit (5GB), file count limit (100K)
2. **Implement filesystem-based sensitive file check** for non-git projects — same patterns as git-based check

### P1 — Correctness

3. **Fix `.git` prefix matching** — `rel == ".git" || strings.HasPrefix(rel, ".git/")`
4. **Eliminate dual hash** — CLI sends content hash as metadata, API uses it directly
5. **Remove `sourceId` dead variable** or wire into flow
6. **Collapse SourceStore to 1 method** — `PushBundle` returns `(sourceID, bundlePath, error)`
7. **Extract repo naming** into single function

### P2 — DX

8. **Rename COMMIT → VERSION** in build list/inspect
9. **Add deploy feedback** for non-git: "Deploying all files in current directory"
10. **Rewrite init warning** with explanation + suggestion
11. **Exclude `loopzero.yaml` from content hash**

### P3 — Tests (Gate for Merge)

12. **CLI unit tests**: `computeContentHash` (6), `createTarBundle` (3), `getSourceIdentifier` (3)
13. **API unit tests**: `computeDirHash` (3), `pushTarBundle` (3), path traversal rejection (2)
14. **Init warning test**: JSON output with/without git
15. **E2E**: deploy without git on DO
