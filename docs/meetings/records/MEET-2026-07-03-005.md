## Context

**Problem:** J-16 v0.1 shipped webhook *registration* (CRUD) with a "Delivery coming soon"
banner. Slice 3 adds the worker that POSTs `deploy.succeeded`/`deploy.failed`/
`build.succeeded`/`build.failed` to the customer-registered URL. The handoff recommended
"mirror the memory-webhook worker". The board's job: ratify the design **before** code.

**Prior art:** `loopzero-cloud/internal/memory_webhook_worker/` — poll + `FOR UPDATE SKIP LOCKED`
claim, exp-backoff+jitter (9 attempts → dead_letter), HMAC-SHA256 signing (Stripe
`t=…,v1=…`), stable `Idempotency-Key`, 30s per-attempt timeout.

## Findings (why "mirror verbatim" was REJECTED)

### 1. SECURITY — absolute veto (platform-security-engineer)
- The prior-art worker is a **live, exploitable SSRF sink in production TODAY** (customer URL →
  `http.Do` with default transport, no egress guard → can reach `169.254.169.254` cloud
  metadata → IAM creds; response body persisted → exfil channel). Filed as **loopzero-cloud#148 (CRITICAL)**.
- Mirroring it would replicate a live vuln into a second surface. **VETO** until the conditions are met.

### 2. BOUNDARY — the deploy-event trigger (api-domain-architect)
- Deploy events fire in the **engine**; the worker lives in **loopzero-cloud**; the two repos MUST NOT
  import each other (decoupling invariant). Chosen: **Option C — transactional outbox.** The engine
  writes ONE generic `deploy_events` row **inside the state-transition tx** (`ActivateReleaseKernel`'s
  `tx`, symmetric build→FAILED tx); loopzero-cloud drains it and fans out to `workspace_webhooks`.
  Rejected: (A) engine SELECTing `workspace_webhooks` (engine becomes a control plane for a cloud
  feature); (B) cloud polling the churny `releases`/`builds` tables via a hand-rolled cursor
  (silent event loss on cursor gaps); reuse of the ephemeral SSE deploy-timeline (non-transactional,
  30-min-capped — not a durable source).

### 3. DURABILITY — do not inherit at-most-once (distributed-systems-engineer)
- The memory `Publish` is **at-most-once** (non-transactional, request-scoped, errors swallowed) → a
  crash between the ACTIVE commit and the enqueue **silently drops `deploy.succeeded`** with no
  detection. The claim lifecycle also has a **permanent `'delivering'` orphan class** (crash after
  claim-flip, before record; nothing re-claims it) — routine under multi-replica. `retry.go` backoff
  is **uncapped** (~4.25h to dead_letter) while its comment claims a 3600/7200 cap (stale).

## Decision (design ratified WITH conditions)

- **Enqueue:** engine transactional outbox `deploy_events` (migration **000051**, engine-owned/written/
  never-read), written on the state-transition `tx`. `deploy.succeeded`/`deploy.failed` are the frozen
  contract, matching the `workspace_webhooks.events` enum. `correlation_id` forwarded through the payload.
  A retention reaper mirrors the release reaper (append-only ≠ grow-forever).
- **Fan-out + queue:** `workspace_webhook_deliveries` (migration **000052**, engine-owns-DDL, cloud
  reads/writes) with **`UNIQUE (transition_id, webhook_id)`** — `transition_id` is per *entry* into ACTIVE
  (NOT `release_id`; the Release machine re-enters ACTIVE after rollback recovery, so `release_id` alone
  would suppress a legitimate second event). Cloud fan-out is idempotent (`ON CONFLICT DO NOTHING`).
- **Worker:** reuse the memory worker's `dispatcher`/`retry`/`signing` core; **redesign** claim lifecycle:
  add `claimed_at`/`claimed_by` lease + a **visibility-timeout reaper** (`status='delivering' AND
  claimed_at < NOW()-90s → failed, next_attempt_at=NOW()`); set `ClaimBatch ≈ MaxInFlight`; per-tenant
  fairness (no global-order starvation); embed a per-`(project,environment)` monotonic `sequence` +
  `event_id` in the payload so at-least-once + reorder is consumer-safe; port the replay endpoint 1:1;
  add a `dead_letter` metric + alert; cap the backoff and fix the comment.
- **Egress security (blocking):** shared **`internal/safehttp`** client — `Transport.DialContext` →
  `Dialer.Control` rejecting the **resolved** IP (loopback / 169.254.0.0/16 / RFC1918 / fc00::/7 / ::1 /
  unspecified / multicast) at connect (defeats DNS rebinding) + `CheckRedirect` → `ErrUseLastResponse`
  (no redirects). Injected into **both** the workspace worker **and** the memory worker (retro-fixes #148,
  no copy-paste). `https://`-only; signing secret **encrypted at rest** (OpenBao Transit `vault:v1:`);
  per-tenant active-webhook cap + auto-revoke circuit breaker on sustained dead-letter; payload
  **field-allowlist** (`event_type, deploy_id, project, status, timestamp`) with a Rule-3 denylist test.

## Conditions for approval (all BLOCKING — Security + SRE hold absolute veto)

1. `internal/safehttp` egress guard (dial-time resolved-IP reject + redirects disabled), injected into BOTH workers; **#148 retro-fixed atomically**.
2. SSRF test suite (loopback v4/v6, 169.254 metadata, RFC1918 table, **DNS-rebinding**, **redirect-to-internal**, public-allowed) — each proves **zero socket** to the internal target, not merely a returned error.
3. Transactional outbox: enqueue inside the state-transition `tx`; rollback → 0 rows (tested). Engine import graph contains **zero** `loopzero-cloud/...`; worker import graph contains **zero** `loopzero/api/...` (both asserted in `task quality:gates`).
4. `UNIQUE (transition_id, webhook_id)`; lease + 90s reaper closes the `'delivering'` orphan class; delivery-semantics + SKIP-LOCKED concurrency + 9th-failure→dead_letter tested against a **real Postgres** (the memory `worker.go` has zero tests — do not inherit the gap).
5. Payload field-allowlist + Rule-3 denylist grep (no `argocd|gitea|minio|tenant_id|kubeconfig|cell|svc.cluster.local`).
6. `https://`-only; signing secret Transit-encrypted at rest; `List`/`Get` never return `secret`; per-tenant caps + auto-revoke circuit breaker.
7. Migrations 000051/000052 forward-only (+ `.down.sql`), idempotent, `schema.gen.sql` regenerated; CHANGELOG updated in **both** repos.
8. Runtime metrics: `loopzero_workspace_webhook_enqueued_total`, `…_delivery_total{result}`, `…_ssrf_rejected_total{reason}`, attempt-duration histogram — each incremented by a test path.

## Impact if ignored
Shipping the mirror hands every authenticated tenant a POST-from-inside-the-VPC primitive (metadata →
IAM → cross-tenant breach) **and** silently drops deploy events on any pod restart. The SSRF sink is
**already live** via the memory worker (#148).
