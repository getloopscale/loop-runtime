## Root cause (confirmed via reconcile logs + code, all 3 reviewers)

The environment reconcile sets the `NameTooLong`/`InvalidEnvRef` condition + phase `Empty→Pending`, then persists via a refetch-then-restore `r.Status().Update`. On an optimistic-concurrency conflict the code `return ctrl.Result{}, nil` (no requeue) — silently dropping the condition AND the phase. The second writer is the **Tenant controller** (`tenant_controller.go` `Owns(&Environment{})` + `CreateOrUpdate` bumping `AnnotationParentGeneration`), which writes Environment spec/metadata sharing the object resourceVersion with the `/status` subresource → 409. With phase never persisted as Pending, `reconcileDelete` later calls `TryTransition(Empty, DeleteRequested)` — an edge absent from `pkg/statemachine/environment.go` (valid only from Pending/Failed/Active) → "invalid state transition for delete". The refetch-then-restore pattern is a secondary anti-pattern (clobbers fresh status with a stale snapshot).

**Environment `.status` has exactly ONE writer** (the environment controller); the Tenant controller writes only Environment spec/metadata. This precondition makes a merge-patch fix safe.

## Decision + mandatory actions

**APPROVED_WITH_CONDITIONS.** T2 ratified (additive SM edge signed off by the state-guardian, who owns the machine).

- **MA-1:** Convert all four status-write sites in `operators/internal/environment/environment_controller.go` (InvalidEnvRef, NameTooLong, per-step loop, final Active) to `r.Status().Patch(ctx, &env, client.MergeFrom(base))` where `base` is a DeepCopy captured right after the initial Get (before any status mutation). Delete the `savedStatus`/refetch-restore dance. A merge patch carries no resourceVersion → no 409; sends only changed fields → cannot clobber the single-writer status.
- **MA-2:** No status-write path may `return ctrl.Result{}, nil` on a write failure — return the error (requeue). Reconcile is idempotent and re-derives `NameTooLong` each pass, so requeue converges.
- **MA-3:** Add the additive edge `EnvironmentEmpty --EnvironmentDeleteRequested--> EnvironmentDeleting` to `pkg/statemachine/environment.go`; keep `Deleting` the sole terminal. Update the stale transition doc comment (`environment_typed.go`) + the `InvalidTransitionPanics` assertion in `pkg/statemachine/environment_test.go` (Empty→Delete is now valid). Do NOT special-case delete in the controller (Rule 8 — the edge belongs in the SoT machine).
- **MA-4:** Set `env.Status.ObservedGeneration = env.Generation` on the NameTooLong/InvalidEnvRef branches (status must not under-report the observed generation).
- **MA-5 (deterministic proof):** New unit tests — (a) `pkg/statemachine`: Empty→DeleteRequested→Deleting valid + terminal-finality preserved; (b) `operators/internal/environment` with `controller-runtime/pkg/client/fake` + a conflict-injecting status client: NameTooLong/InvalidEnvRef condition PERSISTS after an injected `Status().Patch` conflict; (c) delete-from-Empty removes the finalizer without error.
- **MA-6 (corroboration):** envtest stress — `go test ./operators/internal/tenant/ -count=N` clean, zero `object has been modified` / `invalid state transition` / t31 timeout. N chosen so a partial fix (residual ~10%) is caught.
- **MA-7:** Remove the FlakeAttempts/quarantine comment from `environment_controller_t31_test.go`; CHANGELOG `[Unreleased] § Fixed`; close the finding with the stress evidence.
- **MA-8:** Document the single-status-writer invariant (code comment + `rules/loopzero-design.md`).

### Risks accepted

| Risk | Mitigation |
|---|---|
| Merge-patch correctness depends on status having one writer | MA-8 documents the invariant; a future 2nd status-writer must revisit |
| Empty→Deleting runs delete GC from Empty | benign — namespace Get returns NotFound → finalizer removed; no code assumes a provisioned namespace on delete |
| Requeue-on-conflict re-reconciles until the write lands | converges (deterministic derivation); not a hot-loop |

### Alternatives rejected

- **RetryOnConflict around the refetch-restore snapshot** — rejected: re-applies a stale status blob over fresh state (lost-update). Merge-patch is strictly better (single field, single writer).
- **Controller-side no-op bypass for delete-from-Empty** — rejected: erodes Rule 8 (SM is the SoT). The additive edge keeps every delete flowing through the machine.
