## Stage 1 — Context

### Problem

Three quality gaps in Helm charts:

1. **No schema validation in published charts.** `find charts -name values.schema.json` = 0. Misconfigured `values.yaml` (wrong type, missing required field) silently passes `helm lint` and only fails at deploy. Bitnami treats schema as standard.
2. **No helm-unittest tests.** The 5 existing `tests/test-connection.yaml` files are `helm test` probes (post-deploy connectivity checks), NOT helm-unittest pre-render assertions. We have ZERO unit tests for chart template logic — meaning conditional rendering (e.g., `if .Values.networkPolicy.enabled`) is not validated.
3. **securityContext inconsistency.** 55 occurrences of `runAsNonRoot|readOnlyRootFilesystem` across 33 bootstrap charts — but no audit confirms uniformity. Some charts genuinely require privilege (`promtail`, `nfs-server-provisioner`, `chaos-mesh`, `cloudflared`). Others are simply missing the directive without justification.

### Decision Required

1. Approve `values.schema.json` mandate for `charts/` (15 charts), but NOT for `infra/helm/` (33 charts) per ADR D4.
2. Approve helm-unittest scope: 5 charts × ≥ 3 tests each, focused on security-critical conditional logic (D5).
3. Approve audit-first / fix-or-document approach for `infra/helm/` securityContext (D7).
4. Approve CI enforcement (`audit-security-context.sh --gate`).
5. Approve ADR-of-exception convention for charts that legitimately need privilege.

### Constraints

- D4: schema mandatory in `charts/` only. Bootstrap charts are internal, simple, fixed values — schema overhead without return.
- D5: 100% template coverage is YAGNI; security-critical branches are the value.
- D7: forcing `runAsNonRoot:true` on `nfs-server-provisioner` breaks it. Exception path required.
- Charts in `charts/` are published via OCI to `registry.digitalocean.com` — schema must be consumable by ArgoCD Helm rendering.
- `loopzero-common` is a library chart — no values.schema.json required, but it documents inputs for consumers.

## Stage 2 — Analyses

### Verification Architect — Sponsor (CONDITIONAL VETO)

**Assessment.** Schema validation is a formal correctness gate. helm-unittest is a unit test layer that's currently absent. Without these, we have no proof that templates render as intended for the security-critical paths. The audit of bootstrap charts is the right shape: read-only first, classify, then either fix or formally document the exception. Forcing uniformity creates broken-but-shipped charts; ADR-of-exception keeps the trade-off auditable.

**Position.** APPROVE. **Condition:** every chart marked NON-CONFORMANT in the audit MUST have either a fix OR an ADR file `infra/helm/<chart>/ADR-securitycontext-exception.md` before T3.3 (CI gate) is enabled. Half-completed audit with `# TODO: fix later` comments is not acceptable.

**Veto if not met.**

### Production Design Reviewer — Challenger

**Assessment.** Bitnami's schema discipline is industry baseline. The 15 charts × `values.schema.json` is mandatory. helm-unittest scope must NOT slip toward 100% template coverage — that's the trap that turns a good idea into shelfware. Stick to security-critical branches (D5).

**Risks.** (1) Schema too strict (e.g., requiring `image.digest` always) breaks dev workflow where digest is set late. (2) helm-unittest `set:` overrides may not match production values shape — tests must use realistic values. (3) Audit produces ~10 charts NON-CONFORMANT; fixing all in one sprint is realistic but documenting all exceptions is the harder part.

**Position.** APPROVE. **Condition:** schemas validated by `ajv compile` to ensure they're parseable JSON Schema Draft 7; bad schemas at lint time fail CI.

### Principal Architect

**Assessment.** D4 (schema only in `charts/`) is correct. D5 (security-critical scope for helm-unittest) is correct. D7 (audit-first) is correct. D8 (gate without enforcement is not a gate) requires that this entire phase ends with `infra-gates.yml` consolidating all checks as required CI. Without that, the work is documentation, not platform.

**Position.** APPROVE.

### API/Domain Architect

**Assessment.** Schemas express the API contract for chart consumers (operators of those charts). LoopZero's charts are consumed by: (a) LoopZero platform itself via ArgoCD, (b) future external operators (e.g., enterprise self-host). For both, schema is documentation + validation. helm-unittest is the unit test layer of the same contract.

**Position.** APPROVE.

## Stage 3 — Decision

### Verdict: APPROVED

### Mandatory Conditions

1. **Schemas mandatory in `charts/` only.** `infra/helm/` is exempt per D4.
2. **helm-unittest scope locked.** 5 critical charts × ≥ 3 tests on security-critical branches. NO scope creep to 100% coverage.
3. **Audit-first for securityContext.** T3.1 (read-only) MUST complete before T3.2 (fix-or-ADR).
4. **Each NON-CONFORMANT chart has a verdict.** Either fixed code OR ADR-of-exception. No half-state.
5. **CI gate is the closure.** T3.3 (`audit-security-context.sh --gate`) blocks PRs that introduce NON-CONFORMANT charts without ADR.
6. **Schemas validated as JSON Schema.** `ajv compile` step in CI rejects malformed schemas.

### Rejected Alternatives

- **Schema for all 48 charts (`charts/` + `infra/helm/`).** Rejected per D4: bootstrap charts have fixed internal values; schema is overhead.
- **100% helm-unittest template coverage.** Rejected per D5: YAGNI. Security-critical only.
- **Force uniform securityContext.** Rejected per D7: breaks legitimate-privilege charts.
- **No CI gate on audit.** Rejected per D8: gate without enforcement is documentation.
