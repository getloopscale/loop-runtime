# MEET-2026-04-01-025: Pipeline Idempotency — Destroy+Recreate Architecture

**Date:** 2026-04-01
**Type:** pipeline, architecture
**Verdict:** APPROVED_WITH_CONDITIONS
**Agents:** SRE Engineer, Principal Architect, GitOps Engineer

---

## Problem

`pulumi destroy && pulumi up` fails because Pulumi creates Deployments that reference container images that don't exist yet. The registry is recreated empty and DOKS clusters lose registry credentials.

## Root Cause (unanimous agreement)

The Pulumi program creates **infrastructure AND application workloads** in the same `pulumi up`. This violates build/release separation. Deployments are created before images exist.

Additional finding: `tenant-controller` Deployment was missing `skipAwait` annotation — causing Pulumi to block and timeout waiting for pods that can never start.

## Decision

### Immediate Hotfix (applied now)

1. Add `skipAwait` to tenant-controller Deployment
2. This unblocks Step 1 so it completes even when images don't exist

### Architectural Change (next session)

Split the single Pulumi program into phases with explicit gates:

**Phase A: Infrastructure Only** — VPC, clusters, DB, registry, Spaces, Helm charts (public images only: cert-manager, Traefik, ArgoCD, Gitea, MinIO, Prometheus)

**Gate: Build Images** — docker build + push to registry + doctl registry add

**Phase C: Application Workloads** — loopzero-api, tenant-controller, gitea-bootstrap, CWTs (images now exist)

Implementation options:
- **Option 1 (Pulumi config gate):** `if (config.imageTag !== "none")` guards app Deployments
- **Option 2 (Separate Pulumi stacks):** `infra-core`, `infra-platform`, `infra-apps` with stack references
- **Option 3 (Conditional in workflow):** Step 1 runs with `--config imageTag=none`, Step 3 with real tag

### Additional Requirements (from SRE)

1. Registry integration via Pulumi `Command` resource (not `doctl` in CI)
2. cert-manager readiness via deterministic check (not 90s sleep)
3. Post-deploy health gate (mandatory, not continue-on-error)
4. Registry import logic in pre-Step-1 (alongside VPC/bucket imports)
5. Remove `|| true` from critical-path operations

## Alternatives Rejected

- **Retry + sleep:** Treats symptoms, not root cause. Cannot fix missing images.
- **Pre-build images:** Inverts dependency (can't push to non-existent registry).
- **Make all Deployments skipAwait:** Masks problem. Pods still fail. Platform is degraded.

## Risks Accepted

- Hotfix (`skipAwait`) leaves pods in ImagePullBackOff during Step 1 — acceptable because Step 3 converges
- Single Pulumi program until architectural split is implemented
