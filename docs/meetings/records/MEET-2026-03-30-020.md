## Context

Full dogfood audit (40 tests, 37 PASS) revealed 8 findings. The system deploys end-to-end but has critical gaps in state lifecycle, observability, and CLI output that make it "a working system that appears broken" (DX Engineer).

## Findings Summary

| ID | Severity | Title | Root Cause |
|----|----------|-------|------------|
| F-01 | S1 | Build stuck RUNNING | `UpdateStatus` never sets `started_at` → reaper SQL returns NULL → RUNNING builds never reaped. Reconcile loop has no circuit breaker for repeated `OnBuildCompleted` failures. |
| F-02 | S1 | Logs unavailable | Loki not installed locally, no fallback, no user-facing indication of unavailability |
| F-03 | S2 | Deploy says "no URL" for server apps | CLI not checking IngressRoute existence for server-type apps |
| F-04 | S2 | `finished_at`/`duration_seconds` empty | `UpdateStatus` only writes `status` column. No code path sets `finished_at` for SUCCEEDED builds. |
| F-05 | S3 | whoami email empty | Email not persisted after login |
| F-06 | S3 | Inconsistent JSON error shape | Multiple error serialization patterns across handlers |
| F-07 | S3 | ArgoCD "Progressing" | Orphaned IngressRoute for static frontend. Blocks ALL notifications for tenant. |
| F-08 | S4→S1 | `loopzero_build_queue_depth` stale | `BuildQueueDepth.Inc()` exists. Zero `Dec()` calls. Gauge only goes up. SLO alerts permanently fire. |

## Veto Items

| Agent | Veto | Condition |
|-------|------|-----------|
| **SRE** | F-08 | `BuildQueueDepth` gauge must decrement. Current state: two SLO alerts permanently firing = alert fatigue. |
| **SRE** | F-07 | ArgoCD stuck Progressing must have detection mechanism. Current state: silently kills all deploys for tenant. |
| **DX** | F-01+F-02+F-03 | Must fix before any external user. Current state: user deploys, system says it's still running, no logs, no URL. |
| **Verification** | Reconcile loop tests | 562 lines, 0 tests. Rule 1 violation. Every fix PR must include regression test. |

## Causal Chain Discovery

```
F-04 (started_at never set)
  → F-01 (reaper can't reap RUNNING builds — SQL WHERE started_at < $2 returns NULL)
    → F-08 (BuildQueueDepth never decrements — builds never reach terminal state)
      → SLO alerts permanently fire → alert fatigue → F-01 undetectable by monitoring
```

**Fix F-04 first.** It unblocks the reaper, which mitigates F-01, which allows F-08 to decrement correctly.
