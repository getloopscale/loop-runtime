## Guardian invariant sign-off — WITHHELD (both)

### tenant-guardian: INV-1 ⚠️ · INV-2 ✅ · INV-3 ✅ · INV-4 ❌ · INV-5 ❌
- **INV-4 ❌ (real bug):** the plan derives namespaces via `pkg/naming.TenantNamespace` → single `loopzero-{tenant}` (`naming.go:90-92`), but M2 workload pods live in `loopzero-{tenant}-{project}-{env}` (`naming.go:102-117`), derivable only from PG (projects × environment_targets). The producer meters the wrong (empty) namespace → **systematic under-billing of every multi-project tenant**, masked by the single-pod Goal test.
- **INV-5 ❌:** attribution-anchored-to-PG (MEET action 19) was deferred to the follow-up (plan:264); Security required it HERE. No negative test that a mutable `loopzero.io/tenant` pod label (`naming.go:239,260-276`) is ignored.

### state-guardian: INV-1 ⚠️ · INV-2 ❌ · INV-3 ❌ · INV-4 ✅
- **INV-2/INV-3 ❌ (design gap):** period-rollover split is a DECLARED TEST (`TestMeteringLoop_SplitsDeltaAcrossPeriodBoundary`, plan:234) with NO design mechanism — ADR-4's single-period `UPDATE ... WHERE period_start=$p` (plan:85) cannot write two period rows, and as an UPDATE (not upsert) it affects 0 rows when the new-period row does not yet exist. **Needs ADR-9 + upsert-per-period.** Confirms Verification R2.
- **INV-1 ⚠️ (real bug):** `ListActiveTenantsWithCell` filters `status='ACTIVE'` (plan:173) but the canonical constant is `TenantActive = "Active"` (`pkg/statemachine/tenant.go:11`, mixed-case). If `tenants.status` persists `"Active"`, the literal matches ZERO rows → **silent whole-fleet metering loss**.
- **INV-4 ✅:** `metering_cursor` correctly period-independent (keyed `(tenant,metric,cell)`, no period column) — the right substrate for the split.

Per governance rule 4 (guardian invariant violation = BLOCKER), the meeting CANNOT reach unconditional APPROVED until both guardians sign. They will re-sign on the v1.2 conditions below.

## Consolidated v1.2 conditions (deduplicated across all 7 v1.1 reviews)

**A. Write-path correctness (Security, Verification, state-guardian):**
1. Re-express ADR-4 as a **two-table data-modifying CTE** (`metering_cursor` CAS+fence → `cost_counters` increment → `usage_records` upsert, one tx). The "single atomic UPDATE" text is literally wrong across two tables.
2. **ADR-9 (period-rollover split):** same-tx two-write split (tail→P1, head→P2) from one cursor advance; period boundary from a deterministic billing-period function (never read from `cost_counters`); each period write an **upsert** (`INSERT ... ON CONFLICT (tenant_id,metric,period_start) DO UPDATE`) so P2's row is created. Remap Coverage-Matrix action 8 to ADR-9 (design), Task 6.1 as verification only.
3. Bound ADR-8 clamp `k×interval` **< one billing period** (else N-boundary split needed).
4. Spell out the fencing subquery (which lease `name`/`cell_id` predicate against `leader_generations`); confirm `current_generation` is written atomically on lease acquire **before** any meter write (SRE R4 — else a new leader fences its own writes).

**B. Tenant isolation / attribution (tenant-guardian, Security):**
5. Replace `TenantNamespace` with **PG-derived enumeration**: per ACTIVE tenant on its resolved `cell_id`, query its (project, env) pairs → `naming.Namespace(tenant,project,env)`; sum pods across ALL its namespaces on that cell into ONE `(tenant,metric,cell)` delta. Add `TestMeteringLoop_MetersAllProjectEnvNamespaces_SingleCursorNoDoubleCount` (PG-REAL) + make the Goal fixture multi-namespace so it can't pass on the single-namespace shortcut.
6. Pull MEET action 19 back into THIS plan: `TestMeteringLoop_IgnoresMutablePodTenantLabel` (pod bearing a forged `loopzero.io/tenant` in tenant A's namespace bills to A) + `TestCollect_RejectsForeignNamespacePods`. List pods **per PG-derived namespace**, never by cross-cell label selector.
7. Attest the cross-cell `ClusterCredential` is read-scoped (`get/list pods`), not cluster-admin (Security least-privilege).

**C. State correctness (state-guardian, PDR):**
8. Bind the ACTIVE filter to the canonical `TenantActive` constant (confirm `tenants.status` stores `"Active"` vs `"ACTIVE"`); add a state-literal **drift guard** (analogue of the Task 1.2 metric-enum guard) in `task quality:gates`.
9. Lock `metering_cursor` period-independence (keyed `(tenant,metric,cell)`, no `period_start`, no reset at rollover) with an assertion/ADR line.
10. Read-only tenant-state attestation test (worker emits no Tenant Event, calls no Transition).
11. Add a **per-tenant-coverage** signal (`loopzero_metering_tenants_metered_total` vs active-tenant count) so a subset-enumeration miss pages (`MeteringStalled` only catches total silence).

**D. Operability / production fitness (SRE, PDR):**
12. **Bounded write path with pool isolation as a designed Phase-3 task** (NOT risk-table prose): a dedicated small `pgxpool` for the metering worker (preferred) OR bounded-concurrency + per-write breaker recheck, so the burst physically cannot exhaust the API pool. **Gated DoD:** load test at 1,500 tenants (post-namespace-fix volume) proving the API `pg_breaker` does not trip → no 503 on the deploy path. **(SRE R1 + PDR C1 — BLOCKER for LIVE merge.)**
13. **Panic-recovery boundary + single-flight** around `RunOnce` (`loopzero_metering_panics_total`; no overlapping passes) — a meter panic must not crash the controller running the deploy path.
14. Name the kill-switch config source = **DB row / per-tick read** (not ConfigMap mount — kubelet refresh defeats MTTR-seconds).
15. **ADR for raw-LIST vs informer** (conscious choice) with a documented `loopzero_metering_pass_duration_seconds` ceiling that triggers informer migration.
16. Extend the rollback runbook to correct `cost_counters` AND reset `metering_cursor`, not only `usage_records`.
17. State `metering_cursor` RLS = disabled by design (control-plane cursor).
18. Confirm no Stripe reporter consumes the new compute `usage_records` rows until the enforcement follow-up (observe-only bounds the 402 surface, NOT the invoice surface).

**E. Verification gate (Verification, CVP):**
19. **PG-REAL mandate in the DoD:** P1–P9 + I1–I3 + all migration tests run against **real Postgres** with `cost_counters_tenant_isolation` loaded, connection under the `loopzero_worker` role. sqlmock confined to loop/collect logic (S5–S7). Explicit in the plan.
20. **Negative RLS twin** `TestMeterCompute_WithoutRLSBypass_WritesZeroRows` (proves `SET LOCAL` is load-bearing).
21. **LIVE must be ≥2-cell** with a tenant deliberately spanning cells (single-cell never exercises per-cell keying); chain per `cleanroom-up-live-test-mandate.md` + sponsor JUNTOS + zero-402 assertion + rollback rehearsal.

**F. Scope (PDR, recommended):**
22. **Split Phase 4 (pricing) into its own follow-up** to shrink the LIVE-validation diff. Do NOT split the metering loop itself further (interdependent invariants).
