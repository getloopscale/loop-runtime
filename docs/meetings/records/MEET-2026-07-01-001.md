## Context

**Problem:** LoopZero has billing *tables* (`usage_records`, `cost_counters`) and enforcement *mechanism* (`CapChecker`/`CostEnforcer` → 402) but **zero producers** — the counters are never written, so caps are inert. The plan ships the first producer: a leader-elected background worker that meters allocated CPU/mem (`pod.Spec.Requests`) per ACTIVE tenant across cells, writes the counters, enforces a NEW per-plan compute 402 cap (new `CostMetric` in the `loopzero-contracts` sibling repo, tag v0.2.0), and replaces hardcoded `ComputeMonthlyCost` with a DB-backed pricing table.

## Technical Confrontation — convergent BLOCKERs

All five reviewers converged independently on the same core defect: **the write path is not transactionally correct for a money counter.** Specifically:

1. **RLS write-context (Security BLOCKER).** ADR-1 places the worker in the background-loop class that `mig 000023_loopzero_worker_role` moved to the non-owner `loopzero_worker` role — **for which RLS policies APPLY.** The plan quotes the *stale* `000017` comment ("control plane bypasses RLS"). If the worker's pooled connection carries a stale `app.tenant_id`, per-tenant UPSERTs for all other tenants match the policy against the wrong tenant → **0 rows written, no error.** Silent revenue loss; and because enforcement reads fail-open, the caps also never fire.
2. **Non-atomic read-modify-write (DistSys + Security + Verification).** Task 2.3 splits the "advance the meter" into 4 separate `:exec` statements with no transaction. A crash between them re-meters the interval → **double-count.** ADR-4's "advance only on success" is void without atomicity.
3. **NULL-bootstrap (all).** `last_metered_at` is added nullable with no seed. First tick computes `now − NULL/epoch` → **~decades of compute billed instantly** → 402 lockout for the whole fleet on day one.
4. **Two-leader / no fencing (DistSys + Security + SRE).** A `leader_generations.generation` fencing token EXISTS (`leader/election_test.go:58,172`) but is never passed into the counter write. During lease handoff two passes both advance → **double-bill.** Lease-based leadership does not guarantee single-writer without a CAS/fence.
5. **Coarse `last_metered_at` key (DistSys + Verification).** Keyed `(tenant, metric)` but a tenant spans multiple cells; `QueryAllCellsParallel` error isolation *guarantees* partial passes → every partial-cell failure loses OR doubles an interval.
6. **Clock skew (DistSys + Verification).** Delta from the Go clock, not DB `now()` → negative delta on failover.
7. **Gap spike (SRE + DistSys + Verification).** No max-delta clamp → a 6h outage bills 6h in one tick.
8. **Period rollover (State-domain via DistSys + Verification).** Delta straddling a period boundary is misattributed; no finalizer story; leader-down-across-month-end is the common case.
9. **Operability gaps (SRE).** No kill switch without redeploy; bypasses `pg_breaker` (worker can saturate PG and trip the API breaker → 503 to paying users); no freshness SLO/alert (a stalled meter = silent revenue loss, nobody pages); reuses the 5s interactive timeout → slow-cell starvation.
10. **Architectural honesty (Architect).** Metric-enum has two masters (contracts constant + SQL CHECK) with no drift guard; data-source SoT (pod.Spec vs declared scaling config) chosen by copying sealos, not deliberately; `QueryAllCellsParallel` cannot be "reused verbatim" (returns `*CellStatus`, not pod data); the plan reads as if it activates cost enforcement broadly (egress/docr/build caps stay inert).

Consensus was NOT immediate agreement — the five attacked from different angles and converged, which raises confidence in the finding.

## Decision

**DEFERRED — BLOCKED.** Two absolute vetoes (Security + SRE) + one conditional veto (Verification) prevent `/implement`. Per governance rules, Security/SRE veto is absolute. The plan returns to `/to-plan` for a corrective revision (a design change, not test-tacking), then re-runs this T2+ meeting with the missing governance + guardian agents.

**Additional structural decision (all reviewers):** **decouple metering (producer) from enforcement (402).** Ship + LIVE-validate the producer in **observe-only** first; wire the 402 only after (a) counters are proven correct in production and (b) cap numbers are sponsor-ratified.

### Alternatives considered
- **Approve with halt-loop fixes** — rejected: the defects are transactional/design-level (single-statement atomic write, per-cell keying, fencing), not patchable reactively in `/implement`; a money-writer must be correct by design on paper.
- **Reject outright** — rejected: the architecture (ADR-1/2/3/5) is sound; only the write-path + operability need rework.

### Trade-offs accepted
- Slower path to shipping metering, in exchange for a billing writer that is transactionally correct, RLS-explicit, fenced, observable, and stoppable.

## Mandatory actions (conditions to lift the vetoes)

**Correctness (Security + DistSys + Verification):**
1. **Single atomic write per (tenant, metric, cell) tick** — one `UPDATE ... value = value + Σreq*EXTRACT(EPOCH FROM(now()-last_metered_at)), last_metered_at = now() WHERE ... AND last_metered_at = $expected` — delta + advance from the **same DB `now()`**, guarded by **CAS on `last_metered_at`**; collapse the 4 `:exec` queries. Write `usage_records` in the **same transaction**.
2. **Consume the leader fencing token** (`leader_generations.generation`) in the write `WHERE` clause — reject a demoted leader's late write.
3. **RLS write-context** — the write tx MUST `SET LOCAL app.tenant_id = ''` (per mig 000023 contract) on a connection proven not to carry pooled tenant context, OR run as owner with an explicit ADR. Confirm + document `usage_records` RLS status; apply the same fix if enabled.
4. **NULL-bootstrap = 0** — seed `last_metered_at` on tenant activation/first sight; first tick charges ≤ one interval.
5. **Per-cell keying** — key `last_metered_at` at `(tenant, metric, cell)`; resolve each tenant to its own `cell_id` (targeted, NOT all-cells fan-out — respect placement-once-route-many + grill Q8).
6. **Max-delta clamp** — `elapsed = min(now − last_metered_at, k×interval)`; emit `loopzero_metering_clamped_total`; ADR the gap-direction (clamp + under-bill + alert; never uncapped over-bill).
7. **Clock skew** — negative delta → contribute 0, no decrement, WARN + metric.
8. **Period-rollover split** — split the interval at the boundary; own leader-down-across-boundary.

**Operability (SRE):**
9. **Runtime kill switch** — `metering_enabled` re-checked per tick (env-at-restart insufficient); MTTR to stop = seconds.
10. **pg_breaker integration + bounded/batched writes** — consult the breaker before the write burst; bounded-concurrency writer; load test at documented capacity (1,500 tenants) without tripping the API breaker; add `loopzero_metering_writes_shed_total`.
11. **Freshness SLO + alerts** — export `loopzero_metering_seconds_since_last_success` (global + per-cell); ship `MeteringStalled` / `MeteringCellStarved` alert rules + runbook.
12. **Batch-appropriate timeout** — do NOT reuse the 5s interactive `cross_cell_aggregator` deadline; slow ≠ down.
13. **`usage_records` growth policy** — INSERT-per-tick vs upsert-per-period resolved explicitly + retention/partition plan.
14. **Blast-radius rollback runbook** — disable live + correct a bad billing window (prove the reversal query exists).

**Architecture / scope (Architect + Security):**
15. **Decouple enforcement** — new compute metrics default `Unlimited` in loopzero-contracts until sponsor-ratified (no placeholder cap can ever 402); Phase 5 402 hard-gated on ratified numbers; fail-open path emits `loopzero_cost_enforcement_read_errors_total` + alert.
16. **Metric-enum drift guard** — SQL CHECK is a projection of the loopzero-contracts constants; test asserts equality of the allowed set.
17. **ADR-6: data-source SoT** — state why metering reads `pod.Spec.Requests` (defensible reason: dynamic replicas via HPA/KEDA/canary Rollout ⇒ declared config understates real allocation) — or meter from PG and drop the cross-cell poll.
18. **Least-privilege** — the cross-cell `ClusterCredential` scoped to namespace `get/list pods` only.
19. **Attribution anchored to PG SoT**, not trusted from mutable cluster labels.
20. **Correct the reuse claim + assert single-writer invariant + scope honesty** (compute enforcement only; egress/docr/build stay inert).

**Verification gate (Verification — the acceptance gate):**
21. **Exact-value Goal** — replace `>0` with `cpu_core_seconds == Σreq × interval` to float epsilon (inject the Clock).
22. **MUST-ADD failure tests A-J** — exactly-once-under-concurrent-passes, NULL-bootstrap=0, atomic-crash-between-writes, max-delta-clamp, clock-skew, period-rollover-split, partial-cell-failure keying, RLS cross-tenant isolation, restart idempotency. All deterministic (injected clock/fakes), all green before `IMPLEMENTATION_COMPLETE`.
