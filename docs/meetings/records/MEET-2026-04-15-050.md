# MEET-2026-04-15-050: Pipeline Simplification Plan

**Date:** 2026-04-15
**Type:** pipeline
**Verdict:** APPROVED_WITH_CONDITIONS
**Agents:** Helena Duarte (Pipeline), SRE, Principal Architect

## Problem

`infra-deploy.yml` is 1539 lines. `pulumi up` works locally but fails in CI because 200+ lines of state surgery wrapper create more problems than they solve (state duplicates, tunnel replace loops, phantom resources).

## Decision

### Pipeline Architecture (4 workflows, each < 200 lines)

**`infra-deploy.yml` (~150 lines)**
- Trigger: push to develop/main on infra/** changes
- Steps: npm ci → helm dep update → pulumi login → pulumi config set → pulumi up → health check
- NO state surgery. NO retries. If pulumi up fails, pipeline fails.
- First deploy: pods in ImagePullBackOff until build-images completes (accepted behavior)

**`infra-bootstrap.yml` (~100 lines)**
- Trigger: workflow_dispatch only (manual)
- Steps: Gitea tokens → ArgoCD account → DB seed → Tenant CR → CF Worker deploy
- Idempotent — safe to re-run. Each step has explicit pre/postcondition checks.
- Zero `|| true` — every operation succeeds or fails explicitly.

**`infra-destroy.yml` (~80 lines)**
- Trigger: workflow_dispatch with required approval for ALL environments
- Steps: pre-destroy-cleanup.sh (STACK-SCOPED) → pulumi destroy → state reset
- pre-destroy-cleanup.sh filters by `$PREFIX` not `'loopzero' in name`

**`infra-restart.yml` (~50 lines)**
- Trigger: workflow_run from build-images.yml (on success)
- Steps: kubectl rollout restart for all platform deployments
- Replaces the "restart-only" mode embedded in current monolith

### What Gets Removed

- All state surgery from normal deploy path (cancel, state delete, stack import, refresh DELETE_UNREACHABLE)
- Image build steps (already in build-images.yml)
- 2-pass deploy with recovery sequence
- Orphaned Helm release cleanup
- Orphaned DNS record cleanup
- adopt-or-create.ts (Pulumi code handles imports natively)

### SRE Conditions for Lifting BLOCK

1. Zero `pulumi state delete` or `pulumi cancel` in infra-deploy.yml
2. Zero `|| true` on state-modifying operations
3. Deploy health output: duration, resource count, created/updated/deleted
4. pre-destroy-cleanup.sh filtered by stack prefix
5. Destroy requires approval for ALL environments (not just prod)
6. State backend bucket versioning enabled (recovery from corruption)

### Architect Conditions

1. Single Pulumi codebase for all environments (delete monolith duplication)
2. infra-deploy.yml under 200 lines
3. infra-bootstrap.yml has explicit pre/postconditions per step
4. StackReference for output coupling (not pipeline env vars)

## Trade-offs Accepted

- First deploy has ImagePullBackOff until images built (accepted: system converges)
- CF DNS uses Command provider workaround (accepted: CF provider bug is external)
- Single Pulumi stack for now (accepted: split deferred to post-launch)
- Bootstrap is manual trigger (accepted: runs once per environment setup)

## Definition of Done

1. `pulumi up` runs clean from empty state — zero errors, all resources created
2. Same `pulumi up` command works locally and in CI with identical results
3. `pulumi up` is idempotent — running twice produces no changes
4. Pipeline is 4 files, each < 200 lines
5. State surgery is 0 operations in normal deploy
