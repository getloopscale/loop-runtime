## Stage 1 — Context

### Problem

LoopZero's CI pipeline has three classes of supply-chain and DX gaps that compound risk:

1. **Tag-pinning supply-chain risk.** 88 occurrences of `uses: <action>@v[0-9]` in 21 workflows. The `tj-actions/changed-files` attack of March 2025 proved tags are mutable and exploitable. OpenSSF Scorecard penalizes tag-pinning. Today a single compromised maintainer of any dependent action can rewrite `@v4` to inject a malicious step in our build path (BuildKit, cosign signing, Helm push).
2. **No security baseline gate.** Charts in `charts/` and bootstrap charts in `infra/helm/` lack automated security context auditing in CI. Polaris would surface missing `runAsNonRoot`, `readOnlyRootFilesystem`, `drop:[ALL]`, and missing probes BEFORE deploy.
3. **Taskfile monolith (2348 lines).** Onboarding cost is high, hot-loop changes risk merge conflicts, and there's no domain separation. Task supports `includes:` natively but LoopZero hasn't adopted it.

### Decision Required

1. Approve SHA-pinning of all 88 actions (Renovate-driven thereafter).
2. Approve Polaris integration as additive CI step (no enforce mode initially — baseline first).
3. Approve Taskfile split via `includes:` (refactor, public commands preserved).
4. Approve reusable workflows extraction (`reusable-setup-go.yml`, `reusable-setup-helm.yml`, `reusable-setup-node.yml`).
5. Define escape hatch convention for tag-pinning (internal reusable workflows, e.g., `uses: ./.github/workflows/*.yml`).

### Constraints

- **Pre-release governance:** all CI changes are T2 per `.claude/rules/pre-release-governance.md`.
- **No regressions in CI duration.** SHA-pinning by itself does not change behavior; reusable workflows must not add overhead.
- **Local = production parity.** Polaris must run identically locally (`bash scripts/run-polaris.sh`) and in CI.
- **Renovate Bot integration required.** SHA bumps cannot be a manual chore — Renovate must own them.

### Known Context

## Stage 2 — Analyses

### Pipeline Reviewer (Helena Duarte) — Sponsor

**Assessment.** SHA-pinning is overdue. The `actions/checkout`, `setup-go`, `setup-helm`, `setup-node`, `pulumi/actions`, `azure/setup-helm`, and `cosign-installer` are all in our supply chain. None are pinned. Reusable workflows are the right DRY mechanism — currently `setup-go` is duplicated in `ci.yml`, `cli-commands.yml`, `pulumi-archive.yml`, and `infra-bootstrap.yml`.

**Risks.** (1) Renovate Bot misconfiguration could batch-update SHAs without human review of the version mapping. (2) Polaris in `enforce` mode initially would block legitimate deploys (e.g., `promtail` needs `hostPath`). Start in audit/baseline mode. (3) Taskfile split must preserve `task <command>` resolution — if `task k3d:heal` breaks, `task setup` breaks, the entire dev loop breaks.

**Position.** APPROVE all four sub-tasks. **Condition:** Polaris starts in baseline mode (warnings only) for ≥ 1 CI run before any `severity=danger` gating.

### Security & Blast Radius Reviewer — Challenger (VETO power)

**Assessment.** Tag-pinning is unambiguously a supply-chain attack vector. The `tj-actions` incident is recent enough that engineering teams treating it as "tomorrow's problem" are negligent. SHA-pinning is non-negotiable.

**Risks.** (1) Internal reusable workflows (`uses: ./.github/...`) cannot have SHA pin — the escape hatch must be explicit and minimized. (2) Renovate's `pinDigests: true` must include `automergeSchedule` so SHA bumps don't pile up unreviewed. (3) Polaris config must NOT be in `infra/helm/` (would be in scope of a chart) — keep it at repo root or in `scripts/`.

**Position.** APPROVE. **Condition:** internal-only reusable workflows are exempted via explicit `# pragma: allow-tag-pin` comment, and `infra-gates.yml` script greps for absence of pragma in non-internal `uses:` lines.

**No veto.**

### DX Engineer — CONDITIONAL VETO

**Assessment.** 2348 lines in `Taskfile.yml` is hostile to onboarding. Every change creates merge conflicts. The current dev loop relies on `task k3d:heal`, `task test`, `task validate:manifests` — these MUST resolve identically post-split.

**Risks.** (1) `includes:` path resolution depends on `Taskfile.yml` location — moving from monorepo root would break it. We're not moving, so this is OK. (2) Vars defined at root must be available in includes. Validated by Task v3 docs — works automatically. (3) CI workflows reference `task <name>` strings — none of those should change.

**Position.** APPROVE. **Condition:** `scripts/check-taskfile-interface.sh` MUST run as part of CI for the duration of the migration, asserting that `task --list-all` includes a known set of public commands. If any goes missing, CI fails.

**Veto if condition not met:** Without the interface check script, the split is unsafe.

### Principal Architect

**Assessment.** Reusable workflows + SHA-pinning + Polaris + Taskfile split are independent in scope but reinforce one another: reusable workflows reduce the surface area where SHA-pinning matters; Polaris enforces what manifests should look like, complementing kubeconform (schema) and helm lint (template). The four together raise the floor without raising the ceiling.

**Position.** APPROVE.

## Stage 3 — Decision

### Verdict: APPROVED

### Mandatory Conditions

1. **Polaris baseline-first.** First CI run with Polaris enabled produces report, no gating. Engineer reviews, classifies warnings, then promotes to `severity=danger` gating in a follow-up commit.
2. **Renovate Bot configured.** `.github/renovate.json` MUST include `pinDigests: true` and a `packageRules` entry for grouping action bumps.
3. **Pragma escape hatch documented.** `# pragma: allow-tag-pin` is the ONLY way to bypass SHA pinning; documented in `infra-gates.yml` header.
4. **Taskfile interface check is required CI.** Cannot merge a Taskfile change without `scripts/check-taskfile-interface.sh` GREEN.
5. **Reusable workflows tested in pilot.** Each of the 3 reusables consumed by ≥ 1 workflow before broad migration in T5.2.

### Rejected Alternatives

- **Big-bang Polaris enforce.** Rejected: would block deploys for charts with legitimate exceptions. Baseline-first is operationally safer.
- **Manual SHA bumps.** Rejected: 88 actions × monthly bumps = unsustainable. Renovate is the enforcement mechanism.
- **Split Taskfile by file size, not domain.** Rejected: file-size split doesn't align with cognitive boundaries. Domain split (k3d, helm, test, infra, db, dev) maps to the agent ownership model.
