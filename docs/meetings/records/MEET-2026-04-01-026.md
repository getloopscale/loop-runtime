# MEET-2026-04-01-026: Infrastructure Pipeline Deep Review

**Date:** 2026-04-01
**Type:** pipeline, security, architecture

## Problem

The `infra-deploy.yml` pipeline (~1043 lines) provisions the entire LoopZero platform in a single monolithic job. Multiple iterations of destroy+recreate have exposed systemic fragility. A deep review was requested to identify problems, gaps, anti-patterns, and improvements.

## CRITICAL Findings

### CRIT-01: `continue-on-error: true` on Bootstrap — platform ships broken
**Lines:** 613, 972 (infra-deploy.yml)
**Agents:** SRE (unanimous), Pipeline

Bootstrap creates Gitea tokens, ArgoCD JWT, K8s secrets, seeds DB, creates Tenant CR. If ANY fails, pipeline reports **success**. Health validation (line 972) also `continue-on-error: true`. Result: green pipeline, non-functional platform. No alert fires. Discovery: when a user runs `loopzero deploy` and gets opaque auth error.

**Fix:** Remove `continue-on-error: true` from Bootstrap and Health Validation. These MUST fail the pipeline.

### CRIT-02: Destroy path deletes ALL resources across stacks
**Lines:** 85-91 (pre-destroy-cleanup.sh), 261-268 (infra-deploy.yml)
**Agents:** SRE, Security, Architect (unanimous)

- Load balancers: **NO FILTER** — deletes every LB in the DO account
- Clusters: filters by "loopzero" — matches `loopzero-infra-prod-*` when destroying `dev`
- Registry: account-wide DELETE — destroys ALL images across all stacks
- Buckets: deletes all `loopzero-*` buckets regardless of stack
- CF Worker routes: no name filter

**Blast radius:** Running `destroy dev` deletes production infrastructure.

**Fix:** Filter ALL API calls by `loopzero-infra-${STACK}`. Never delete shared registry. Require confirmation for destroy via `workflow_dispatch`.

### CRIT-03: SQL injection via `github.triggering_actor`
**Lines:** 774-814 (infra-deploy.yml)
**Agents:** Security, Pipeline

```bash
GH_LOGIN="${{ github.triggering_actor }}"
psql "$LOOPZERO_DB_URI" <<SEED_SQL
INSERT INTO users (...) VALUES ('${GH_USER_ID}', '${GH_LOGIN}@...', ...)
```

`${{ }}` is expanded by GitHub Actions template engine BEFORE bash. Expression injection risk. SQL injection via unparameterized heredoc.

**Fix:** Set via `env:` block, sanitize, use `psql -v` with `:variable` syntax.

### CRIT-04: Non-expiring tokens accumulate without revocation
**Lines:** 664 (Gitea), 709 (ArgoCD)
**Agents:** Security (VETO)

- ArgoCD: `expiresIn: 0` = non-expiring apiKey. New one per pipeline run. Never revoked.
- Gitea: `--scopes all` = god-mode admin token. New one per run. Never revoked.
- After 100 deploys: 100 valid non-expiring tokens in each system.

**Fix:** Set TTL (7d max). Revoke previous tokens before generating new ones. Reduce Gitea scope from `all` to minimum required.

### CRIT-05: Mutable image tags — no artifact lineage
**Line:** 504
**Agents:** Pipeline, Architect

`TAG="$STACK"` means `loopzero-api:dev` is overwritten on every push. Same tag, different content. No way to trace running image to commit. If Step 3 fails and retries, no guarantee images match current code.

**Fix:** `TAG="${STACK}-${GITHUB_SHA::8}"`. Capture digest after push. Pulumi references digest, not mutable tag.

### CRIT-06: Single Pulumi stack conflates 3 lifecycles
**Agents:** Architect (root cause)

One `pulumi up` manages: cloud infra (monthly changes), platform services (weekly), app workloads (every commit). The 3-step dance (up → build → up again) is a workaround. `skipAwait` annotations are a symptom. State corruption (4× `pulumi cancel`, 3× `pulumi refresh`, nuclear state clearing) is the consequence.

**Fix:** Split into 3 stacks: `loopzero-infra-core`, `loopzero-infra-platform`, `loopzero-infra-apps`. See Architecture section below.

## Architectural Recommendation (Principal Architect)

### Root Cause
Single Pulumi program managing resources across 3 lifecycle boundaries, with critical bootstrap logic living outside the control plane in imperative shell.

### Target Architecture

```
Stack 1: loopzero-infra-core (VPC, clusters, DB, registry, Spaces)
  Changes: monthly | Blast radius: cloud resources only
  
Stack 2: loopzero-infra-platform (Helm charts, namespaces, RBAC, CRDs)  
  Changes: weekly | Depends on: Stack 1 outputs
  
Stack 3: loopzero-infra-apps (loopzero-api, tenant-controller Deployments)
  Changes: every commit | Depends on: Stack 2 + container images
  
Bootstrap: PlatformBootstrap CR (already exists!)
  Reconciled by PlatformBootstrapReconciler (already exists!)
  Eliminates 270 lines of shell
```

### Migration Path
1. **Phase 1 (immediate):** Fix CRIT-01 through CRIT-05 in current pipeline
2. **Phase 2 (next sprint):** Extract Stack 1 (infra-core) as separate Pulumi project
3. **Phase 3:** Extract Stack 3 (apps), wire to build-images.yml with image digests
4. **Phase 4:** Migrate bootstrap shell to PlatformBootstrap CR
5. **Phase 5:** Delete pre-destroy script, let Pulumi own destruction
