## Critical conditions integrated into plan v1.1

### Phase 1 ordering changes (from platform-architect C1, sre veto, security veto)

1. **T5.4 (cache scoping congruence test) HOISTED to Phase 1** — runs between T1.3 and T1.4. Deleting monolith without proving split scopes are correct = ship regression.
2. **AP-3 (silent error swallow at `application_controller.go:179-181`) HOISTED to Phase 1** — runs as T1.0.5 pre-migration, OR T1.6 explicit verification "no E2E test depends on AP-3 swallow". Carrying the bug into canonical tree then fixing in Phase 2.4 risks behavioral regression discovered only in dogfood.
3. **T1.5 atomic helmfile swap REJECTED.** Replaced with 4-stage rollout:
   - **Stage A — Coexistence:** deploy 4 split operators with same lease names, monolith stays Running (no reconcile work splits).
   - **Stage B — Per-controller cutover:** PlatformBootstrap → Preview → Application → Tenant (ascending blast radius). Disable single controller via env-flag in monolith; observe 60min `loopzero_reconcile_loop_last_success_timestamp`.
   - **Stage C — 24h soak per cell:** cell-1 first; cell-2 only after cell-1 GREEN.
   - **Stage D — Delete monolith chart:** only after 30d `OperatorRestartRate24h` silent (existing gate, kept).
4. **T1.4 deletes `cmd/main.go` only at Stage D** (NOT immediately after T1.3 as plan v1.0 ordered). Local development can delete sooner; production deletion is staged.
5. **Production rollout SCOPED OUT of this plan.** Phase 1 ends at local dogfood GREEN. Production cutover handled via separate `CHG-NNNN-OPERATOR-SPLIT-PROD` change record per platform-architect C3.

### Verification requirements (from verification-architect 5 vetos)

1. **Drift baseline document committed BEFORE T1.1 starts** — `docs/plans/operators-sota-faang-grade-plan/drift-baseline.md`. Per-file diff between monolith and split with explicit "mechanical / semantic-port-N-lines" classification. Already-known: ClusterCredential 78 LOC divergence.
2. **T4.3 analyzer fixture suite committed alongside analyzer** — `hack/validate-rbac/testdata/{positive,negative,false-positive}/` with minimum 5+3+3 cases.
3. **Dogfood Special Validation Steps codified as scripts** — `infra/tests/dogfood/operators-sota/{blast-radius,kstatus-interop,rbac-drift-gate,capability-matrix-audit}.sh`. Manual bash in markdown is not a gate.
4. **E2E baseline file committed** — `docs/plans/operators-sota-faang-grade-plan/e2e-baseline.txt` listing exact 25 currently-green test names. Prevents silent substitution.
5. **Helm rollback runbook with failure injection** — `infra/scripts/operator-cutover-rollback.sh` MUST be executed end-to-end against dev cluster with proof in PR (not just pre-flight steps 1-2).

### Security conditions (from security-engineer)

1. **Marker style guide BANS `resources=*` and `verbs=*`** — extends `hack/validate-rbac.sh`.
2. **AST analyzer distinguishes `r.Client` (local) from `r.RuntimeClientFactory.For(cellID)` and `r.BuildClient`** — cross-cluster RBAC has separate gate via `kubectl auth can-i` matrix in CI.
3. **T4.1 PR includes 3-way diff** — `current-handedited.yaml` vs `generated.yaml` vs `intersection.yaml`. Net-new permissions require explicit per-rule justification.
4. **Phase 1 SA rename safety** — Helm chart `extraSubjects` knob on all 4 split charts allowing temporary dual-binding (`tenant-controller` + `loopzero-tenant-operator`) for rollout window. NetworkPolicy `podSelector` widened to `app in (tenant-controller, loopzero-tenant-operator)`.
5. **Pre-flight inventory:** `grep -r "tenant-controller\|loopzero-controller" infra/ charts/ operators/` audited; every match either renamed or annotated.
6. **Documented analyzer blind-spot list** — `hack/validate-rbac/KNOWN_GAPS.md` (dynamic clients, unstructured, helper indirection, watches/informers, field selectors, EventRecorder).

### SRE / Observability conditions

1. **ServiceMonitor selector migration** — `infra/helm/monitoring/manifests/servicemonitor-tenant-controller.yaml` MUST update selector before cutover (current `app: tenant-controller` matches zero new pods → silent metrics blackout).
2. **New required metrics:**
   - `loopzero_status_update_conflicts_total{controller}` — observe D2 conflict rate
   - `controller_runtime_active_workers{controller, binary}` — saturation alert
   - `workqueue_depth{controller}` per binary
   - `leader_election_master_status` per binary (split-brain detection)
   - `up{job="loopzero-*-operator"} == 0 for 2m` page per binary
3. **Health probe correctness:**
   - Liveness MUST NOT depend on cache sync
   - Readiness MUST wait for cache sync (`mgr.AddReadyzCheck("informer-sync", mgr.GetCache().WaitForCacheSync)`)
4. **Dogfood Gate enhanced** — minimum 4-hour soak with continuous deploy traffic at production baseline rate (~30/h auto-deploy webhooks); chaos injection (API-server 429s, network partition mgmt↔workload, PG advisory lock contention); cell-2 isolation regression test re-run; `operator-cutover-rollback.sh` executed against dirty environment; SLO assertion `loopzero deploy P95 < 705ms` (cell-2 baseline).

### kubebuilder convention conditions (from k8s-controller-engineer)

1. **D2 retry helper:** add `defer ctx.Err()` short-circuit; max-attempts cap with `wait.Backoff{Steps: 5, Cap: 2*time.Second}`; spec-mutation guard via deep-copy reset; SSA evaluation note in ADR ("RetryOnConflict for now; SSA evaluated post-launch").
2. **D3 SetReadinessSummary:** `defer` in each Reconcile so summary runs even on panic/error (stamps `Stalled=True` if non-transient retErr); idempotency test FIRST (not seventh); ClusterCredential `Test_ClusterCredential_SecretNotFoundExcludesReady`.
3. **D4 controller-gen:** `paths=` scoped per binary (`./internal/tenant/...`), not `./operators/...`. Output to per-binary chart. Dead-marker analyzer (markers without matching `r.Client.X`).
4. **T5.4 cache scoping:** add Runtime layer `TestCacheScopingCongruence_Runtime` (boot manager via envtest, inspect `mgr.GetCache().GetInformersByGVK()`) alongside Static AST layer. Static-only misses default-scoped fallback overlap.

### DX conditions (from dx-engineer)

1. **Shared label `app.kubernetes.io/component: loopzero-operator`** added to all 4 deployments (Tilt + Helm). Enables canonical `kubectl logs -l app.kubernetes.io/component=loopzero-operator -n loopzero-system --all-containers --max-log-requests=4 -f`.
2. **`task doctor` extended** with `=== Operator Pods ===` section checking `kubectl rollout status deploy/{tenant,app,preview,platform}-operator -n loopzero-system`.
3. **`task logs:operators` (all) and `task logs:operator -- <name>`** helpers in `taskfiles/dev.yml`.
4. **`task debug:operator -- <name>`** with `kubectl port-forward 2345:2345` + `dlv connect` instructions.
5. **T1.5 enumerates 6 fan-out points** (ServiceMonitor, NetworkPolicy, alert rules, cutover-rollback.sh, rbac-subset-check.sh, CI workflow path filters) and updates them in same PR.
6. **`capability-matrix-audit.sh` CI gate** added to `validate:docs` before T5.1 closes — greps every `Setup*` function in `internal/{tenant,app,preview,platform}/`, ensures each appears in matrix with file:line + test references.
7. **`docs/technical/operators/README.md` + per-binary runbooks** updated with "binary → CRD → debug command" table.
