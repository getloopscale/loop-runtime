## Context

**Problem:** the per-app-pod memory-request floor is hard-coded at `128Mi` (`api/internal/manifests/renderer.go:280-287`); most apps idle but reserve it 24/7. CTO wants a disruptive low-cost runtime "like Bun", supporting only LoopZeroKit, Python descoped.
**Decision required:** adopt Bun-class container for `runtime: node` apps (Trilho 1, one-pod-per-app) with per-app build-time dispatch — Bun-eligible → `bun build --compile` → scratch image (cheap); break-class (Prisma/node-pre-gyp/runtime-package.json) → existing Node-container fallback.
**Proposal:** the blueprint + its ADR-B1..B4.
**Review Board:** principal-architect, platform-security-engineer (absolute veto), sre-engineer (absolute veto), dx-engineer (conditional veto). (pipeline-reviewer is a skill, not spawnable — its lens covered by deploy-guardian + CVP.)
**Guardians:** deploy-guardian.
**Governance:** production-design-reviewer (PDR), change-validation-planner (CVP), security-blast-radius-reviewer (SBR, absolute veto).

## Stage 3 — Technical Confrontation (key findings)

### Convergence (the meeting's signal)

1. **The cost win is NOT WIRED (deploy-guardian, decisive).** `memoryRequest()` (`renderer.go:280-288`) returns a flat global `128Mi`; both consumers (`renderer_deployment.go:31`, `renderer_rollout.go:330`) call it. Even a perfect Bun scratch binary idling at ~24Mi is **scheduled at 128Mi** — the mandate's headline goal is structurally unmet by the build change alone. A per-app, runtime-aware floor must be designed + wired, or there is zero cost reduction in production.

2. **The cost is UNMEASURED, and the wrong baseline is implied (everyone; PDR sharpest).** ADR-B4 honestly tags the numbers `[ESTIMATED]`. PDR's escalation: the decision number must be the **incremental Bun-over-tuned-Node** delta — measure Bun against *Node at the existing `64Mi` lean floor + KEDA scale-to-zero (already installed)*, not against untuned `128Mi`. Lowering the floor alone may capture most of the win with **zero new runtime fleet, zero classifier, zero new SPOF**. That comparison is "the missing denominator of the entire cost case."

3. **`.env` autoload = CRITICAL secret leak (platform-security + SBR, HARD GATE).** `bun build --compile` autoloads `.env`/`bunfig.toml` by default (`references/bun/docs/bundler/executables.mdx:413`). A customer-committed `.env` → secrets baked into a cosign-signed, registry-pushed, ESO-rotation-bypassing artifact; the signature makes it worse (admission runs it). SBR added a pre-existing Layer-1 finding: `canonical_dockerfile.go:112` does `COPY . .` with **no `.dockerignore`**, so `.env` is already in today's Node image layer — Bun *weaponizes* it at runtime. Also: Bun build-step images would inherit the **tag-pinned (not digest-pinned)** weakness of `constants.go:24-35`.

4. **Smoke gate (boot + 1 endpoint) is INSUFFICIENT (CVP, SRE, PDR).** It cannot catch a lazy-loaded native (Prisma engine resolved on the first DB query, not at boot). A false-positive-to-Bun classification ships green and crashes in front of a paying tenant. Needs "native-exercising smoke" + a classifier that reads the **resolved** dep tree (transitive Prisma) and **fails safe to fallback** on ambiguity.

5. **No observability / kill-switch / debug story (SRE, PDR, DX).** Scratch image = no shell (`kubectl exec` → "executable file not found"). No metric for fleet split or misclassification (violates LoopZero's own wiring-triad rule). No per-app or global lever to route back to Node without a per-app rebuild (unbounded MTTR).

6. **Transparency / Rule-3 tension (DX, conditional veto).** The user declares `runtime: node` but one of three runtimes runs — invisibly. A 🟡 partial API divergence becomes a mystery prod bug. Needs a user-visible `runtime_mode` (product language `optimized|compatibility`, never "Bun"/"Node" — Rule 3), an override flag, and a debug affordance.

7. **Downgrade-attack vector (SBR).** An attacker can trip the break-class detector to force routing onto the larger-surface Node path. Both paths MUST be security-equivalent; the dispatch is a performance axis only, never a security axis.

### Ratified as sound (consensus)

- **ADR-B2 (orthogonal axis, never `runtime: "bun"`)** — ratified by architect, deploy-guardian, security, CVP. Adding `runtime: "bun"` would hit the fail-closed branch (`languages.go:73-91`) for every existing node app — correctly rejected.
- **Supply-chain chain is digest-scoped, content-agnostic** — platform-security + deploy-guardian both verified in code (`cosign.go:135-148`, `manifest_builder.go:60-67`, `vap-require-image-digest.yaml:46`, `cluster-image-policy.yaml`): a scratch single-binary image signs + admits identically. The change is **below** the supply-chain trust boundary.
- **Scratch single-binary = net attack-surface reduction** (SBR credit): no shell/pkg-manager/node_modules → smaller TCB, fewer CVEs.
- **The per-app fallback genuinely de-risks the CTO's "can't install deps" fear** (DX, architect).

### Architecture correction (principal-architect)

Dispatch must resolve to a `NodeBunStrategy` **peer** at `ResolveStrategyForApp` (`languages.go:120`), NOT be decided inside `DockerfileStep` (which would overload SRP + break the `dockerfileStepTemplateName` dummy-app probe at `languages.go:206-215`). The classification must be **persisted as durable build-output state** (a source of truth readable by status/admission/next-build), not a transient in-build branch. The smoke gate must be an explicit Workflow step with a state machine (passed/failed/timeout→fallback).

3. **Per-app runtime-aware memory floor — design** — `memoryRequest()` must become strategy/app-aware (consumed at `renderer_deployment.go:31` + `renderer_rollout.go:330`). Without this the cost win is discarded. (deploy-guardian I2 BLOCKER.)

### Phase 1 — Design hardening (conditions before `/implement`, IF the spike justifies adoption)
4. **Security HARD GATES (BLOCKING):** every `bun build --compile` passes `--no-compile-autoload-dotenv --no-compile-autoload-bunfig`; inject a platform `.dockerignore` stripping `.env*`/`*.pem`/`*.key`/`credentials*`/`id_*` on **both** Node and Bun paths (closes pre-existing Layer-1 leak); secret-scan the compiled binary (TruffleHog/gitleaks) BEFORE cosign signs, fail-closed on a hit. Tests assert each.
5. **Supply chain:** digest-pin the Bun builder image + verify the Bun release checksum at builder-build time (no runtime download, SEC-006 pattern); extend `TestBaseImages_AreDigestPinned`; generate the CycloneDX SBOM from the resolved lockfile pre-`--compile` so Trivy CVE scanning is not blinded; provenance captures the Bun version.
6. **Architecture:** `NodeBunStrategy` peer resolved at `ResolveStrategyForApp` (not in `DockerfileStep`); persist the eligible/fallback verdict as durable build-output state; model the smoke gate as an explicit Workflow step with a state machine. Keep the `node-bun` canonical Dockerfile byte-stable.
7. **Compat gate rigor:** native-exercising smoke (hit a route forcing lazy native resolution); classifier reads the resolved (transitive) dep tree; **fails safe to fallback** on ambiguity (mirror `unsupportedStrategy` fail-closed); both paths security-equivalent (no downgrade vector).
8. **Observability triad:** `loopzero_app_runtime_path{path="bun|node"}` metric, per-path error/restart rate, classifier-decision audit, idle-RSS histogram (prove the cost claim in prod); ≥2 alerts+runbooks (OOM/crashloop, runtime-break counter).
9. **Kill-switch:** per-app AND global lever to force the Node-container path without a per-app rebuild; tested LIVE.
10. **DX transparency (ADR):** `loopzero deploy/status --json` expose `runtime_mode: optimized|compatibility` (product language, Rule 3 — never "Bun"/"Node"); build-time signal on 🟡-API use + fallback "why"; explicit user override flag; debug affordance for scratch (ephemeral debug container OR distroless-with-debug). Verify sourcemaps survive `--compile --bytecode` (legible stack traces).
11. **Schema lock:** `services.json` `runtime` enum stays `["python","node"]` (`services.schema.json:59`). Any PR adding a value = auto-REJECT.

## Errata (2026-06-23, post-meeting, Rule 3)

The meeting used **Prisma** as the canonical example of the `--compile` break class (finding #4: "Prisma engine resolved lazily on the first DB query"). **This specific example was WRONG** — it derived from the blueprint's inference (not measurement) and from outdated knowledge of Prisma's legacy binary query engine. The official Prisma+Bun guide documents `bun build --compile` as a **supported** Prisma deployment path via **driver adapters** (`@prisma/adapter-*` + a JS driver, `prisma-client` generator — no native engine binary). **Prisma is Bun-compatible, not a break class.**

What this changes / does NOT change:
- **CHANGES:** the canonical break-class example moves from Prisma → **node-pre-gyp consumers that don't `require()` the `.node` directly** (candidate: `canvas`/Cairo). The break class is **even narrower** than the meeting assumed → the cost-win case is marginally **stronger**.
- **DOES NOT CHANGE — and in fact REINFORCES — the meeting's core decision (DEFER + measure-don't-infer).** This errata is itself a live instance of finding #4's principle: an *inferred* compat claim was wrong; only *measurement* (or reading the primary source) is authoritative. The benchmark mandate (actions 1-3) is vindicated, not weakened.
- Action items 1-13 stand. The genuine break candidate (`canvas-app`) replaces `prisma-app` as the fallback fixture in the Phase-0 plan; `prisma-app` becomes a Bun-eligible **success** fixture. Corrected artifacts: blueprint (ERRATA block), `loopzerokit-bun-phase0-benchmark-plan.md` (v1.2).
- Credit: the correction came from a **human with the official doc in hand**, not the automated gate — exactly the failure mode (LLM post-rationalized citation) the pipeline's golden rules are designed to surface.
