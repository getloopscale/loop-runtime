# MEET-2026-04-15-049: Infra Pipeline Idempotency

**Date:** 2026-04-15
**Type:** pipeline + architecture
**Verdict:** APPROVED_WITH_CONDITIONS
**Agents:** Helena Duarte (Pipeline), Principal Architect, SRE, GitOps

## Problem

The `infra-deploy.yml` pipeline (1539 lines) is not idempotent. `pulumi up` fails on every run due to:
1. CF Tunnel replace loop (tunnelSecret drift → delete fails → active connections)
2. CF DnsRecord provider bug (error 9000 for valid payloads)
3. Harbor Helm "cannot re-use a name" (release in K8s but not Pulumi state)
4. Excessive automatic state surgery masking root causes

## Decision

### D1: Remove CF resources from Pulumi stack
CF Tunnel, DNS A records, KV Namespace, Worker → managed via dedicated pipeline step using CF API directly (Node.js HTTPS). Not via `@pulumi/cloudflare` provider. Rationale: provider v6.x has confirmed bugs, CF resources are long-lived (create-once), different lifecycle from K8s/DO infra.

### D2: Eliminate state surgery from normal deploy path
`pulumi up` must work without cancel/delete/import/refresh on happy path. Recovery sequence (Pass 2) may exist but must be logged as anomaly, not norm.

### D3: Tunnel is immutable after creation
Never delete/recreate tunnel in normal pipeline. Use `ignoreChanges` + clean state once. The tunnel lifecycle: create on first deploy, persist forever, destroy only on environment teardown.

### D4: Harbor uses atomic install
Replace `skipAwait` with proper lifecycle handling. Import if exists, create if not.

## Conditions for Approval
1. Pipeline `pulumi up` succeeds on first attempt (no Pass 2 needed)
2. Zero `pulumi state delete` or `pulumi cancel` in normal deploy path
3. CF resources managed outside Pulumi (dedicated step)
4. State surgery only in `workflow_dispatch` with `command=repair`

## Risks Accepted
- CF DNS workaround via Node.js HTTPS is not declarative (accepted: CF provider is buggy)
- Single Pulumi stack for now (accepted: split deferred to post-launch)

## Actions
1. Clean tunnel pending-replacement from state (one-time fix)
2. Move CF Tunnel creation to adopt-or-create shell step in pipeline
3. Move DNS A record creation to post-deploy shell step
4. Remove state surgery from normal deploy path
5. Add `--atomic` to Harbor Helm release
