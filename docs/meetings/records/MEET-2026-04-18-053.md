**Decisao do founder (pre-meeting):** Multi-cell sera o default. A reuniao define COMO, nao SE.

**Decisao tecnica:** Implementar em 4 fases sequenciais, cada uma independentemente deployavel e rollback-safe. SRE VETOES devem ser resolvidos ANTES do flip (Phase C).

## Contexto

O sistema LoopZero tem arquitetura cell-based (ADR-0008) com codigo 90% pronto mas 0% ativado em producao. O founder decidiu ativar multi-cell como default desde Phase 0 para fail-fast: descobrir bugs no path multi-cell agora, nao apos meses de investimento.

**Estado atual:**
- `DynamicRouter` + `RoundRobinEngine` + `K8sCellStore` + `ClusterCredentialController` existem
- Zero `ClusterCredential` CRs criados
- API cai silenciosamente no `PassthroughRouter("cell-default")`
- Admission hardcoded a `DefaultCellID`
- `BuildReconcileLoop` scoped a `cell-default`

## Trade-offs Aceitos

1. **60s cache staleness** — DynamicRouter refresca a cada 60s. Nova cell leva ate 60s para ser descoberta. Aceitavel para Phase 0 (1 cell). Event-driven watch e Phase 3 optimization.
2. **Shared PG** — Todas as cells compartilham 1 PG. Nao e problema de correctness, apenas performance a 5+ cells. Aceitavel ate Phase 3.
3. **TOCTOU no placement** — Com 1 cell, round-robin trivialmente escolhe a mesma cell. Fix (D-01) e obrigatorio antes de cell-2, nao antes do flip.
