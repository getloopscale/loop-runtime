## Decision

**Phase 2 (TokenProvider pattern) is DEFERRED. Option C (YAGNI) approved unanimously.**

### Rationale

1. The threat model changed. Phase 0 replaced 24h session JWT with permanent apiKey. Silent expiry no longer exists.
2. Phase 1 provides sufficient observability: `ErrArgoCDUnauthorized`, circuit breaker excludes 401, Prometheus metrics, deep health auth distinction, startup validation, production runbook.
3. YAGNI: no rotation scenario exists. The only invalidation event (ArgoCD signing key rotation) is extraordinary and covered by alerting + runbook. MTTR ~2 minutes.

### Option A (atomic.Value) Rejected

- Half-implemented hot-reload creates false confidence
- Reload trigger undefined (polling interval? file watch? what triggers the re-read?)
- Cannot propose realistic tests for undefined mechanism

### Option B (TokenProvider interface) — Preserved for Future

Design sketch for when Phase 2 is activated:

```go
type TokenProvider interface {
    Token() string
    Refresh() error
}

type StaticTokenProvider struct { token string }
type FileWatchTokenProvider struct { path string; token atomic.Value }
```

Estimated implementation: 1 day.

### Trigger Conditions for Phase 2 Activation

Implement Phase 2 when ANY of these occur:
1. Token rotation is automated (CronJob, External Secrets Operator)
2. Compliance/security requires periodic credential rotation
3. A second credential-bearing client needs the same pattern
