## 1. Context

The LoopZero platform has ~268 test files across 5 components but critical production paths have ZERO test coverage. The proposal was to introduce mutation testing to validate test suite effectiveness.

### Current State

| Component | Test Files | Tests | Quality |
|-----------|-----------|-------|---------|
| CLI (Jest) | 50 | ~905 | Good — strong base |
| API (Go) | 120 | ~1800+ | Concentrated — gaps in services layer |
| Operators (Ginkgo) | 30 | ~188 | Good — envtest-based |
| Pkg (Go) | 22 | ~150 | Strong — state machines well-tested |
| E2E (Ginkgo) | 6 | ~30 | Exist but NOT in CI |

### Critical Gaps Identified (ZERO tests)

| File | Lines | Production Risk |
|------|-------|----------------|
| `api/internal/github/autodeploy.go` | 336 | PRIMARY deploy path — git push auto-deploy |
| `api/internal/github/appclient.go` | 236 | GitHub App JWT auth + installation tokens |
| `api/internal/services/build_reconcile_*.go` | 830 | Background build lifecycle processor |

---

## 3. Decision

### APPROVED_WITH_CONDITIONS: Phased Test Quality Improvement

**Mutation testing is DEFERRED to Phase 3.** The immediate priority is filling the catastrophic test gaps in the deploy pipeline core.

### Rejected Alternatives

| Alternative | Rejected Because |
|------------|------------------|
| Mutation testing now | SRE VETO: cannot measure quality of tests that don't exist |
| Global coverage thresholds | Creates perverse incentives (trivial tests to hit numbers) |
| Mutation testing on all code | DX VETO: 30-45min runs will kill developer productivity |
| Skip E2E in CI permanently | Principal Architect: 1,281 lines of tests that never run = dead weight |

### Phase 3 — Mutation Testing (Week 7+, CONDITIONAL)

> Only starts after Phase 0-2 complete. SRE VETO lifts when conditions met.

**Tools:**
- **Go:** `gremlins` (actively maintained, Go module workspace support, better than go-mutesting)
- **TypeScript:** `StrykerJS` with `--incremental` mode (good Jest integration)

**Scope (surgical, not broad):**

| Package | Why | Expected Duration |
|---------|-----|------------------|
| `pkg/statemachine/` | Highest correctness requirement, best coverage | ~2 min |
| `api/internal/lock/` | Advisory lock must be tested for timeout behavior | ~1 min |
| `api/internal/services/build_orchestrator*.go` | 29 tests — validate assertion strength | ~5 min |
| `cli/src/output/` | Exit code mapping, JSON schema stability | ~3 min |

**NOT in scope for mutation testing:**
- Route handlers (tested via handler tests)
- Operator controllers (envtest is slow enough)
- Pulumi IaC (no mutation tooling for Pulumi)
- Manifest renderer (complex output, low mutation ROI)

**CI Integration:**

| Where | What | Blocking? |
|-------|------|-----------|
| Local | `task test:mutate -- <package>` (focused, developer choice) | Never |
| Nightly CI | Full critical-path mutation report | Never blocking — artifact only |
| PR comment | One-line summary: "Mutation score: 92% (1 surviving mutant)" | Advisory only |

**Mutation Score Thresholds:**
- Initial: 70% (floor)
- Target after 3 months: 80%
- `pkg/statemachine/`: 90% from day 1

**Taskfile commands:**

```yaml
test:coverage:
  desc: Run all tests with coverage report
  
test:mutate:
  desc: Run mutation testing on specific package (e.g., task test:mutate -- pkg/statemachine)
  
test:mutate:report:
  desc: Generate mutation report for CI (nightly, never blocking)
```
