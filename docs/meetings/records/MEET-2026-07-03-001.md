# MEET-2026-07-03-001 — M9 Step 5 db-split design ratification + decomposition mandate

- **Date:** 2026-07-03
- **Type:** `architecture` / `database` (state-machine-adjacent, MA-7)
- **Change tier:** **T2** (under MEET-2026-07-02-001 M9 approval; MA-7 blocking)
- **Verdict:** **RATIFIED_WITH_DECOMPOSITION_MANDATE** (design approved; single-session execution REJECTED)
- **Trigger:** `/goal` to execute the CYCLE for M9 Steps 5+6 (split `api/internal/db` into generated/repository/store; group `api/internal/services` by domain). The DISCOVER+PLAN phases convened a design meeting before any code move because the split touches MA-7 (state-machine status-mutation invariant).

## Review board

- **state-guardian** (MA-7/MA-8 owner) · **api-domain-architect** (module boundary) · **distributed-systems-engineer** (behavior/concurrency preservation).

## Measured ground truth

- `api/internal/db`: 71-file flat package (7,790 root LOC) + `generated/` (sqlc, 24 files, 6,959 LOC — MA-6 no-regen) + `raw/`. Pattern: ~20 entities, each `<entity>_types.go` (a `<Entity>Store` interface + Row/Params types) + `<entity>_wrapper.go` (a `<Entity>StoreSqlc` impl bridging `generated.Queries`).
- **Status-mutation surface = exactly 4 entities:** `release` (`ReleaseStoreSqlc.UpdateStatus`, machine-enforced via `releaseMachine.SafeTransition`), `build` (machine-enforced), `domain` (DB-CAS string, **NO** SafeTransition), `preview` (direct string write, **NO** SafeTransition). `project_wrapper.go` imports `pkg/statemachine` only for a **read** projection (decoy — not a mutation).
- The status method is a METHOD ON the aggregate store, mixed with CRUD; it does `GetByIDTx(tx) → SafeTransition → generated.Update*Status(tx, tenant-predicate)` in one tx, with a 23505 partial-unique-index → `NewConcurrentActivation` typed error (→ HTTP 409).
- `db.Release` referenced 217× / `db.DBTX` 165× across 57 non-db files.
- `services/`: 56 files, 12,254 LOC, 86 structs; already uses consumer-defined narrow interfaces (ISP) — the only concrete cross-service field is intra-`placement/` (`cross_cell_aggregator → CellService`).
- MA-4 baseline: **141** db test functions.
- MA-7 baseline is CLEAN: zero `services/*` import `internal/db/generated`.

## Decision 1 — the literal "repository/store" (CRUD-vs-status type split) is REJECTED

All three reviewers reject splitting each `<Entity>StoreSqlc` into a CRUD `repository` type + a status `store` type:
- It splits by responsibility-type, not by aggregate → **fragments cohesive aggregates** (Build's CRUD and Build's status transition in two packages) — ISP-inverted, KISS/SRP violation.
- The status method's read-modify-write (`GetByIDTx → SafeTransition → UPDATE`, tenant predicate sourced from the fetched row) must stay **one method in one tx**; fragmenting it across a package seam risks order-reordering (update-before-validate) and tenant-predicate-source drift (distributed-systems).

**Ratified design (synthesis):**
- `db/generated/` — sqlc output, UNCHANGED (MA-6).
- root `db` — the PORTS: Row/Params types + `<Entity>Store` interfaces + `DBTX`/connection contracts STAY (moving 400+ refs buys nothing).
- `db/store/` — ALL entity adapters (`<Entity>StoreSqlc` impls) move here; each aggregate keeps its status method. (Optional `db/pgx/` for connection/pool/pgx_adapter/query_executor plumbing.)
- **MA-7 is enforced by grep-gates, NOT by a type bifurcation:** Gate A (no `services/routes/server` imports `db/generated`), Gate B (the enumerated generated `*Status*`/`*Transition*` UPDATE funcs referenced only from `db/store/`), Gate C (`buildMachine`/`releaseMachine.SafeTransition(` called only from `db/store/`; whitelist the `project` read-cast decoy). Ship as a `pkg/quality` Go gate wired into `task quality:gates`.

This de-flattens the 71-file package (the audit finding) without fragmenting aggregates or the dangerous read-modify-write.

### Architect divergence (ADR REQUIRED before 5b)

state-guardian proposed `repository/` (all CRUD) + `store/` (status only, embedding repository); api-domain-architect proposed unified `store/` (status stays on aggregate) with MA-7 via gates. Synthesis above adopts the unified-store + gate-based MA-7, but the exact `repository/` vs `pgx/` sub-layer naming and whether pure-CRUD entities get their own sub-package is **an open ADR** to be locked before the 5b store-layer slice.

## Decision 2 — single-session execution REJECTED; decompose into sub-cycles

UNANIMOUS. ~41k LOC / ~191 files is not behavior-preservingly completable in one session at MA-7 rigor. Ratified decomposition (each ends fully GREEN + independently revertible):

- **5a** — stand up the adapter sub-package by moving the ~13 pure-CRUD entities + land **Gate A** enforcing. Zero statemachine risk. Topology/import/constructor-relocation proof.
- **5b** — move the 2 machine-enforced status entities (`release`, `build`) into `store/`; land **Gates B+C** enforcing. MA-7-critical; smallest surface, maximal review. **Gated on:** the ADR (Decision 1 divergence) + the strengthened concurrency oracle (below).
- **5c** — relocate `domain` + `preview` (machine-UNENFORCED status — flag the I1/I2 gap as a follow-up, do NOT retrofit SafeTransition during the move) + sweep remaining CRUD.
- **Step 6 (services grouping) = a SEPARATE cycle** after Step 5 lands fully GREEN (Step 6 imports depend on Step 5's final package names). 8 domain subpackages by bounded context (build/release/preview/domain/placement/scaling/billing/platform); enforce `services/<A> ⊄ services/<B>` + `db/* ⊄ services/*` via an import-linter deny-rule; hoist shared cross-context DTOs to a leaf before moving the first context.

## Blocking pre-conditions for 5b (distributed-systems, MUST land first)

1. **The concurrency oracle is FALSE today.** `release_wrapper_concurrent_activation_test.go:131` does a direct `pool.Exec` UPDATE + *synthesizes* the typed error instead of calling `UpdateStatus`, and `t.Skip`s without live PG. It stays green even if the split severs the 23505→CONCURRENT_ACTIVATION wire. **Strengthen to call the real `UpdateStatus` end-to-end against live PG BEFORE 5b.**
2. **nil-tx atomicity gap (pre-existing correctness finding — see below).** Status mutations must reject `nil` tx; but 3 callers pass `nil` today, so this is a correctness fix, not a no-op.
3. Keep fetch→validate→update as ONE store method; repository/pgx exposes only raw primitives.
4. Move `isReleasesActiveUniqueViolation` + `activeUniqueIndexName` + the typed-error construction into `store/` together (byte-identical).
5. Per-entity incremental; `release` isolated in its own slice; sign-off gated on a live-PG run, not hermetic-only.

## Correctness finding surfaced (tracked, NOT fixed here)

**Non-atomic status mutation via nil-tx pool fallback (pre-existing, HIGH).** 3 call sites pass `nil` tx to a status read-modify-write, so `GetByIDTx` and the `UPDATE` execute on TWO separate pooled auto-committed connections — no atomicity, `pg_advisory_xact_lock` never held:
- `internal/services/preview_service.go:380` — `Store.UpdateStatus(ctx, nil, previewID, newStatus)`
- `internal/services/build_orchestrator_submit.go:213` — `buildStore.UpdateStatus(ctx, nil, buildID, BPEventStarted)`
- `internal/services/build_orchestrator_submit.go:326` — `buildStore.UpdateStatus(ctx, nil, buildID, BPEventFailed)`

Not introduced by M9; surfaced by the design review. Filed as [`docs/operations/findings/2026-07-03-nil-tx-status-mutation-atomicity.md`](../../operations/findings/2026-07-03-nil-tx-status-mutation-atomicity.md). Fixing it (wrap in tx OR reject nil) is a T2 correctness change with its own concurrency analysis — sequence it as pre-condition 2 of 5b, NOT bundled into the behavior-preserving relocation.

## MA landmines (LOCKED)

- MA-6: `db/generated` moved by reference only; never re-run sqlc.
- MA-8: touch ZERO `db/migrations` / `schema.gen.sql` / `*_status_check` constraints in Step 5 (pure Go re-packaging). Do NOT retrofit SafeTransition onto domain/preview during the move.
- tx-threading is load-bearing (I7 atomic supersede + advisory-lock scope): store methods stay tx-parametric across the move.

## Execution contract

- **DoD (Step 5):** met ONLY when 5a+5b+5c all closed GREEN (per-slice `go build ./... && go test ./... && MA-4 set-diff == ∅ && task quality:gates`), Gates A/B/C enforcing, the concurrency oracle strengthened + live-PG-validated, and the nil-tx finding resolved.
- **Guardian re-review at implementation:** state-guardian (each slice), distributed-systems (5b concurrency), api-domain-architect (Step 6 boundaries).
- **Next required artifact before 5b:** an ADR resolving the repository-vs-pgx sub-layer divergence.
