# MEET-2026-03-26-011 — Static Frontend Router Architecture

**Data:** 2026-03-26
**Tipo:** architecture
**Status:** REJECTED (DO Functions) + DEFERRED (External Router) + APPROVED (nginx-s3-gateway inside cluster)
**Sponsor:** SRE (Go Router proposal)
**Challenger:** Principal Architect (stay with approved architecture) + Security (external router risks)
**Owner:** Infra Engineer

---

## Contexto

MEET-009 aprovou Traefik+S3 proxy para frontends estáticos. Na implementação, descobrimos: (1) Traefik bloqueia ExternalName services por default, (2) passHostHeader envia hostname errado ao S3, (3) sem cache. Duas novas propostas foram avaliadas: DO Functions serverless e Go Router no DO App Platform.

## Decisão

**REJEITAR DO Functions. REJEITAR external router. APROVAR nginx-s3-gateway como Pod interno ao cluster.**

### Proposta Rejeitada: DO Functions

| Motivo | Detalhe |
|--------|---------|
| **Custo catastrófico** | $800K+/mês a 5.000 tenants (SRE math: 1M req/min × $0.0000185 = $1,110/hora) |
| **Sem CDN/cache** | Cada invocação re-fetcha do S3. Pior que Traefik com browser caching. |
| **Supply chain risk** | Node.js com npm deps. Credencial S3 exposta a dependency compromise. (Security VETO) |
| **Cold starts** | 50-200ms no primeiro request após idle. Incompatível com "Vercel-quality DX". |

### Proposta Rejeitada: External Router (Go no App Platform)

| Motivo | Detalhe |
|--------|---------|
| **Boundary violation** | Componente fora do control plane, fora do modelo 4-plane. (Architect VETO) |
| **Segunda fonte de verdade** | Build-id resolution duplica `environment_targets`. Dois SOTs = incident garantido. |
| **Sem reconciliação** | Router imperativo, sem convergência. Drift não é detectado. |
| **Novo SPOF** | Componente sem health model, alerting, ou runbook. (SRE VETO) |

### Proposta Aprovada: nginx-s3-gateway dentro do cluster

Deploy `nginxinc/nginx-s3-gateway` como Deployment no workload cluster, atrás do Traefik existente.

```
Browser → Traefik IngressRoute → nginx-s3-gateway Service → DO Spaces S3
                                  ├── S3 auth SigV4 (built-in)
                                  ├── Response cache (built-in)
                                  ├── Compression (built-in)
                                  └── SPA fallback (nginx config)
```

**Por que é correto:**
1. **Sem ExternalName** — nginx-s3-gateway é um Pod com ClusterIP Service. Traefik roteia normalmente.
2. **Sem passHostHeader** — nginx faz a request ao S3 com o hostname correto do bucket.
3. **Cache built-in** — nginx `proxy_cache` reduz hits ao S3. Browser caching via Cache-Control.
4. **S3 auth** — SigV4 signing embutido. Bucket NÃO precisa ser público. (Security win)
5. **URLs unificadas** — mesmo hostname para container e static apps. Zero divergência. (DX win)
6. **Declarativo** — IngressRoute em Gitea, reconciliado por ArgoCD. Mesmo modelo existente.
7. **Oficial** — mantido por Nginx Inc, Docker image pronta, config via env vars.

### DDoS Concern

O tráfego static passa pelo Traefik (dentro do cluster). Isso é aceitável para Fase 1:
- Traefik já serve TODO o tráfego (API, workers, frontends container) — blast radius é igual
- nginx-s3-gateway cache absorve requests repetidos (reduz carga real)
- Browser caching com content-hash filenames (`max-age=31536000`) elimina re-requests
- Fase 2 (CDN edge) é triggered quando tráfego justifica (>1000 req/dia por tenant)

### DX: URLs Unificadas (DX VETO se divergir)

| App Type | URL Format |
|----------|------------|
| Server (container) | `https://{app}-{env}.{project}.{tenant}.dev.loopzero.example` |
| Frontend (static) | `https://{app}-{env}.{project}.{tenant}.dev.loopzero.example` |
| Worker | Sem URL |

**Mesmo hostname. Mesmo TLS cert. Mesmo DNS.** O usuário nunca sabe se é pod ou S3.

## Trade-offs Aceitos

1. **Tráfego static passa pelo cluster.** Aceito porque: cache + browser caching reduzem volume real. Phase 2 (CDN) quando tráfego justifica.
2. **nginx-s3-gateway é um novo Deployment.** Aceito porque: imagem oficial, config via env vars, zero código custom. Menor que qualquer alternativa.
3. **Bucket não é público.** Aceito como feature: S3 auth via SigV4 é mais seguro. Elimina Security FINDING de bucket público.

## Ações Obrigatórias

1. Deploy `nginxinc/nginx-s3-gateway` como Deployment no workload cluster (Helm ou Pulumi)
2. Configurar: `S3_BUCKET_NAME=loopzero-static-assets`, `S3_SERVER=sfo3.digitaloceanspaces.com`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (read-only)
3. Criar ClusterIP Service `static-assets` apontando para nginx-s3-gateway
4. `renderStaticFrontendApp()`: IngressRoute com **mesmo hostname** (sem `static.`), roteando para `static-assets` Service
5. Middleware: addPrefix `/{tenant}/{project}/{app}/{build-id}/` para rewrite de path
6. SPA routing: nginx config com `try_files $uri $uri/ /index.html`
7. Cache-Control headers: `max-age=31536000` para assets com hash, `no-cache` para index.html
8. Security headers: CSP, X-Frame-Options, X-Content-Type-Options em todas responses
9. Remover bucket policy público — nginx-s3-gateway autentica via SigV4
10. Atualizar Sprint 10 roadmap com esta decisão
