## Stage 1 — Context

### Problem

Cosign signing today is **key-based** in two distinct paths:

1. **Platform images path** (`.github/workflows/build-images.yml` + `.github/workflows/helm-charts.yml:259`) — runs in GitHub Actions, signs platform images and Helm charts. Uses `cosign sign --key env://COSIGN_KEY`. Keyless via Fulcio is straightforward here because GitHub Actions provides OIDC tokens via `permissions: id-token: write`.

2. **User-app images path** (`api/internal/argo/cosign.go:cosignSignTemplate`) — runs as Argo Workflows step inside the build cluster, signs user-app images post-BuildKit. Uses key-based with `cosignKeyMountPath`. The code comment at line 93 is explicit: *"cluster does not have OIDC provider for keyless"*. Keyless here requires either (a) a Kubernetes Service Account token configured as OIDC issuer that Fulcio accepts, or (b) Fulcio configured with custom issuer, or (c) Spire/cert-manager-csi-driver-spiffe.

Both paths must migrate to keyless to satisfy proposed gate INF-G16 (Supply Chain Integrity for Charts) and to fulfill CLAUDE.md's "Sprint 9: enforce-mode + cosign keyless (Fulcio)" plan documented in `infra/helm/admission-policies/templates/cluster-image-policy.yaml:5`.

### Decision Required

1. Approve keyless migration strategy.
2. Approve **two-track** approach: Track-1 (GitHub Actions, low risk, fast) and Track-2 (in-cluster Argo, higher complexity).
3. Approve coexistence period (key-based + keyless dual-signing for 1-2 weeks before cutover).
4. Approve admission policy update (`policy-controller loopzero-images-keyless` ClusterImagePolicy in warn → enforce flip).
5. Approve cutover criteria (100% keyless coverage in Rekor for 7 consecutive days before key revocation).

### Constraints

- LoopZero is cloud-only — air-gap is not a current concern (D2 of plan).
- `policy-controller` is deny-by-default (CHG-2026-04-26-SPRINT6-IMPL); changing authorities requires care.
- Production cluster does not currently issue OIDC tokens that Fulcio's public sigstore.dev would accept. Track-2 requires either Spire deployment OR private Fulcio.
- COSIGN_KEY secret in GitHub is the current root of trust for chart signatures. Revoking it without complete keyless coverage creates a verification gap for older chart versions.
- Rekor entries are public — no secrets should leak via signing identity (already the case; identities are GitHub usernames or workload SA names).

### Known Context

- `.github/workflows/helm-charts.yml:259` — current key-based signing of charts.
- `.github/workflows/build-images.yml` — current key-based signing of platform images (multiple jobs).
- `api/internal/argo/cosign.go:53-154` — cosignSignTemplate generating Argo step, key-based.
- `infra/helm/admission-policies/templates/cluster-image-policy.yaml` — current `loopzero-images-warn` policy with `static.action: pass` (sprint 6 audit-only).
- `infra/helm/admission-policies/values.yaml` — `clusterImagePolicy.mode` toggle.
- CLAUDE.md: "cosign keyless verification with Fulcio pendente Sprint 9".
- Plan `infra-sota-hardening-plan.md` ADRs D2 (keyless > key-based), D8 (gate without enforcement is not a gate).

## Stage 2 — Analyses

### Platform Security Engineer — Sponsor (VETO power)

**Assessment.** Keyless via Fulcio + Rekor is the modern best practice. Eliminates key management, adds public audit trail (Rekor transparency log), removes a long-lived secret (COSIGN_KEY) from CI. The two-track approach is correct because the OIDC provider story differs fundamentally between GitHub-hosted runners and in-cluster Argo workloads.

**Risks.** (1) Track-2 requires production OIDC infrastructure that doesn't exist today. Doing it wrong (e.g., minting overly-broad SA tokens, configuring Fulcio to accept untrusted issuers) creates a worse posture than key-based. (2) Cutover too early breaks verify of historical artifacts — keep `loopzero-images-warn` (key-based) authority active until old artifacts are retagged or rebuilt. (3) Identity regex must be tight (`^https://github\.com/getloopscale/loopzero$`) to prevent fork-PR signing.

**Position.** APPROVE. **Condition:** Track-2 must include either (a) a private Fulcio deployment OR (b) a documented decision to defer Track-2 to Sprint 9+ if private Fulcio is out of scope. Track-1 is non-blocking and proceeds immediately.

**No veto** if conditions met.

### SRE Engineer — Challenger (VETO power)

**Assessment.** Production cutover with 1-week observation is correct. Without that, a cosign verification regression takes down deploys silently. The admission policy in `loopzero-images-warn` mode protects us during transition, but only if every image AND chart goes through the dual-sign window with verification confirmed.

**Risks.** (1) Rekor downtime affects keyless verification — must define fallback (cache TUF root, accept on Rekor 5xx for X minutes). (2) Cosign verify in admission webhook adds latency — must measure before flipping enforce. (3) Track-2 in-cluster keyless: if the SA token mounted to Argo step is too broad, an attacker compromising Argo could mint signing requests for arbitrary identities.

**Position.** APPROVE. **Conditions:** (a) admission webhook timeout configured ≤ 3s; (b) policy in `warn` for ≥ 7 days before flip; (c) `cosign verify` failure rate metric exposed and on Grafana before cutover; (d) Track-2 deferred to Sprint 9 if private Fulcio is not stood up before plan completion.

**Veto if not met:** Cutover before warn-period or without metrics.

### GitOps Engineer

**Assessment.** ArgoCD applications already pin charts by version. Adding chart digest pinning (G16 evidence) is a small extension. Keyless verify happens at admission webhook level — ArgoCD itself doesn't verify signatures (that's policy-controller's job). No GitOps changes required for Track-1 charts; Track-2 affects build-time signing of user-app images which ArgoCD also doesn't verify.

**Position.** APPROVE.

## Stage 3 — Decision

### Verdict: APPROVED WITH CONDITIONS

### Mandatory Conditions

1. **Two-track explicit split.** T4.1 splits into T4.1a (GHA, in-scope) and T4.1b (in-cluster, deferred to Sprint 9+ unless private Fulcio is delivered earlier).
2. **Dual-signing for ≥ 7 days.** Both key-based and keyless signatures present before policy flip.
3. **Policy in `warn` mode.** `loopzero-images-keyless` authority added in warn mode; `loopzero-images-warn` (existing static-pass) stays active until cutover.
4. **Admission webhook latency monitored.** Metric `policy_controller_verify_duration_seconds` exposed; alert at p95 > 2s.
5. **COSIGN_KEY revocation requires audit.** `bash scripts/cosign-coverage-audit.sh` must show ≥ 100% keyless coverage for 7 days before secret revocation.
6. **Identity regex narrow.** `^https://github\.com/getloopscale/loopzero$` — single repo only. PR signing from forks is REJECTED.

### Rejected Alternatives

- **Big-bang cutover.** Rejected: violates SRE conditions; no rollback.
- **Skip dual-signing.** Rejected: removes safety net during transition.
- **Track-2 in same sprint as Track-1.** Rejected: OIDC infrastructure for in-cluster Argo is its own meeting and probably its own ADR (Spire vs private Fulcio vs minted-SA-tokens).
