# ADR-0026 — RBAC Generated from `kubebuilder:rbac` Markers; Hand-Edits Forbidden

## Status

Accepted — 2026-05-04 (MEET-2026-05-04-068, security-engineer ABSOLUTE veto NOT triggered)

## Context

LoopZero's `config/rbac/role.yaml` and the per-chart `charts/loopzero-*-operator/templates/role.yaml` files are HAND-EDITED. Privilege drift is silent: a developer adds `r.Client.Delete(ctx, ns)` to a Reconciler, runs `task lint` (no RBAC check), and the pod CrashLoopBackOff with `Forbidden` is the only signal. Audit (`improvement-roadmap.md` §QW-3) confirms current `infra/helm/tenant-controller/templates/rbac.yaml:21-24` carries `apiGroups: ["loopzero.io"], resources: ["*"], verbs: ["*"]` — wildcard.

Reference patterns from FAANG-bar projects:

- **Crossplane:** every controller uses `+kubebuilder:rbac` markers; generated YAML is the only RBAC source.
- **CloudNativePG:** same pattern + per-resource resourceNames where possible.
- **Korifi:** generated RBAC + lint rule blocking wildcard resources.
- **Kueue:** generated RBAC + per-binary scope (`paths=` per binary).

Hand-editing is recognized as an anti-pattern across the SIG community. Generated RBAC is a compile-time guarantee that operator's permissions match its observable behavior.

## Decision

`config/rbac/role.yaml` and `charts/loopzero-*-operator/templates/role.yaml` are GENERATED from `+kubebuilder:rbac` markers placed on each Reconciler struct by `controller-gen rbac`. Hand-editing the generated files is forbidden (header comment "DO NOT EDIT — generated by controller-gen"). CI gate fails any PR that:

1. Hand-edits a generated `role.yaml` file, OR
2. Adds `r.Client.{Get,List,Create,Update,Patch,Delete}` calls without corresponding markers, OR
3. Authors a marker with `resources=*` or `verbs=*` (wildcard ban).

This ADR ratifies plan T4.1 (markers per controller), T4.2 (generation pipeline), T4.3 (CI gate) with the following conditions integrated.

### Conditions (per platform-security-engineer)

1. **Marker style guide BANS wildcards:** `resources=*` and `verbs=*` are forbidden patterns. CI gate enforces. All resources listed explicitly; all verbs enumerated. Exceptions require explicit ADR.

2. **Cross-cluster RBAC blind spot acknowledged + gated separately:**
   - `controller-gen rbac` only generates RBAC for the cluster the operator runs IN.
   - `BuildClient` (build cluster) and `RuntimeClient` (cell-1, cell-2) execute calls using `default` SA token from kubeconfig Secrets.
   - Cross-cluster RBAC lives in `infra/argocd-bootstrap/apps/runtime-rbac.yaml` and `charts/loopzero-build-cwts/templates/rbac.yaml` — hand-maintained.
   - `hack/validate-rbac.sh` AST analyzer MUST distinguish `r.Client` (local, marker-checked) from `r.RuntimeClientFactory.For(cellID).Client` and `r.BuildClient` (cross-cluster, hand-maintained).
   - Cross-cluster gate: `kubectl auth can-i --as=system:serviceaccount:loopzero-system:default <verb> <resource>` matrix in CI against kind cluster, asserting documented allow-list.

3. **3-way diff in T4.1 PR:** PR body MUST include `current-handedited.yaml` vs `generated.yaml` vs `intersection.yaml`. Net-new permissions require explicit per-rule "+ADDED" justification (one inline comment or one ADR per added verb/resource pair). Net-removed permissions require smoke-test evidence (`/dogfood smoke` GREEN with reduced RBAC).

4. **`paths=` scoped per binary (per k8s-controller-engineer):** `controller-gen rbac:roleName=loopzero-tenant paths=./internal/tenant/...` (NOT `./operators/...`). Each binary's chart receives only its markers' RBAC. Plan T4.2 originally specified `paths=./operators/...` — corrected to per-binary.

5. **Static analyzer documented blind-spot list:** `hack/validate-rbac/KNOWN_GAPS.md` enumerates patterns the AST analyzer cannot detect:
   - Dynamic client (`dynamic.NewForConfig(...).Resource(gvr).Get`)
   - Unstructured via discovery
   - Helper indirection (e.g., `shared.applyServerSide(ctx, obj)` wrapping `r.Client.Patch`)
   - Watches/informers requiring implicit `list+watch` not visible in call sites
   - Field/label selectors triggering implicit `list`
   - EventRecorder calls with internal `Patch` events

   Each gap has corresponding negative test fixture in `hack/validate-rbac/testdata/false-positive/`.

6. **Phase 1 SA rename safety (per security-engineer + dx-engineer):**
   - Pre-flight inventory: `grep -r "tenant-controller\|loopzero-controller" infra/ charts/ operators/` audited; every match either renamed or annotated as legacy-tolerant.
   - Helm chart `extraSubjects` knob enables temporary dual-binding (`tenant-controller` + `loopzero-tenant-operator`) on cell ClusterRoleBindings during rollout.
   - NetworkPolicy `podSelector` widened to `app in (tenant-controller, loopzero-tenant-operator)` for rollout window.
   - cell-1/cell-2 ClusterCredential Secrets re-validated post-rollout via `task k3d:heal` family + `kubectl auth can-i` matrix BEFORE legacy chart removed.

7. **Dead-marker analyzer (per k8s-controller-engineer):** Second analyzer pass — every marker verb MUST have at least one matching `r.Client.X` call in the package. Otherwise markers accumulate dead permissions over refactors. Test: `Test_RBACAnalyzer_DetectsExtraMarker`.

### Test fixture suite (per verification-architect veto #2)

`hack/validate-rbac/testdata/`:

- `positive/` — minimum 5 cases (one per CRUD verb + List): missing-marker scenarios that MUST trigger error
- `negative/` — minimum 3 cases: correct markers that MUST NOT trigger
- `false-positive/` — minimum 3 cases: known blind-spot patterns (dynamic client, library wrapper, indirect call through interface) that MUST trigger only warning, not error

Without fixture suite, analyzer reliability is unknown — and analyzers that produce false positives get disabled by frustrated devs within weeks.

## Rationale

### Why generated RBAC

Generated RBAC = compile-time guarantee permissions match code. Hand-editing = silent privilege drift detected only at pod CrashLoopBackOff (or worse, never detected if permission is over-broad). Auditable supply chain requires machine-checkable RBAC.

### Why marker style guide

Naive `+kubebuilder:rbac:groups=loopzero.io,resources=*,verbs=*` reproduces the current wildcard hidden in a Go comment that's HARDER to spot in review than the YAML wildcard. Style guide + CI gate prevents trading a visible wildcard for an invisible one.

### Why cross-cluster gets its own gate

Markers are local-only by design. Cross-cluster RBAC has fundamentally different ownership (runtime cluster admins vs operator developers) and lifecycle (manually maintained, audited separately). Treating cross-cluster as "out of scope for markers" with a SEPARATE explicit gate is more honest than pretending one analyzer covers both.

## Alternatives considered

- **Status quo (hand-edited RBAC):** Rejected — silent drift, wildcard hidden, no automation.
- **OPA / Gatekeeper-only enforcement:** Rejected — runtime enforcement is too late; we want compile-time gate.
- **Custom DSL for RBAC:** Rejected — `controller-gen` is the SIG-standard tool; reinventing violates Don't Reinvent The Wheel.
- **Markers-only without CI gate:** Rejected — makes drift even easier (markers + YAML can disagree, no enforcement).

## Consequences

### Enables

- Least-privilege RBAC by construction.
- Auditable supply chain (markers in code = source of truth).
- New controller PRs auto-update RBAC via `task generate:rbac`.
- Privilege escalation requires explicit marker change + 3-way diff review.

### Constrains

- Developers must add markers BEFORE adding kubectl calls (CI gate enforces; explicit error message points to missing marker).
- Migration: 8 Reconcilers need markers added; 4 chart `role.yaml` files get regenerated.
- Cross-cluster RBAC retains hand-maintenance burden — separate gate, separate review.
- AST analyzer false-positive rate must be documented and managed.

### Reversibility

- ADR reversible via new MEET + ADR.
- Hand-edited RBAC restorable by removing CI gate + deleting markers. Loses auditability.

## Risks

- **HIGH:** First-time generation may produce LARGER permission set than current (silent privilege escalation). Mitigation: 3-way diff gate (condition #3).
- **HIGH:** Cross-cluster RBAC drift invisible to D4 pipeline. Mitigation: separate `kubectl auth can-i` CI matrix (condition #2).
- **HIGH:** SA rename in Phase 1 breaks cell-1/cell-2 ClusterCredential consumption. Mitigation: dual-binding window + 24h soak (condition #6).
- **MEDIUM:** AST analyzer false negatives on dynamic/unstructured/helper-indirect calls. Mitigation: documented blind-spot list with negative tests (condition #5).
- **MEDIUM:** Marker authoring footgun — `resources=secrets` without `resourceNames` enables cluster-wide Secret read. Mitigation: style guide + lint.
- **LOW:** `git blame` traceability degrades because marker→YAML is generated. Mitigation: header comment in generated YAML pointing to source `file:line`.
