Premissas do cenário 50k (ultrathink — edite)

Cells = derivado de maxPerCell (500 → 100 cells @ 50k, engine.go:91). Overhead ~2 nós/cell × 100 = 200 nós só de overhead — o custo real dos "100 clusters" que o cells=25 manual escondia. Densidade vem do KEDA scale-to-zero — 50k tenants ≠ 50k pods.
Nós = derivados pelo Modelo de Capacidade (abaixo): pods/nó = min(CPU-request, memória, ENI/pod-density) → nº de nós. 2 maiores levers: % ativo e pods/tenant. Habilitar prefix delegation destrava o teto ENI.
RDS = 5 bancos de domínio (memory·promptly·rag·lens·trust) × (Multi-AZ + read replicas). Read-heavy (memory/rag pgvector) justificam as réplicas. NÃO é per-tenant — per-tenant RDS = 50k instâncias = milhões/mês.
ECR 60 TB = ~$6k/mês. Lifecycle policy (keep last N digests) é o lever — sem ela cresce sem limite.
Route53 = zonas de plataforma, NÃO per-cliente. Se OD7 virar 1 zona/cliente: 50k × $0,50 = $25k/mês. Evitar via ACM wildcard + zona compartilhada.
Tráfego = simulado (CloudFront 50 TB egress + 2 bi req/mês) — o mais incerto; ajuste com dado real.
