## Quick start

**To bootstrap a fresh local k3d** (`task setup`):

| Required env var | Purpose | Default if unset (after T1.3) |
|---|---|---|
| `LOOPZERO_DB_PASSWORD` | Postgres password (all services) | FAIL fast — no default |
| `LOOPZERO_GITEA_ADMIN_PASSWORD` | Gitea admin password (org `loopzero`) | FAIL fast |
| `LOOPZERO_GITEA_TOKEN` | Gitea API token (CLI + operators) | Generated by `provision-api-tokens.sh` |
| `LOOPZERO_HARBOR_ADMIN_PASSWORD` | Harbor admin password | Auto-generated (`get_or_generate`) |
| `LOOPZERO_HARBOR_REDIS_PASSWORD` | Harbor Redis password | Auto-generated |
| `MINIO_ROOT_PASSWORD` | MinIO admin password (standalone only) | FAIL fast (post T1.3) |

**To run drill (`task drill:up`)**:

| Required env var | Purpose |
|---|---|
| `DIGITALOCEAN_TOKEN` | DO API + DOKS provisioning |
| `PULUMI_ACCESS_TOKEN` | Pulumi state backend |
| `PULUMI_CONFIG_PASSPHRASE` | Decrypts secure: entries in Pulumi.drill.yaml |
| `CLOUDFLARE_API_TOKEN` | CF Zone + Worker management |

Per D7' sponsor override (2026-05-16): drill uses the **same** `DIGITALOCEAN_TOKEN` as prod with isolation at DO project tag + state bucket level. **Deprecated:** `DRILL_DO_TOKEN`.

## Rotation playbook

### `loopzero-db-credentials`

```bash
# 1. Update Secret value
NEW_PASSWORD="$(openssl rand -base64 32 | tr -d '/+=')"
kubectl --context k3d-loopzero-core -n loopzero-system create secret generic loopzero-db-credentials \
  --from-literal=password="$NEW_PASSWORD" --dry-run=client -o yaml \
  | kubectl apply -f -

# 2. Update PostgreSQL role
PGPASSWORD="<current>" psql -h localhost -p 15432 -U loopzero -d postgres -c \
  "ALTER USER loopzero WITH PASSWORD '$NEW_PASSWORD';"

# 3. Restart consumers (they cache DSN at boot)
kubectl --context k3d-loopzero-core -n loopzero-system rollout restart deploy/loopzero-api
kubectl --context k3d-loopzero-core -n loopzero-auth rollout restart deploy/hydra deploy/kratos

# 4. Verify health
task doctor
```

### `gitea-admin` (password + token)

```bash
# Use re-run path (idempotent, refreshes both Secret + Gitea API):
bash infra/helmfile/scripts/generate-secrets.sh standalone mgmt
bash infra/scripts/production/provision-api-tokens.sh

# ArgoCD repo-server cache invalidation:
kubectl --context k3d-loopzero-core -n argocd rollout restart deploy/argocd-repo-server
```

### `cosign-signing-key`

Automated via `.github/workflows/cosign-rotation-drill.yml` (quarterly cron). Manual override:

```bash
bash infra/scripts/cosign-rotation-drill.sh --confirm-rotate
```

### Pulumi config secrets

```bash
cd infra/pulumi
npx pulumi config set --secret <key> <new-value> --stack <stack>
npx pulumi up --stack <stack> --yes
```

### Other K8s Secrets

Each has a generator script. Re-run the script idempotently — `get_or_generate` will preserve existing values unless the override env var is set, OR delete the Secret first to force regeneration:

```bash
kubectl -n <ns> delete secret <name>
bash infra/helmfile/scripts/generate-{secrets,runtime-secrets,build-secrets}.sh standalone <plane>
```

## Pre-condition for `pulumi --stack prod`

Before T1.5 lands placeholder `secure:` entries, running `pulumi preview --stack prod` locally without the secrets produces cryptic provider errors deep in resource creation. After T1.5:

```bash
PULUMI_CONFIG_PASSPHRASE="<passphrase>" pulumi preview --stack prod
# Fails fast with: "secret 'digitaloceanToken' = REQUIRED_PLACEHOLDER"
```

Operators MUST have `PULUMI_CONFIG_PASSPHRASE` to decrypt the stack config; this is a stand-by RBAC gate (per EC-14 of the plan).

## Drift gate

`infra/tests/docs/credentials-sot_test.sh` is the enforcement gate. It runs in CI and fails if any K8s Secret created by code is missing from this document.

```bash
bash infra/tests/docs/credentials-sot_test.sh
# Expected: [credentials-sot] PASS — all bootstrap Secrets enumerated in docs/operations/credentials-required.md
```

Add a credential? You MUST update this doc in the same PR, or the gate fails.
