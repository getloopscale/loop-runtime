# T2.2 Cosign Keyless Infrastructure — Change Governor Diagnostic Package

**Date prepared:** 2026-05-27 (Ralph iter 11)
**Plan reference:** T2.2 of [`docs/plans/2026-05-26-maturity-3-62-to-4-0-roadmap-plan.md`](./2026-05-26-maturity-3-62-to-4-0-roadmap-plan.md)
**Status:** **AWAITING SPONSOR MEETING** — this doc pre-populates everything Change Governor needs

> **Operator action:** Invoke `/meeting` with `topic="T2.2 Cosign keyless Fulcio+Rekor provisioning"` and reference this doc. Required reviewers below.

## 1. Problem Statement

ADR 2026-05-12 committed LoopZero to migrate cosign signing from `keyed` mode (static keypair em ESO Secret) to `keyless` mode (workload identity → Fulcio cert → Rekor transparency log) by **2026-08-10** (T0+90 days hard deadline). Today is 2026-05-27 = **74 days remaining**.

Phase A of the cutover (infra provisioning, T0+30d) was targeted for 2026-06-11. As of today we are **15 days into the 30-day Phase A window** with zero provisioning started. The enforcement script `infra/scripts/security/check-cosign-cutover-deadline.sh` (T3.3, shipped iter 1) will block production builds when `mode=keyed AND date > deadline`.

## 2. Decision Required

**APPROVE Pulumi-based Fulcio + Rekor provisioning** em `infra/pulumi-platform/` to enable cosign keyless signing, OR formally defer via MEET-ASYNC-AMENDMENT acknowledging timeline slip.

## 3. Tier Classification

**T3** — architecture + critical flow + supply chain. Per `.claude/rules/pre-release-governance.md`, T3 requires:
- Sponsor sign-off em `.claude/governance-gate.local.md`
- Production Design Reviewer + Security & Blast Radius + SRE meeting
- Formal ADR

## 4. Alternatives Evaluated

### Option A — Pulumi component (RECOMMENDED)

Provision Fulcio + Rekor as Pulumi ComponentResources em `infra/pulumi-platform/src/services/`, following same pattern as cert-manager.ts and traefik.ts.

**Pros:**
- Declarative + idempotent + auditable
- Single source of truth (ADR-0023 layered IaC)
- Pulumi preview shows resource diff before LIVE apply
- Stack-per-env config (dev/drill/prod) via Pulumi.<stack>.yaml
- Aligns with existing platform-services pattern

**Cons:**
- ~16h engineering effort (vs ~8h manual Helm)
- Requires TypeScript proficiency for component authoring
- New external dependency on `sigstore/charts/fulcio` OCI chart

**Effort:** 16h engineering + 24h drill soak + sponsor review window

### Option B — Manual Helm install

Run `helm install` manually on each cluster (mgmt + drill + prod).

**Pros:**
- Faster initial setup (~8h)
- No Pulumi component authoring needed

**Cons:**
- Configuration drift between clusters (per existing IaC discipline doc)
- No diff preview before apply
- Operator-led upgrade burden (3x cluster rotations)
- Violates ADR-0023 layered bootstrap pattern
- No `pulumi destroy` clean tear-down

**Verdict:** REJECTED — violates established platform conventions.

### Option C — Defer to v1.x post-GA

Skip keyless cutover; remain em keyed mode with manual rotation cadence (≥90 days).

**Pros:**
- Zero short-term engineering
- No new infra to maintain

**Cons:**
- Breaks ADR 2026-05-12 hard commitment (sponsor-ratified per MEET-2026-05-12)
- check-cosign-cutover-deadline.sh will block production builds on 2026-08-10
- Requires emergency override flag (`--emergency-override`) with audit trail + post-hoc Change Governor review
- Increases blast radius window of key compromise (90d vs 10min)
- Signals to enterprise customers (T11 SOC 2 prep) that supply-chain commitment is soft

**Verdict:** REJECTED unless explicit MEET-ASYNC-AMENDMENT formalizes timeline slip with new deadline.

## 5. Trade-offs (Option A)

| Dimension | Trade-off |
|-----------|-----------|
| Cost | ~$0 (Fulcio + Rekor são open-source self-hosted) + provisioning compute (~$5/mês em mgmt cluster) |
| Engineering effort | ~16h (vs ~8h manual) |
| Time to ship | ~3 weeks (engineering + drill soak + prod cutover) |
| Operational complexity | +2 services to monitor (Fulcio + Rekor health) |
| Blast radius reduction | Key compromise window: 90d → 10min (270× improvement) |
| Auditability | Public Rekor log = external append-only audit trail |
| Compliance | Aligns with SOC 2 supply-chain controls (future enterprise tier) |

## 6. Risk Analysis

### Risks to APPROVE

| Risk | Severity | Mitigation |
|------|----------|------------|
| TLS issuer mismatch per env (k3d cant letsencrypt-prod) | HIGH | EC-3 already absorbed in plan v1.1 — issuer per env (k3d=self-signed CA, drill=staging, prod=prod) configured via Pulumi config key `cosign.tlsIssuer` |
| Fulcio chart version drift over time | MEDIUM | EC-2 absorbed — chart pinned to `oci://ghcr.io/sigstore/charts/fulcio` specific version; Renovate manages bumps |
| Pod restart cycle if existing builds use keyed during transition | MEDIUM | Phased rollout — keep `mode=keyed` in ConfigMap until ALL infra verified; flip is single ConfigMap edit |
| Fulcio API server outage breaks build pipeline | MEDIUM | Operate Fulcio HA (2 replicas + PDB); fallback to keyed mode via ConfigMap edit |
| Rekor public log dependency on external service | LOW | Self-host Rekor instance; no external SaaS dependency |

### Risks to DEFER (Option C)

| Risk | Severity |
|------|----------|
| ADR 2026-05-12 commitment broken — sponsor credibility loss | HIGH |
| Production builds blocked on 2026-08-10 (74 days) | HIGH |
| Emergency override flag becomes load-bearing — anti-pattern accumulates | MEDIUM |
| Maturity score regression em next audit (M07 Build Pipeline) | MEDIUM |

## 7. Validation Plan (Change Validation Planner format)

### Pre-deploy

- [ ] Pulumi component tests PASS (vitest, 8-12 tests per Fulcio + Rekor)
- [ ] `pulumi preview --stack drill` shows correct resource diff
- [ ] Fulcio CA root extractable via `kubectl exec fulcio-0 -- cat /var/run/fulcio/ca.crt`
- [ ] Rekor public key extractable similarly

### Post-deploy (drill stack 24h soak)

- [ ] Fulcio + Rekor pods Running 1/1 (HA mode 2/2)
- [ ] Build pipeline can request keyless cert successfully
- [ ] Cert TTL <= 10 minutes (verify via `cosign verify` of signed image)
- [ ] Rekor entry appears within 5s of signature
- [ ] policy-controller verifies signed image via keyless path
- [ ] Zero impact on existing keyed builds (ConfigMap mode=keyed unchanged)

### Cutover (mgmt → prod)

- [ ] Phase A (T0+30d): infra deployed em drill + mgmt (this task)
- [ ] Phase B (T0+45d): staging cutover + 14-day soak
- [ ] Phase C (T0+75d): prod cutover after drill GREEN + Phase B clean
- [ ] Phase D (T0+90d): keyed mode deprecation; emergency override expires

### Rollback procedure

If keyless fails at any phase:
1. Edit ConfigMap `loopzero-system/loopzero-cosign-config`: `mode: keyed`
2. Re-deploy keyed signing key via ESO (path preserved)
3. Document failure mode in `.claude/knowledge-base/reviews/`
4. Schedule fix sprint; do NOT pass T0+90d without resolution OR formal deferral ADR
