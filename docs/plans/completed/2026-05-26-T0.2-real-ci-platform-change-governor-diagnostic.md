# T0.2 Real CI Platform Choice — Change Governor Diagnostic Package

**Date prepared:** 2026-05-27 (Ralph iter 11)
**Plan reference:** T0.2 of `docs/plans/2026-05-26-maturity-3-62-to-4-0-roadmap-plan.md`
**Status:** **AWAITING SPONSOR T3 MEETING** — diagnostic pre-populated

## 1. Problem Statement

GitHub Actions was removed 2026-05-23 (operator decision: "GitHub Actions is not the CI/CD platform"). Per CLAUDE.md current state, all CI logic was re-homed to `task quality:*` orchestrated by `cmd/loopzero-ops` Go binary + operator-driven invocation. **All scheduled crons (drill watchdog every 6h, soaks weekly, coverage report) became operator-mediated.**

Strategic implication per M12 audit:
- Zero automated PR-time gates blocking merges (branch protection has no required checks)
- Drill watchdog cron + soaks weekly + coverage reports = operator must remember to run
- Trivy + TruffleHog scans wired em `task quality:gates` (skip-on-missing per iter 4 T4.7) but no PR-time enforcement
- Maturity gate (a) "operator-run prod-identical drill GREEN" was previously the GitHub Sunday cron `drill-prod-identical-soak.yml` — now requires operator to run `task drill:l2-scale` manually

## 2. Decision Required

**Choose one CI platform** to provide:
1. PR-time gate enforcement (block merge if `task quality:gates` fails)
2. Scheduled cron equivalents (drill watchdog 6h, soak weekly, coverage weekly, cosign deadline daily)
3. Multi-cluster awareness (must work with k3d local + DOKS prod-identical drill)
4. Secret management integration (ESO-compatible)
5. Required status checks for branch protection

## 3. Tier Classification

**T3** — architecture + critical flow (affects ALL quality gates + drill orchestration + production canary automation). Per `.claude/rules/pre-release-governance.md`, T3 requires:
- Sponsor sign-off
- Production Design + Security + SRE + Sponsor meeting
- Mandatory ADR

## 4. Alternatives Evaluated (6 options)

### Option A — Argo Events + Workflows + CronWorkflows

Re-uses existing Argo Workflows infra (already provisioned em build cluster).

**Pros:**
- Zero new external dependencies — Argo Workflows already running for builds
- K8s-native (multi-cluster aware via cluster credentials)
- Same SSE/observability stack as build pipeline
- CronWorkflow is mature for scheduled cron equivalents

**Cons:**
- Less mature for CI (PR-time gating) than for build pipelines
- Argo Events EventSource for GitHub webhook needs separate provisioning
- Smaller community for CI use case

**Cost:** $0 (already have Argo Workflows)
**Engineering:** ~4-8h

### Option B — Self-hosted GitHub Actions runners

Re-deploy `.github/workflows/*.yml` (restoration of 2026-05-23 status quo) on self-hosted runners.

**Pros:**
- Workflows already exist (51 files were deleted; git history preserves)
- Mature CI ecosystem; well-known to operators
- GitHub-native PR comments + status checks

**Cons:**
- Undoes the 2026-05-23 operator decision — needs MEET-ASYNC-AMENDMENT
- Runners must be operationally maintained (security patches + scaling)
- Cost (compute + maintenance)

**Cost:** $50-200/mo compute + ongoing ops
**Engineering:** ~8h (restore workflows + runner provisioning)

### Option C — Drone CI

K8s-native CI platform.

**Pros:**
- K8s-native; simple to operate
- Open source

**Cons:**
- Smaller community
- Limited cron/scheduled job support compared to Argo Workflows

**Cost:** Open source self-hosted
**Engineering:** ~16h (new platform learning curve)

### Option D — BuildKite (hybrid cloud orchestrator + on-prem runners)

SaaS orchestrator + LoopZero-controlled runners.

**Pros:**
- Excellent multi-cluster + multi-environment support
- Best-in-class secret management
- Mature scheduled jobs

**Cons:**
- Cost (per-build pricing)
- Vendor lock-in
- External dependency

**Cost:** $300+/mo
**Engineering:** ~16h

### Option E — GitLab CI

Integrated GitLab platform.

**Pros:**
- Mature CI ecosystem
- Strong PR/MR integration

**Cons:**
- Requires GitLab SaaS OR self-hosted GitLab (~12GB RAM single instance)
- Major migration from GitHub repo (code/issues/PRs all em GitHub)

**Cost:** $19/user/mo SaaS OR ~$50/mo self-hosted
**Engineering:** ~40h (repo migration is massive)
**Verdict:** REJECTED — repo migration prohibitive

### Option F — Jenkins

Most flexible CI platform.

**Pros:**
- Plugin ecosystem (anything you can imagine)
- Mature

**Cons:**
- High operational overhead (plugin compatibility, version management)
- Security concerns (regular CVEs em plugins)
- "Configuration-as-code" plugin maturity weak

**Cost:** Open source self-hosted
**Engineering:** ~24h
**Verdict:** REJECTED — operational burden + security history

## 5. Recommended (subjective — sponsor decides)

**Option A (Argo Events + Workflows + CronWorkflows)** — reuses existing infra, K8s-native, $0 marginal cost. Implementation:

1. Provision Argo Events EventBus + Sensor (Pulumi component)
2. Provision GitHub Webhook EventSource (pointing at github.com/getloopscale/loopzero)
3. Author WorkflowTemplate for PR-time gates (`task quality:gates`)
4. Author 4 CronWorkflows (drill watchdog 6h, soaks weekly Sunday, coverage Monday, cosign deadline daily 00:00 UTC)
5. Wire GitHub status check API (so branch protection blocks)
6. Document operator runbook for failure modes

**Fallback (per EC-15 of T0.2 plan):** If sponsor doesn't decide em 4 weeks, default to Option B (restore GitHub Actions runners) — status quo restoration is safer than continued operator-mediated chaos.

## 6. Trade-offs (Option A vs alternatives)

| Dimension | Option A (Argo) | Option B (GH Actions) | Option D (BuildKite) |
|-----------|----------------|----------------------|---------------------|
| Cost | $0 marginal | $50-200/mo | $300+/mo |
| Engineering | 4-8h | 8h | 16h |
| Operational burden | Same as build (Argo expertise required) | GitHub-managed runners | SaaS-managed |
| K8s-native | Yes (built for) | No (foreign) | Hybrid |
| Vendor lock | Apache 2.0 | GitHub | Proprietary |
| Maturity for CI | Medium | High | High |

## 7. Risk Analysis

### Risks to APPROVE Option A

| Risk | Severity | Mitigation |
|------|----------|------------|
| Argo Events maturity gap for PR-time CI | MEDIUM | Pilot em drill stack first; 30-day soak |
| GitHub webhook delivery reliability | LOW | Argo Events has retry semantics |
| Workflow template authoring burden vs YAML actions | MEDIUM | One-time investment; templating once = N PRs benefit |

### Risks to DEFER decision

| Risk | Severity |
|------|----------|
| Branch protection has no required checks → broken merges land | HIGH |
| Drill watchdog cron forgotten → orphan drill stack accumulates cost ($24/day) | HIGH |
| Maturity gate (a) cannot close without scheduled drill | HIGH |
| Trivy + TruffleHog gates wired but never enforce | MEDIUM |
