# Plan: Live CA Fetch from `kube-root-ca.crt` on ClusterCredential Reconcile (Op B)

> **Version 1.3** — Eliminates the entire class of "stale `caData` in ArgoCD cluster Secret" bugs (root cause behind closed issues #66 and #67) by making the `ClusterCredentialReconciler` fetch the live cluster CA from the target cluster's `kube-root-ca.crt` ConfigMap on every reconcile, instead of relying on the kubeconfig caData snapshot captured at bootstrap. Expected outcome: heal scripts H19/H19a become unnecessary; no manual operator intervention required when any target cluster rotates its CA.

## Context

### What exists today

**`reconcileArgoCDClusterSecret`** in `operators/internal/platform/clustercredential_controller.go:284-376` reads `caData` from the kubeconfig stored in the source `ClusterCredential.spec.secretRef` Secret:

```go
restConfig, err := clientcmd.RESTConfigFromKubeConfig(kubeconfigData)
// ...
caData := ""
if len(restConfig.CAData) > 0 {
    caData = base64.StdEncoding.EncodeToString(restConfig.CAData)  // ← snapshot
}
```

That kubeconfig is generated by bootstrap scripts (`infra/scripts/lib/bootstrap-cell-cc-common.sh`, `infra/helmfile/scripts/lib/clustercredential-create.sh`) at the moment the cluster is wired. The `caData` is **frozen at that snapshot** and the controller writes it into the ArgoCD cluster Secret on every reconcile.

### What's broken

1. **k3d local**: every k3s server container restart can rotate the k3s server CA (`/var/lib/rancher/k3s/server/tls/server-ca.crt` regenerated). The snapshot becomes stale → ArgoCD fails with `x509: certificate signed by unknown authority` → all deploy/promote/rollback flows silently break (CLI returns exit 0, but ArgoCD never syncs).
2. **Prod (DOKS, Droplet)**: same failure mode would occur if the managed control plane rotated its CA during a repair or incident. Rare but plausible — and prod has worse blast radius.
3. **Reactive workarounds accumulating**: H19 (Secret patch) was overwritten by the operator's next reconcile; H19a (CR patch) shipped in `40580a0b` works because the CR is the SoT — but H19a only flips `insecure=true`, which is a downgrade in TLS posture inappropriate for clusters that must verify (Enterprise tier).

### Evidence

- **Closed issue [#66](https://github.com/getloopscale/loopzero/issues/66)** — original "rollback bug" symptom (CLI exit 0, app keeps serving v2). Root cause traced to ArgoCD x509 to cell-default.
- **Closed issue [#67](https://github.com/getloopscale/loopzero/issues/67)** — `loopzero-platform-operator overwrites argocd cluster-cell-* Secrets with stale caData`. Op (A) shipped in `40580a0b`.
- **LIVE evidence 2026-05-25** captured in close-comment of #67: `managedFields` showed `loopzero-platform-operator` rewriting the Secret 2h27m after H19's manual patch, with `tlsClientConfig.insecure:false` + stale caData.
- **`kube-root-ca.crt` standard since K8s 1.21** — every cluster has this ConfigMap auto-provisioned in every namespace by `kube-controller-manager`, refreshed when CA rotates. Used by every in-cluster pod for API validation (`/var/run/secrets/kubernetes.io/serviceaccount/ca.crt`). H13 in the heal script already uses this pattern for SA token CA refresh.

## Objective

**Done = ArgoCD cluster Secret always reflects the live cluster CA without any heal script intervention, on every target cluster (k3d local, DOKS prod, future on-prem).**

Specific measurable goals:
1. `reconcileArgoCDClusterSecret` fetches `kube-root-ca.crt` from the target cluster `default` namespace on every successful connectivity check, uses that PEM as `caData`.

4. New envtest specs cover (a) live fetch overrides snapshot, (b) fallback path, (c) insecure-true skip path, (d) idempotency under reconcile cycles.

## ADRs

### D1 — Source live CA from `kube-root-ca.crt` ConfigMap on target cluster (with insecure-fetch bootstrap)

- **Decision**: each reconcile of `ClusterCredentialReconciler` issues one `GET ConfigMap default/kube-root-ca.crt` against the target cluster (via the existing bearer token) and uses `data["ca.crt"]` as the ArgoCD `tlsClientConfig.caData` (after base64-encoding). The GET call uses a **cloned `rest.Config` with `TLSClientConfig.Insecure = true`** (caData/certData zeroed) to avoid the bootstrap circular dependency where stale snapshot CA prevents fetching fresh CA (see EC-13 amendment).
- **Rationale**: `kube-root-ca.crt` is the K8s-blessed, auto-rotated authoritative source for the cluster CA. Every namespace has it (K8s ≥ 1.21 universal default), every cluster type supports it (k3d, kind, kubeadm, DOKS, EKS, GKE). The H13 heal script already validates the pattern works for SA token CA. Alternatives rejected:
  - **cert-manager `Certificate` watching the API server** — adds a hard dependency on cert-manager + requires a CertManager Issuer per cluster + bespoke watcher logic. Heavyweight.
  - **CronJob refreshing the Secret periodically** — same loop problem as H19 (gets overwritten by the operator), and reactive in spirit.
  - **Force admin to run `task k3d:heal` after every CA rotation** — current state, demands tribal knowledge, violates CTO Rule 5 (50k tenants needs zero-touch ops).
  - **External secret backend (Vault, Infisical, ESO provider)** — wrong domain; cluster CA is not a vault secret, it's a control-plane primitive.
- **Insecure-fetch bootstrap trade-off (EC-13 amendment)**: the GET to `kube-root-ca.crt` is intentionally `Insecure: true` because:
  1. The payload IS the public CA itself — there's nothing to keep secret.
  2. Using the stale snapshot CA to validate the connection that fetches the fresh CA is logically impossible after rotation (TLS fails first → fetch never runs → Op B silently becomes no-op).
  3. ArgoCD subsequently uses the fetched CA for ALL secure traffic — the insecure window is exactly one GET per reconcile, never user data, never write operations.
  4. An attacker MITM-ing this GET could inject a forged CA, but only if they ALSO control the kubeconfig's bearer token endpoint resolution (DNS / network routing) — at which point the cluster is already compromised at a layer Op B isn't designed to defend.
- **Consequences**:
  - **Enables**: zero-touch CA rotation in any cluster; identical local↔prod mechanism (CTO Rule 0); future Enterprise tier with TLS verification required.
  - **Constrains**: target cluster must allow `GET ConfigMap default/kube-root-ca.crt` for the credential's SA. K8s default RBAC grants this via `system:public-info-viewer` ClusterRoleBinding — universal. RBAC-strict clusters (CIS Level 2 hardening) may revoke; we handle via fallback (D2).
  - **Audit**: each fetch logs `audit="insecure_ca_bootstrap"` so SRE can grep for the insecure-window invocations if compliance asks.

### D2 — Graceful fallback to kubeconfig caData snapshot

- **Decision**: when live CA fetch fails (RBAC denied, ConfigMap missing, network error, malformed PEM), log a structured `Warn` and fall back to the existing `restConfig.CAData` snapshot. Reconcile still produces a Secret; only the "freshness guarantee" degrades.
- **Rationale**: Op (B) should never be worse than today. If a cluster refuses the fetch, today's behavior (snapshot caData) is exactly what ArgoCD gets. Failures are loud (`slog.Warn` + Prometheus counter) so SRE can detect and fix RBAC; no silent silently-broken state.
- **Consequences**:
  - **Enables**: gradual rollout — clusters without proper RBAC continue working with current semantics; admin can opt-in by fixing RBAC.
  - **Constrains**: testers must verify both paths (live + fallback) — adds 1 envtest spec but no production complexity.

### D3 — Inject CA fetcher via interface (DIP)

- **Decision**: extract `caFetcher` interface with one method `FetchClusterCA(ctx, restConfig) ([]byte, error)`. Production impl uses `client-go`. Tests inject a fake.
- **Rationale**: envtest already runs in-cluster — calling `kubernetes.NewForConfig` inside the reconciler under test is fine but couples test infrastructure to envtest config. The interface lets unit tests stub failures deterministically (RBAC denied, timeout, malformed PEM) without needing live envtest scenarios for each branch.
- **Consequences**:
  - **Enables**: unit tests for all error branches in milliseconds (no envtest spin-up).
  - **Constrains**: adds ~30 lines of interface boilerplate. Worth it for ISP + LSP discipline.

### D4 — `spec.tls.insecure=true` short-circuits the fetch

- **Decision**: at the top of `reconcileArgoCDClusterSecret`, if `cr.Spec.TLS.Insecure==true`, skip the CA fetch entirely. Render the Secret with `insecure:true` and empty `caData` (current behavior matches this when caData is empty).
- **Rationale**: when ArgoCD has `insecure:true`, it ignores `caData` by design. Doing the fetch anyway would (a) waste a network call, (b) cascade `Warn` logs in dev clusters where the fetch may legitimately fail because of broken RBAC nobody cares about. Op (A) declarative override stays cleanly orthogonal.
- **Consequences**:
  - **Enables**: Op (A) k3d-local fast path remains zero-cost; gradual migration possible (clusters that want TLS verification opt in by flipping `spec.tls.insecure=false` AFTER Op B is live).
  - **Constrains**: two code paths to maintain (insecure vs verified). Acceptable; the if-check is one line.

### D5 — Heal H19 + H19a deletion deferred to dedicated post-soak task

- **Decision**: do NOT delete H19/H19a from `infra/scripts/local/k3d-cross-cluster-heal.sh` in the same PR that ships Op (B). Land Op (B), wait 7-day LIVE soak with zero CA-related regressions, then delete in Phase 5.
- **Rationale**: H19/H19a are the safety net during the migration window. Deleting them prematurely couples the rollout to perfect reconciler behavior on day one. The 7-day window is short enough to maintain momentum, long enough to catch the failure modes a single-day cleanroom misses (DST changes, k3s GC cycles, long-running tilt sessions).
- **Consequences**:
  - **Enables**: zero-regression rollout; ability to disable Op (B) via revert without losing the operational safety net.
  - **Constrains**: heal script carries dual logic for 7 days. Trivially small cost (~30 lines, idempotent).

#### Deep Dives

**Interface signature** (DIP-friendly, minimal):
```go
// caFetcher abstracts how the reconciler obtains the live cluster CA.
// Production uses kubeRootCAFetcher (calls client-go); tests inject fakes.
type caFetcher interface {
    FetchClusterCA(ctx context.Context, restConfig *rest.Config) ([]byte, error)
}
```

**Default impl** (EC-13 + EC-15 + EC-16 amendments):
```go
type kubeRootCAFetcher struct {
    // namespace can be overridden for tests; production uses "default".
    namespace string
}

func newKubeRootCAFetcher() *kubeRootCAFetcher {
    return &kubeRootCAFetcher{namespace: "default"}
}

// utf8BOM is the UTF-8 byte order mark sometimes prepended by cert generators
// that write files in BOM-aware mode (EC-16). Strip before PEM validation.
var utf8BOM = "﻿"

func (f *kubeRootCAFetcher) FetchClusterCA(ctx context.Context, restConfig *rest.Config) ([]byte, error) {
    // EC-15: nil-protect — DI bug in tests would otherwise panic in NewForConfig.
    if restConfig == nil {
        return nil, fmt.Errorf("kube-root-ca fetcher: restConfig is nil")
    }

    // EC-13 (CRITICAL): bootstrap circular dependency.
    // restConfig.CAData came from the SAME stale snapshot we're trying to
    // refresh. Using it for TLS verification means: after CA rotation, this
    // GET fails with x509 → fallback path → silently no-op. Defense:
    // clone the config and force Insecure for this ONE call. The payload IS
    // the public CA; insecure-fetching it is logically safe (ADR D1 trade-off).
    cfg := rest.CopyConfig(restConfig)
    cfg.TLSClientConfig = rest.TLSClientConfig{Insecure: true}

    cs, err := kubernetes.NewForConfig(cfg)
    if err != nil {
        return nil, fmt.Errorf("kube-root-ca fetcher: create client: %w", err)
    }
    cm, err := cs.CoreV1().ConfigMaps(f.namespace).
        Get(ctx, "kube-root-ca.crt", metav1.GetOptions{})
    if err != nil {
        return nil, fmt.Errorf("kube-root-ca fetcher: get configmap: %w", err)
    }
    pem, ok := cm.Data["ca.crt"]
    if !ok || pem == "" {
        return nil, fmt.Errorf("kube-root-ca fetcher: ca.crt key missing or empty")
    }
    // EC-16: strip UTF-8 BOM if present (some cert pipelines write it).
    pem = strings.TrimPrefix(pem, utf8BOM)
    // Sanity: PEM block must start with `-----BEGIN`
    if !strings.HasPrefix(pem, "-----BEGIN") {
        return nil, fmt.Errorf("kube-root-ca fetcher: ca.crt is not a PEM block")
    }
    return []byte(pem), nil
}
```

**Invariants**:
- Function returns either `(non-nil, nil)` or `(nil, non-error)` — never `(nil, nil)`.
- Returned bytes are valid PEM.
- Timeout: caller's `ctx` controls timeout. Reconciler passes a 5s child context.

**Edge cases handled in unit tests**:
- ConfigMap not found → wrapped error
- ConfigMap exists but `ca.crt` key missing → wrapped error
- `ca.crt` empty string → wrapped error
- `ca.crt` not PEM (e.g., binary garbage) → wrapped error
- Context cancelled mid-fetch → wrapped error from client-go
- Multiple PEM blocks (intermediate + root) → returned as-is (ArgoCD accepts chain)

## Edge Case Review Notes (inline, in lieu of separate /edge-case-plan invocation)

This plan was reviewed for edge cases inline during drafting. Items found:

### MUST FIX (incorporated as sub-tasks above)

- **EC-3**: Reconciler may panic if `r.caFetcher == nil` (forgot DI) → constructor enforces non-nil + Phase 1 wiring sets default. **Already incorporated** in T1.1 step 4.
- **EC-4**: `caFetcher` injected with stub that returns `nil, nil` (test bug) → unit test EC asserts this never happens. **Already incorporated** in T1.1 RED test `TestKubeRootCAFetcher_Success` (must return non-nil on success).
- **EC-5**: H19/H19a deletion BEFORE 7-day soak → ADR D5 + Phase 5 explicitly defers. **Already incorporated**.

### SHOULD TEST (added to T3.1 spec list)

- **EC-6**: Multiple concurrent reconciles for same CR (Secret watcher + periodic + manual edit) → T3.1 spec 4 (idempotency) covers.
- **EC-7**: CA in `kube-root-ca.crt` includes multi-cert chain (root + intermediate) → ArgoCD accepts; assert no truncation.

### DOCUMENT (acknowledged, not fixed)

- **EC-8**: Op (B) does NOT eliminate H13 (SA token CA rotation in cell-default Secret). Different concern (SA UID changes vs CA rotation). H13 cleanup is separate plan.
- **EC-9**: First reconcile after operator restart may fetch concurrently for all CRs → API server cache handles; no rate-limit risk for 3-cell topology.
- **EC-10**: If target cluster's `kube-root-ca.crt` ConfigMap is itself broken (data corruption), Op (B) returns error → fallback → snapshot caData stays in use. **No silent failure**: log Warn + counter increment alerts SRE.

### IGNORE (loopzeroretical, fix worse than problem)

- **EC-11**: Network partition during fetch → ctx 5s timeout returns DeadlineExceeded → fallback. Recovers on next reconcile when partition heals.
- **EC-12**: Adversary forges `kube-root-ca.crt` ConfigMap in default namespace → would require write access to target cluster's `kube-system` controller-manager. If adversary has that, the cluster is already compromised; Op (B) is not the right defense layer.
