## Fixes sistêmicos shipped (commits isolados ADR D6)

### Achado #17 — S0 produção — colisão K8s resource names entre projetos
**Commit**: `14c87203` `fix(manifests): project-scope K8s resource names to prevent collision`
- **Sintoma**: dois projetos com app de mesmo nome (`api`) colidem em Deployment/Service/Cert/IngressRoute. Service.spec.selector match cross-project (label-based).
- **Discovery**: journey-01 retornou body de pods do projeto anterior (compartilhamento de namespace tenant + selector label `app: api`).
- **Fix**: `manifests/renderer_helpers.go:resourceName(project, app) = "<project>-<app>"`. Aplicado em 9 sites (Deployment/Service/HPA/PDB/IngressRoute/Cert/ScaledObject/HTTPSO/Middleware). UX user-facing inalterado (hostname já contém project, loopzero logs/scale continuam usando label `loopzero.io/app-name`).
- **Test regression**: `renderer_collision_test.go:TestRender_NoCollisionBetweenProjectsWithSameAppName`.

### Achado #19 — S0 produção — ESO ClusterSecretStore não bootstrap em helmfile L2
**Commit**: `eee057fd` `fix(dogfood): bootstrap ESO ClusterSecretStore + journeys 03/06 + preflight T0.9`
- **Sintoma**: pods com `secrets:` declarado em loopzero.yaml ficavam CreateContainerConfigError. ESO ExternalSecret reportava "could not get ClusterSecretStore loopzero-mgmt-store: not found".
- **Root cause**: `ClusterSecretStore loopzero-mgmt-store` é provisionado por Pulumi em prod, mas helmfile L2 (standalone-multi) não tinha paridade.
- **Fix**: `infra/helmfile/scripts/bootstrap-eso-cluster-secret-store.sh` (NEW) reproduz exatamente o que Pulumi faz: SA scoped + RBAC + long-lived token + Secret runtime + CSS. Idempotente.

### Achado #20 — S0 produção — sync_client filter desincronizado com Achado #17
**Commit**: `02bf5bf4` `fix(release-convergence): pass project-scoped resource name to ArgoCD health filter`
- **Sintoma**: TODAS releases SYNC_FAILED no DB mesmo com ArgoCD App Healthy + pod respondendo HTTP 200.
- **Root cause**: second-order do Achado #17. `sync_client.go:329` faz match `appSet[res.Name]` onde res.Name é Deployment K8s name (project-scoped) mas appSet vem de raw `app.Name`. Match nunca acontece → matchedCount=0 → healthy=false → release stuck SYNC_FAILED.
- **Fix**: `release_convergence_loop.go` linhas 250 e 428 passam `fmt.Sprintf("%s-%s", release.ProjectID, app.Name)` para deployedAppNames.

### F7 — S0 — static_delivery silent-success eliminado
**Commit incluído em**: `a1220eb2` + ADR-0019 `eee057fd`
- Branch `if kvClient == nil { return nil }` substituído por fail-loud quando ambos kvClient e localProvisioner são nil.
- Nova interface `LocalStaticProvisioner` injectable.
- 3 testes regression.

### Iter 13 — Six bugs in promote+rollback+admin (commit `3bf1b83f`)

#### Achado #21 — promote vaza namespace staging em produção
- **Sintoma**: ArgoCD App `tn-{tenant}-production` reportava resources em `loopzero-{tenant}-staging` namespace. ArgoCD destination.namespace é OVERRIDE-able pelo `metadata.namespace` no manifest, então o body verbatim de staging ficava aplicado em production.
- **Fix**: `rewriteManifestsForEnv` em `promotion_orchestrator.go` parser YAML-aware (sigs.k8s.io/yaml) que reescreve namespace, env label, hostname suffix. 3 regression tests.

#### Achado iter13-A — promote esquece READY → PENDING transition
- **Sintoma**: convergence loop só varre PENDING, então release ficava READY indefinidamente. K8s healthy mas DB pointer nunca movia.
- **Fix**: tx-lock pós-Push faz `SetGitCommit + UpdateStatus(GitMirrorCompleted)` espelhando `container_delivery.go phaseACreateRelease`.

#### Achado iter13-B — `loopzero project delete` deixa zombie ACTIVE/PENDING
- **Sintoma**: estado anterior persistia em DB. Próximo deploy resolvia release antiga via `GetActiveByEnv` e usava git_commit obsoleto.
- **Fix**: state machine `ReleaseProjectDeleted` event com transitions de qualquer não-terminal → CANCELLED. `ReleaseStore.CancelAllByEnv` cascade dentro do env-lock no `ProjectDeleter`.

#### Achado iter13-C — Status API esconde build_id
- **Fix**: `active_release.build_id` adicionado ao `/api/v1/projects/{p}/status` (additive — Rule 5 estável).

#### Achado iter13-D — `ErrNoActiveRelease` rollback-specific
- **Fix**: mensagem genérica "No active release found in the source environment. Deploy at least once before promoting or rolling back."

#### Achado iter13-E — race K8s health vs DB convergência em journeys
- **Fix**: `wait_release_active(project, env, build_id)` build-aware no `_common.sh`. Journey-05 + 06 agora aguardam release ACTIVE em DB com build_id correto.

### Iter 13 batch 2 (commit `167e0f46`)

#### Achado #22 — CLI Rule 8 fail-clear violation em /api/v1/domains
- **Sintoma**: domain endpoints respondem `{"error": "X"}` (não a forma canônica `{"code","message"}`). CLI `mapError` só lia `body.message` → mensagem específica do servidor era trocada pela genérica "Request failed (HTTP 400). Check your command arguments."
- **Fix**: `ApiClient.mapError` agora aceita `body.error` como fallback para `body.message`. 4 regression tests + atualização de 3 tests pré-existentes que assumiam o comportamento errado.

#### Wait helpers: 401-aware token refresh
- **Sintoma**: token TTL local (~30min) era menor que worst-case journey runtime. `wait_build_terminal` polava silenciosamente com 401 por 25min, parecendo travado.
- **Fix**: ambos `wait_build_terminal` e `wait_release_active` agora detectam 401 e regeneram via `ensure_token`.

### Iter 13 batch 3 (commit `120e57e3`)

#### Achado #23 — `loopzero connect` não idempotente
- **Sintoma**: `project_repositories.repo_full_name` é UNIQUE; INSERT no LinkRepository não tinha ON CONFLICT → segunda execução com mesmos params explodia em constraint violation → 503.
- **Fix**: ON CONFLICT (repo_full_name) DO UPDATE SET tenant_id/project_name/installation_id/default_branch/updated_at. Regression test asserting upsert SQL.

#### Achado #25 — endpoints admin inacessíveis pelo CLI
- **Sintoma**: `/api/v1/admin/tenants/evict` registrado dentro do grupo de rotas protegidas (middleware.Auth). middleware exigia X-LoopZero-User-ID/Tenant alongside X-Service-Auth — CLI operator não tem identity → 401 mesmo com secret correto.
- **Fix**: rota movida para fora do grupo, ao lado de `/webhooks/github`. Handler já tem seu próprio gate (LOOPZERO_ADMIN_API=true + service-auth match).
