### Comando padrão de Prova de Vida documentado (T0.5)

Os IngressRoutes do LoopZero usam hosts no formato `<tenant>-<project>-<app>-<env>.loopzero.local`. Para acessar de host:

```bash
curl --resolve <host>:443:127.0.0.1 -k https://<host>/
```

`-k` é necessário em standalone-multi porque o `selfsigned-issuer` emite certs não-confiáveis publicamente. O cert ainda é válido X.509 — verificável via `openssl s_client -servername <host> -connect 127.0.0.1:8443`.

## Phase 1 — Baseline dogfood (frontend + backend)

**Status**: ✅ HTTP 200 alcançado (api). Web (static frontend) pendente CF Worker local.

### Decisão (deviação leve do plano)

Plano original (T1.1) usava `examples/monorepo-turbo` upstream. Esse template tem 3 bugs **na origem** (documentados como F1/F2/F3 nesta sessão) que impedem o build:
- F1: `loopzero.yaml` sem `build: dockerfile` (warning UX)
- F2: `apps/api/Dockerfile` falha com npm workspaces hoisted (`COPY /app/apps/api/node_modules` não existe)
- F3: Dockerfile assume context monorepo-root mas LoopZero seta context per-app (`packages/shared` fica fora)

ADR D2 prevê PR upstream para gaps de templates. Para destravar Phase 1 enquanto gaps são corrigidos, criei `/tmp/dogfood-fb/` (api Express + web Vite) self-contained sem shared packages — exercita os mesmos paths críticos (multi-app build, container, static delivery, cosign, digest fix) com superfície menor de bugs upstream.
