# API contracts

Wire contracts the engine exposes. The OpenAPI document
(`api/openapi/engine.yaml`) is the machine-readable source and is verified against the
running server by `api/internal/contract/engine_conformance_test.go`.

## Stability rules

These come from `CLAUDE.md` and are repeated here because they bind every contract below.

- **Exit codes are permanent** — `0` success, `1` usage, `2` build failure, `3` deploy
  failure, `4` auth, `5` partial failure. No others.
- **`--json` is a stability contract** — field names cannot change without a major bump.
  New fields may be added.
- **No internal terms in user-facing output** — forbidden in CLI output, error messages and
  `--json`: `ArgoCD`, `GitOps`, `CRD`, `tenant_id`, `advisory lock`, `pg_advisory`, `Gitea`,
  `MinIO`, `kubebuilder`, `envtest`, `Kaniko`. Use product language: deploy, team, account,
  service, revert, build.
- **Every mutation uses the environment lock** — `withEnvironmentLock` for all
  `(tenant, project, environment)` mutations, and the concurrent-build check MUST be inside
  the lock.
- **`pg_advisory_xact_lock` only** — never session-scoped `pg_advisory_lock`; it breaks with
  connection pools.
- **Mutating routes handle `Idempotency-Key`.**

## `POST /api/v1/source/upload`

`multipart/form-data`, `Authorization: Bearer <JWT>`.

| Order | Field | Type | Limit | Required |
|---|---|---|---|---|
| 1 | `services_json` | text or file (UTF-8 JSON) | 256 KB | yes |
| 2 | `bundle` | binary (`application/octet-stream`) | 500 MB | yes |

`bundle` is a git bundle (`git bundle create -1 HEAD`) or a tar.gz of a working tree.

### Error codes

| HTTP | Code | Origin |
|---|---|---|
| 400 | `MULTIPART_FIELD_ORDER` | field order violation (`bundle` before `services_json`) |
| 400 | `INVALID_TENANT_OR_PROJECT` | DNS-1123 violation downstream |
| 401 | `UNAUTHORIZED` | missing or invalid bearer token |
| 413 | `PAYLOAD_TOO_LARGE` | body / bundle exceeds 500 MB |
| 413 | `SERVICES_JSON_TOO_LARGE` | `services_json` exceeds 256 KB |
| 422 | `VALIDATION_FAILED` | schema rejection |
| 500 | `SOURCE_UPLOAD_FAILED` | Gitea push or object-store upload failed |

### Why the contract has this shape

**Order** lets the server reject an oversized or malformed `services_json` before buffering
a 500 MB body. **Per-field caps** sit under the global body cap so the client gets a
specific code rather than a generic 413. **Schema versioning** is `oneOf` on `version`, so
a new version is additive.

Invariants and the validation chain: [`loopzerokit-loopzerocloud-seam.md`](loopzerokit-loopzerocloud-seam.md).

## Service-to-service auth

`loopzero-cloud` reaches the engine through an opaque `/engine/*` proxy signed with **Ed25519
service-auth**. Keys are generated by `tools/gen-service-auth-ed25519`; the contract types
live in the sibling repo `../loopzero-contracts` (`serviceauth`). Rotation:
[`runbooks.md`](runbooks.md) § Service-auth secret rotation.

## API keys

`docs/api-keys.md` described API keys scoped `memory:read` / `memory:write` /
`memory:delete` / `memory:admin`. Those scopes belong to **`../loopzero-memory`**, not to this
engine, so the document was removed here rather than consolidated. If the engine grows its
own key surface, document it in this file.

## Progressive delivery, observed from the client

`loopzero deploy` streams SSE while a canary runs:

| Event | Meaning |
|---|---|
| `rollout.step` | a canary step advanced; carries the step index and `setWeight` |
| `rollout.aborted` | Rollout went Degraded or Aborted — the CLI exits **3** |
| `deploy.completed` | the app is Healthy and the URL is live |

Per-plan canary steps and the rest of the pipeline: [`architecture.md`](architecture.md)
§ Deploy flow.
